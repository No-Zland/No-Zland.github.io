# 作品介绍：个人博客与个人知识库系统

> 把 Obsidian 笔记变成可长期维护的个人知识库网站：公开端负责阅读与检索，主人端负责写作、发布和任务同步。

| 项目 | 内容 |
| --- | --- |
| 作品名称 | 梁双宇的个人博客 / 个人知识库 |
| 作品类型 | 个人网站、静态站点生成器、轻量后端 |
| 完成人 | 梁双宇（内容、需求、视觉方向、验收）；AI 编程助手辅助代码实现与文档整理 |
| 在线地址 | GitHub Pages：<https://no-zland.github.io/>；阿里云：<http://47.93.173.214/> |
| 当前规模 | 160 篇文章、189 张站内图片、50 个生成页面 |
| 当前版本 | 以 GitHub `main` 分支最新提交为准 |

## 一、项目定位

### 1. 创作背景

我的学习资料长期分散在 Obsidian、代码目录、竞赛附件和本地 PDF 中。传统笔记库适合自己看，但不适合直接作为对外展示；而现成的博客系统又往往要求把内容重新整理成另一套格式，维护成本高。

这个作品的出发点是：**不搬动原始笔记，在笔记库之上生成一个可阅读、可检索、可长期维护的个人站点**。它既是一个真实的个人网站，也是一个可复用的静态生成与轻量后端实践。

### 2. 目标用户与受众

- **主要用户：我自己**。用于归档课程、竞赛、项目、科研和阅读记录，并在需要时快速检索。
- **次要受众：同学、老师、竞赛伙伴、招聘方**。他们只需要阅读公开内容，不需要注册或登录。
- **不是面向多用户的博客平台**：没有开放注册，没有评论区，没有面向陌生人的投稿入口；写作与任务只对主人开放。

### 3. 拟解决的问题

1. Obsidian 笔记包含 `==高亮==`、`^上标^`、`![[图片]]`、wiki 链接、空行表格等语法，普通静态博客不能直接渲染。
2. 文章长、分类多，按长度自动分页会把文章从中间截断，阅读体验差。
3. 整页刷新会中断背景音乐，阅读长文时尤其明显。
4. 文章、PDF、图片、音乐、任务、搜索分散在不同工具里，缺少统一入口。
5. 公开站点需要只读，但主人又需要在线写作和跨设备任务备份；纯静态托管无法直接写文件。
6. 页面偏亮、内容较多，需要更舒适的阅读控制和更自然的检索入口。

### 4. 应用场景

- 课程笔记、竞赛记录、项目复盘的长期归档；
- 面向同学/老师的个人作品展示；
- 阅读摘录、参考资料与 PDF 资料库；
- 主人在任意浏览器登录后写一篇 Markdown 笔记，自动发布到站点；
- 通过检索型 2D 助手快速找到“我写过什么”。

### 5. 最终形成的成果

一个可运行的个人站点：

- 首页 → 板块 → 分类 → 阅读页的层级浏览；
- 一篇文章一页、左侧文章列表、本篇目录、上一篇/下一篇；
- 全文搜索、PDF/图片查看、全局音乐、任务日历、主人模式；
- 在线写笔记，支持服务器发布和 GitHub 备用发布；
- 页面亮度调节与 2D 站内笔记助手；
- GitHub Pages 公开只读 + 阿里云 Nginx/FastAPI/SQLite 主人端；
- 文章版权说明、robots 与基础防爬机制。

## 二、主要创新

### 创新 1：板块即目录，一篇文章一页

**原有问题**：早期采用“虚拟板块 + 分类目录”的结构，`竞赛经历/竞赛/...` 容易出现重复嵌套；阅读页为了控制长度按内容块自动分页，长文会被从中间截断。

**采用方法**：

- 把 `content/post` 的**顶层目录直接作为板块**，板块下的子目录作为分类；
- 生成器直接按物理目录输出页面，不再维护一套额外的虚拟板块映射；
- 阅读页一次只渲染一篇文章，左侧提供文章列表、当前文章目录和独立的上一篇/下一篇卡片；
- 搜索、文章列表、目录都使用稳定锚点，软导航后仍然有效。

**与已有做法的差异**：不是先要求作者“按博客格式重写”，也不是用固定字数硬切文章，而是让内容结构决定导航结构；文章完整性优先于分页数量。

**实际效果**：当前 160 篇文章可以按 6 个有内容的板块浏览；文章不再出现中途截断；比赛、课程、项目等目录的层级更直观。

### 创新 2：软导航 + 全局音频

**原有问题**：每次站内跳转都整页刷新，音乐播放器被销毁，正在听的歌会中断；播放列表到最后一首后还会停下。

**采用方法**：

- 用 `fetch` + `DOMParser` 拦截站内链接，只替换 `main` 与侧栏卡片；
- 播放器 DOM 和 `<audio>` 节点保留原位，不参与替换；
- 保留浏览器前进/后退、URL、标题、返回按钮；
- 顺序播放到最后一首自动回到第一首；随机/单曲循环分别处理；
- 整页刷新时用 `sessionStorage` 恢复曲目、进度和播放状态作为兜底。

**与已有做法的差异**：不是简单“记住进度后重新加载”，而是让换页时音频节点本身不被卸载；公共的搜索、抽屉、日历、2D 助手也不重建。

**实际效果**：站内切换板块、文章和写笔记页时，播放器节点保持一致，音乐连续播放；自动连播与列表回绕已单独验证。

### 创新 3：公开只读 + 主人可写的双端架构

**原有问题**：GitHub Pages 只能托管静态文件，无法安全地在线写文件；把高权限 GitHub Token 放在浏览器里又不适合作为日常方案。

**采用方法**：

- GitHub Pages 继续作为公开只读镜像；
- 阿里云上使用 Nginx 服务静态站点，FastAPI + SQLite 提供 `/api`；
- 主人登录后，`/写笔记/` 才显示编辑器；发布时写入服务器 `content/post`，触发 `build_blog.py` 重建；
- 任务通过 `/api/tasks` 做主人端同步；
- 保留 GitHub Contents API 作为备用发布方式；
- 访客只能阅读，未登录不渲染编辑器、草稿和发布按钮。

**与已有做法的差异**：不是把整站改成需要登录的动态博客，而是“静态阅读 + 少量动态写入”；公开端速度快、可缓存，主人端才需要认证。

**实际效果**：阿里云上的 Nginx、FastAPI、SQLite、systemd 已运行；登录、发布、构建、任务读取已通过接口测试；外网 `http://47.93.173.214/` 可访问。最新主人门和亮度补丁在 GitHub Pages 已生效，服务器端因 SSH 22 暂时关闭仍待同步。

### 创新 4：面向个人笔记的检索型 2D 助手与阅读体验层

**原有问题**：站内内容多，靠目录逐层查找慢；通用聊天机器人容易编造，且需要外部 API Key。

**采用方法**：

- 右下角提供 2D SVG 形象「小双」，带浮动/眨眼动画；
- 助手读取站内 `search-index.json`，按标题、分类、正文打分，返回摘要和原文链接；
- 不调用外部大模型，不编造内容；回答可追溯到具体笔记；
- 配合底部亮度滑杆、暗色/浅色主题、文章版权和防爬提示，形成统一的阅读体验。

**与已有做法的差异**：不是“通用问答套壳”，而是**只面向本博客内容的可追溯检索**；在没有大模型 Key 的情况下也能工作，部署成本低。

**实际效果**：输入“数学建模”“ADC”“最近更新”等可以返回相关文章卡片和原文链接；亮度滑杆可拖动并记忆，默认 85%。

## 三、技术或创作实现

### 1. 总体技术路线

```text
content/post/*.md + 图片/PDF
          │
          ▼
build_blog.py（Python）
  ├─ 扫描目录、文章、图片、PDF、音乐
  ├─ python-markdown + pymdownx 渲染 Obsidian 语法
  ├─ 生成首页/板块/分类/阅读页/资料库/写笔记页
  └─ 输出 site/
          │
          ├──► GitHub Pages（公开只读）
          └──► 阿里云 Nginx（公开只读 + /api）
                         │
                         ├─ FastAPI + SQLite
                         ├─ 主人登录 / 笔记写入 / 任务同步
                         └─ 写回 content/post → 重新构建 site/
```

浏览器端：

```text
静态页面
  ├─ 软导航（替换 main / 侧栏卡片，保留下载器与公共组件）
  ├─ 搜索索引（客户端全文检索）
  ├─ 阅读页（文章列表 + 目录 + 上下篇）
  ├─ 音乐播放器（全局 Audio，顺序/随机/循环）
  ├─ 日历/任务（本地主人模式 + 服务器同步）
  ├─ 在线写笔记（主人登录门 → 服务器/GitHub 发布）
  └─ 2D 检索助手 / 亮度控制 / 版权与防爬
```

### 2. 主要平台与工具

| 层次 | 工具 |
| --- | --- |
| 内容源 | Obsidian Markdown、图片、PDF、音频 |
| 生成器 | Python 3、`markdown`、`pymdown-extensions` |
| 本地预览 | Hugo（`staticDir = site/`） |
| 前端 | 原生 HTML/CSS/JavaScript、SVG 2D 形象 |
| 公开部署 | GitHub Actions + GitHub Pages |
| 主人端后端 | Ubuntu 22.04、Nginx、FastAPI、SQLite、systemd |
| 文档与版本 | Git、Markdown、GitHub |

### 3. 系统结构与内容结构

内容侧：

```text
content/post/
├── 竞赛经历/           # 板块
│   ├── 202608 .../
│   ├── 202609 .../
│   └── 数学建模/       # 分类
├── 项目经历/
├── 科研经历/           # 目录保留，暂无文章
├── 技能学习/
├── 课程学习/
├── 阅读经历/
└── 个人与总结/
```

生成侧：

```text
site/
├── index.html
├── <板块>/index.html
├── <板块>/<分类>/index.html
├── 资料库/index.html
├── 写笔记/index.html
└── assets/
    ├── style.css / app.js
    ├── search-index.json
    ├── files/          # 图片、PDF 副本
    └── music/          # 音乐
```

### 4. 核心功能与关键方法

- **Obsidian 风格渲染**：`markdown` + `pymdownx` 处理高亮、上下标、任务列表、公式；`fix_tables` 修复被空行打断的表格；图片按文件名/相对路径解析并复制到站点。
- **层级导航**：从物理目录生成首页板块、板块分类、分类/子分类页；左侧导航随当前路径展开。
- **一篇文章一页**：`reading-mode.js` 只显示当前文章，左侧生成文章列表、h2/h3 目录和上下篇卡片；搜索锚点可定位文章。
- **软导航**：`spa.js` 保留播放器 `<audio>` 节点，只替换主内容与侧栏卡片；支持 `pushState`/`popstate`。
- **全局音乐**：顺序、随机、单曲循环，进度条可拖动，歌单面板，悬浮歌词；空列表/自动续播有兜底。
- **搜索**：构建期生成 `search-index.json`，客户端支持精确/模糊匹配和高亮。
- **任务与主人模式**：本地 PBKDF2 密码保护的任务清单，访客不可见；主人可以导出/导入，并可同步到服务器。
- **在线写笔记**：未登录只显示主人专用门；登录后编辑器支持草稿、预览、导出、服务器发布和 GitHub 备用发布。
- **2D 助手**：读取站内搜索索引，按标题/分类/正文评分，输出摘要与原文链接。
- **阅读体验**：亮度滑杆、明暗主题、中英切换、版权块、`noai`/`noimageai` 元信息、robots 规则、复制出处提示。
- **部署**：GitHub Actions 构建 `site/` 发布到 Pages；阿里云 Nginx 服务同一份构建产物，`/api` 反向代理到 FastAPI。
