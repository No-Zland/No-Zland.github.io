### 2. 题目描述

已知多项式方程：
$$ a_0+a_1x+a_2x^2+...+a_nx^n=0 $$
求这个方程在$[1, m]$内的整数解（n和m均为正整数）。

**输入描述:**

> 第一行包含2个整数n、m，每两个整数之间用一个空格隔开。
> 接下来的n+1行每行包含一个整数，依次为$a_0, a_1, a_2, ......, a_n$。

**输出描述:**

> 第一行输出方程在$[1, m]$内的整数解的个数。
> 接下来每行一个整数，按照从小到大的顺序依次输出方程在$[1, m]$内的一个整数解。

#### 示例
**示例1**
输入
```text
2 10
1
-2
1
```

输出
```text
1
1
```

**示例2**
输入
```text
2 10
2
-3
1
```

输出
```text
2
1
2
```

**示例3**
输入
```text
2 10
1
3
2
```

输出
```text
0
```
**备注:**

对于30%的数据，$0<n\le 100$，$|a_i|\le 10^{100}$，$a_n\neq 0$，$m\le 100$；
对于50%的数据，$0<n\le 100$，$|a_i|\le 10^{100}$，$a_n\neq 0$，$m\le 100$；
对于70%的数据，$0<n\le 100$，$|a_i|\le 10^{10000}$，$a_n\neq 0$，$m\le 10000$；
对于100%的数据，$0<n\le 100$，$|a_i|\le 10^{10000}$，$a_n\neq 0$，$m\le 1000000$。

### 3. 解题思路
#### 首次代码
```cpp
class Solution {
public:
    vector<int> twoSum(vector<int>& nums, int target) {
        vector<int> numtwo(2, 0);
        for(int i = 0; i < nums.size(); i ++){
            for(int j = i + 1; j < nums.size(); j ++){
                if(nums[i] + nums[j] == target) {
                    numtwo[0] = i;
                    numtwo[1] = j;
                    return numtwo;
                }
            }
        }
        return numtwo;
    }
};
```
首先是经典的暴力解法。

## 1. 代码细节微调（不改变时间复杂度）

### ✅ 直接返回结果
你用了 `numtwo` 来存储结果，其实可以直接返回 `{i, j}`，更简洁：

```cpp
class Solution {
public:
    vector<int> twoSum(vector<int>& nums, int target) {
        for (int i = 0; i < nums.size(); i++) {
            for (int j = i + 1; j < nums.size(); j++) {
                if (nums[i] + nums[j] == target) {
                    return {i, j};  // 直接返回
                }
            }
        }
        return {};  // 题目保证有解，这里不会执行
    }
};
```

这样减少了 `numtwo` 的创建和赋值，代码更短，可读性更好。

### ✅ 减少重复计算
在内层循环中，每次都要计算 `nums[i] + nums[j]`，但 `nums[i]` 是固定的，可以先算出需要的补数 `complement = target - nums[i]`，然后在内层找 `complement`：

```cpp
for (int i = 0; i < nums.size(); i++) {
    int complement = target - nums[i];
    for (int j = i + 1; j < nums.size(); j++) {
        if (nums[j] == complement) {
            return {i, j};
        }
    }
}
```

这样每轮内层循环只做一次加法（其实由减法替代），略微减少运算量，但仍是 O(n²) 复杂度。

## 2. 排序 + 双指针（时间复杂度 O(n log n)）

如果题目不要求返回原始下标，或者允许我们额外记录原始下标，可以使用排序 + 双指针的方法。

### 思路：
1. 将数组元素连同原始下标一起存储（例如 `pair<int,int>`），然后按值排序。
2. 使用两个指针 `left` 指向开头，`right` 指向末尾。
3. 计算两数之和：
   - 若等于 `target`，返回两个原始下标。
   - 若小于 `target`，`left++`（需要更大的数）。
   - 若大于 `target`，`right--`（需要更小的数）。

### 代码示例：
```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    vector<int> twoSum(vector<int>& nums, int target) {
        vector<pair<int, int>> num_with_index; // 值, 原始下标
        for (int i = 0; i < nums.size(); i++) {
            num_with_index.push_back({nums[i], i});
        }
        sort(num_with_index.begin(), num_with_index.end());

        int left = 0, right = nums.size() - 1;
        while (left < right) {
            int sum = num_with_index[left].first + num_with_index[right].first;
            if (sum == target) {
                return {num_with_index[left].second, num_with_index[right].second};
            } else if (sum < target) {
                  left++;
            } else {
                right--;
            }
        }
        return {};
    }
};
```

### 复杂度：
- 时间：排序 O(n log n)，双指针 O(n)，总 O(n log n)
- 空间：额外 O(n) 存储带下标的结构

这个方法比暴力快很多，尤其当 n 较大时。但需要额外空间，且改变了原数组顺序（我们用额外结构避免了）。

## 3. 哈希表（时间复杂度 O(n)）

这是最优的通用解法，利用哈希表快速查找补数。

### 思路：
- 遍历数组，对于每个元素 `nums[i]`，计算它需要的补数 `target - nums[i]`。
- 如果补数已经在哈希表中（之前遍历过的元素），直接返回两个下标。
- 否则将当前元素的值和下标存入哈希表。
- 注意：必须先查找，再插入，否则可能返回同一个元素两次（例如 `[3,3]` target=6，如果先插入第一个3，再查找第二个3的补数3，会找到自己）。

### 代码：
```cpp
#include <vector>
#include <unordered_map>
using namespace std;

class Solution {
public:
    vector<int> twoSum(vector<int>& nums, int target) {
        unordered_map<int, int> seen; // 值 -> 下标
        for (int i = 0; i < nums.size(); i++) {
            int complement = target - nums[i];
            if (seen.find(complement) != seen.end()) {
                return {seen[complement], i};
            }
            seen[nums[i]] = i;
        }
        return {};
    }
};
```

### 复杂度：
- 时间：O(n) —— 每个元素最多被访问两次（查找和插入）
- 空间：O(n) —— 哈希表存储元素

这是目前最优的解法，也是面试中最常被期待的答案。

## 总结：优化路线

| 方法               | 时间复杂度 | 空间复杂度 | 适用场景               |
|--------------------|------------|------------|------------------------|
| 暴力枚举（你的）   | O(n²)      | O(1)       | 小数据量，要求少内存   |
| 排序+双指针        | O(n log n) | O(n)       | 中等数据量，允许额外空间 |
| 哈希表             | O(n)       | O(n)       | 大数据量，追求时间最优 |

建议从暴力开始，逐步理解为何排序+双指针更快，最后掌握哈希表方法。这样你的算法思维会一步步提升。

## 一、问题的难点

原题的多项式为：
$a_0 + a_1 x + a_2 x^2 + \dots + a_n x^n = 0$
其中 \(n\) 和 \(m\) 是正整数，系数 \(a_i\) 的绝对值可以达到 \(10^{10000}\) 这么大，而 \(m\) 最大为 \(10^6\)。

如果直接用 `unsigned long long` 存储系数，肯定溢出，得不到正确结果。如果使用高精度（大数）计算，那计算量会非常恐怖：对每个 \(x\) 都要计算高精度幂和高精度加法，\(m\) 有 100 万，\(n\) 有 100，这样的计算量完全不可行。

所以我们需要一个**既不需要存储大数，又能快速判断 \(x\) 是否为解**的方法。

---

## 二、核心思想：模素数判定

### 1. 基本原理

如果整数 \(x\) 是方程的解，即：
\[
f(x) = a_0 + a_1 x + \dots + a_n x^n = 0
\]
那么对于**任意**正整数 \(p\)，一定有：
\[
f(x) \equiv 0 \pmod{p}
\]
（因为一个整数是 0，它模任何数都是 0。）

反过来不一定成立：如果 \(f(x) \equiv 0 \pmod{p}\)，我们不能保证 \(f(x)=0\)，因为可能 \(f(x)\) 是 \(p\) 的倍数而不是 0。

但是，如果我们选取**多个不同的素数** \(p_1, p_2, \dots, p_k\)，并且对于某个 \(x\) 同时满足：
\[
f(x) \equiv 0 \pmod{p_1},\; f(x) \equiv 0 \pmod{p_2},\; \dots,\; f(x) \equiv 0 \pmod{p_k}
\]
那么 \(f(x)\) 是这些素数的公倍数。由于这些素数互不相同，它们的乘积非常大（例如 5 个 \(10^5\) 级别的素数相乘得到 \(10^{25}\)），而 \(|f(x)|\) 在 \(x \le m=10^6\) 时，最大值不会超过 \(\sum |a_i| m^i\)。虽然系数本身可能巨大，但经过模素数过滤后，误判的概率极低——数学上可以证明，如果 \(f(x) \neq 0\)，那么它被所有素数同时整除的概率近似于 \(\frac{1}{p_1 p_2 \dots p_k}\)，几乎为 0。

因此，我们可以用**多个素数**来“筛选”出可能的解，最后再通过某种方式验证（实际上误判极罕见，通常不需要最后验证）。

### 2. 为什么用素数而不是合数？

- 素数模运算性质好，不会引入不必要的零因子。
- 素数大小选择在 \(10^4 \sim 10^5\) 之间，因为我们需要计算 \(0\) 到 \(p-1\) 所有余数的多项式值，这个范围是可行的（\(p\) 太大预处理成本高，太小过滤能力弱）。

---

## 三、如何高效计算 \(f(x) \bmod p\)？

### 1. 秦九韶算法

对于多项式求值，我们通常不用直接计算 \(x^k\) 再乘以系数，而是用**秦九韶算法**（霍纳规则）：
\[
f(x) = (\dots((a_n x + a_{n-1})x + a_{n-2})x + \dots)x + a_0
\]
这样只需要 \(n\) 次乘法和 \(n\) 次加法，避免了幂运算，且中间结果可以随时取模，始终保持在 \(p\) 范围内。

例如，给定系数 \([a_n, a_{n-1}, \dots, a_0]\) 和 \(x\)，计算过程：
```
res = 0
for i from n down to 0:
    res = (res * x + a_i) % p
```
最后 `res` 就是 \(f(x) \bmod p\)。

### 2. 预处理系数取模

系数 \(a_i\) 可能极大，无法直接存储。我们读入时用字符串处理，边读边对每个素数取模：
\[
a_i^{(p)} = a_i \bmod p \quad (\text{处理负数后得到 } 0 \le a_i^{(p)} < p)
\]
这样对每个素数 \(p\)，我们得到一组小系数（大小不超过 \(p\)），可以用普通整数存储。

---

## 四、进一步优化：利用余数周期性

直接对每个 \(x \in [1, m]\) 用秦九韶算法计算 \(f(x) \bmod p\) 的复杂度是 \(O(m \cdot n)\)，当 \(m=10^6, n=100\) 时，一个素数就需要 \(10^8\) 次运算，多个素数就会超时。

观察发现：**\(f(x) \bmod p\) 的值只取决于 \(x\) 除以 \(p\) 的余数**。因为多项式求值中乘法加法都只用到 \(x\) 本身，而 \(x \equiv r \pmod{p}\) 时，有：
\[
f(x) \bmod p = f(r) \bmod p
\]
（这里 \(r = x \bmod p\)，但要注意在取模过程中 \(x\) 替换为 \(r\) 是成立的，因为模运算下可以替换底数。）

因此我们可以：
1. 对于每个素数 \(p\)，**预先计算**出所有可能的余数 \(r = 0, 1, 2, \dots, p-1\) 对应的多项式值：
   \[
   val[r] = f(r) \bmod p
   \]
   计算每个 \(val[r]\) 用秦九韶算法，复杂度 \(O(p \cdot n)\)。
2. 然后遍历所有 \(x = 1 \dots m\)，只需检查 \(val[x \bmod p]\) 是否为 0：
   - 如果 \(val[x \bmod p] \neq 0\)，则 \(f(x) \not\equiv 0 \pmod{p}\)，那么 \(x\) 一定不是解，标记为排除。
   - 如果为 0，则保留，等待后续素数进一步判断。

这样，对每个素数，预处理代价 \(O(p \cdot n)\)，过滤代价 \(O(m)\)。\(p\) 大约 \(10^5\)，所以总运算量大约是：
\[
\sum (p_i \cdot n + m) \approx (6 \times 10^5 \times 100) + (6 \times 10^6) = 6 \times 10^7 + 6 \times 10^6 \approx 6.6 \times 10^7
\]
即约 6600 万次基本运算，现代计算机可以轻松在 1 秒左右完成。

## 五、算法流程总结

1. **输入**：\(n, m\)，以及 \(n+1\) 个系数字符串。
2. **选择素数**：选取 4～6 个大小适中的素数（例如 `{10007, 10009, 10037, 100003, 100019, 100043}`）。
3. **系数取模**：对每个素数 \(p_k\)，将每个系数字符串转化为模 \(p_k\) 的非负整数 \(a_{k,i}\)。
4. **初始化可能解数组**：`possible[x] = true` 对所有 \(x=1..m\)。
5. **对每个素数依次过滤**：
   - 预处理余数数组 `val[r]`，计算 \(f(r) \bmod p_k\)（使用秦九韶算法）。
   - 遍历 \(x\) 从 1 到 \(m\)：
     - 如果 `possible[x]` 为真且 `val[x % p_k] != 0`，则置 `possible[x] = false`。
6. **收集结果**：遍历所有 \(x\)，若 `possible[x]` 仍为真，则输出。
7. **输出**：解的个数和每个解。

## 六、为什么能避免溢出？

整个过程中，所有数值运算都发生在模素数范围内，最大不超过 \(10^5\)，因此使用普通的 `int` 或 `long long` 完全足够，不需要高精度。系数本身虽然巨大，但我们只在读入时用字符串逐位取模，不存储原始值，所以不存在溢出问题。

## 七、举例帮助理解

假设有一个方程 \(f(x) = 12345678901234567890 \cdot x + 9876543210987654321\)，且 \(m=10^6\)。我们选取素数 \(p=10007\)。

- 先对系数取模：
  \[
  a_1 = 12345678901234567890 \bmod 10007 = \text{某个小值}，a_0 = 9876543210987654321 \bmod 10007 = \text{某个小值}
  \]
- 预处理余数：对每个 \(r \in [0,10006]\)，计算 \(val[r] = (a_1 \cdot r + a_0) \bmod 10007\)，这是一个长度为 10007 的数组。
- 然后对于任意 \(x\)，我们只需查表 \(val[x \bmod 10007]\) 就能知道 \(f(x) \bmod 10007\) 是否为 0，无需真正用大数计算。

如果某个 \(x\) 在多个素数下都满足模值为 0，那么它很可能是真正的解。

---

## 八、复杂度与正确性讨论

- **时间复杂度**：如上计算，约几千万次运算，能通过 \(m=10^6\) 的数据。
- **空间复杂度**：存储系数模值 \(O(k \cdot n)\)，余数数组 \(O(p)\)（可重复使用），可能解数组 \(O(m)\)，可以接受。
- **正确性**：由于素数乘积足够大，误判概率极低。如果实在不放心，可以再用高精度验证最终候选解（但通常不需要）。
