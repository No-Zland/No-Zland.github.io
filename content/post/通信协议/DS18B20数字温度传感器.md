## 一、DS18B20 核心定义与核心特性
### 1. 基本定义
DS18B20 是一款单总线（1-Wire）数字温度传感器，能够直接将环境温度转换为 16 位二进制补码形式的数字信号，无需额外外部元件即可独立工作，通过一根信号线实现与主机（如 MCU）的双向通信，广泛应用于嵌入式系统的温度采集场景（如环境温度监测、设备温度监控等）。

### 2. 核心特性（文档明确提及）
| 特性                | 说明                                                                 |
|---------------------|----------------------------------------------------------------------|
| 通信方式            | 支持 **1-Wire（一线总线）** 通信，仅需一根数据线（D0 引脚）即可实现数据传输，节省 GPIO 资源。 |
| 无需外部元件        | 内部集成温度采集、A/D 转换、数据存储等功能，无需额外配置电阻、电容等外围器件（仅需总线匹配电阻）。 |
| 测量精度            | 温度数据最小量化单位为 **0.0625℃**，测量精度高，满足大多数场景的温度检测需求。 |
| 数据存储格式        | 温度数据以 **16 位二进制补码** 存储在内部寄存器中，高 5 位为符号位，低 11 位为数据位，可区分正负数温度。 |
| 硬件结构            | 包含温度上限寄存器、温度下限寄存器、暂存器等核心单元，支持温度阈值设置与报警功能（文档提及“温度上和温度下寄存器”）。 |
| 信号引脚            | 仅需 D0 引脚作为数字信号输入/输出端，实现复位、读写等所有通信功能。 |

### 3. 主要用途
- 环境温度采集：监测室内、室外等环境的实时温度。
- 设备温度监控：检测 MCU、电机、电源模块等电子设备的工作温度，避免过热故障。
- 温度报警系统：通过设置温度上下限阈值，实现超温报警功能。

## 二、DS18B20 硬件设计要点
### 1. 核心硬件组成与连接
| 硬件单元       | 功能说明                                                                 |
|----------------|--------------------------------------------------------------------------|
| Vcc            | 电源引脚，供电电压范围通常为 3.3V~5V，需与主机共地，保障电源稳定性。       |
| GND            | 地引脚，为传感器提供参考地，需与主机 GND 可靠连接，减少信号干扰。         |
| D0（DQ）       | 数字信号输入/输出引脚，即 1-Wire 总线数据线，用于与主机传输复位、应答、数据等信号（文档标识为“D0:数字信号输入/输出”）。 |
| 上拉电阻       | D0 引脚需外接 4.7KΩ~10KΩ 上拉电阻至 Vcc，确保总线空闲时为高电平，保障通信稳定性（1-Wire 协议强制要求）。 |

### 2. 硬件连接规范
- 总线拓扑：多个 DS18B20 可挂载在同一根 D0 线上（多从机架构），通过传感器内置的唯一 64 位 ROM 地址区分不同设备。
- 电源供电方式：支持寄生电源模式（通过 D0 线获取供电）和外部电源模式（单独接入 Vcc），外部电源模式稳定性更高，推荐优先使用。
- 抗干扰设计：电源引脚旁可并联 0.1μF 旁路电容滤除电源噪声；D0 线布线尽量短，远离电源线和高速数字信号线，减少电磁干扰。
- 引脚接触：传感器 D0、Vcc、GND 引脚需焊接牢固，避免虚焊导致通信中断（文档提及“温度传感器插反导致软件编码检测不出来”，需注意引脚正负极）。

### 3. 常见硬件问题排查
- 传感器插反：DS18B20 引脚正负极接反会导致无法通信，且软件无法检测，需通过硬件手册确认引脚定义（通常 Vcc 为正极，GND 为负极，D0 为信号端）。
- 上拉电阻缺失：未接或接错上拉电阻会导致总线信号漂浮，无法产生稳定的复位和数据信号，需确认电阻阻值为 4.7KΩ~10KΩ。
- 电源供电异常：供电电压超出 3.3V~5V 范围或电源噪声过大，会导致传感器工作异常，需用万用表测量 Vcc 电压。

## 三、1-Wire 通信协议核心流程（DS18B20 专用）
DS18B20 的所有通信均基于 1-Wire 协议，核心流程包括**初始化（复位与应答）、写时序、读时序**，需严格遵循时序要求才能保障通信成功。

### 1. 初始化时序（复位与应答）
初始化是通信的前提，主机通过拉低总线产生复位脉冲，从机（DS18B20）通过拉低总线产生应答脉冲，表明自身就绪。
- 具体步骤：
  1. 主机拉低 D0 总线 **480~960μs**，产生复位脉冲。
  2. 主机释放 D0 总线，进入接收模式，总线由上拉电阻拉回高电平。
  3. 从机检测到总线上升沿后，延时 **15~60μs**，随后拉低 D0 总线 **60~240μs**，产生应答脉冲。
  4. 主机检测到 D0 总线低电平时，确认从机已就绪，初始化完成；若未检测到应答脉冲，说明通信失败（可能是硬件连接错误或传感器故障）。

### 2. 写时序（主机向从机发送指令/数据）
写时序用于主机向 DS18B20 发送控制指令（如温度转换指令、读取数据指令）或配置参数，分为写 0 和写 1 两种操作，时序精度要求严格。
- 写 0 操作：
  1. 主机拉低 D0 总线，保持 **60μs**（期间从机在 15~60μs 内采样）。
  2. 60μs 后主机释放 D0 总线，总线恢复高电平，完成写 0。
- 写 1 操作：
  1. 主机拉低 D0 总线，持续至少 **1μs**。
  2. 主机在拉低后 **15μs 内** 释放 D0 总线，总线由上拉电阻拉回高电平。
  3. 从机在 15~60μs 内采样，检测到高电平即识别为写 1。
- 注意事项：相邻两个写时序之间需间隔至少 1μs，避免信号叠加导致误判。

### 3. 读时序（主机从从机读取数据）
读时序用于主机读取 DS18B20 转换后的温度数据，需在从机输出数据的有效窗口内采样。
- 具体步骤：
  1. 主机拉低 D0 总线至少 **1μs**，随后释放总线。
  2. 主机在释放总线后 **15μs 内** 读取 D0 总线电平（从机通过拉高或拉低总线传输数据位，高电平为 1，低电平为 0）。
  3. 单个读时序持续时间不超过 60μs，确保从机有足够时间准备下一位数据。
- 注意事项：读取多字节数据时，需连续执行读时序，直至所有数据位读取完成。

### 4. 核心指令（常用）
| 指令代码（十六进制） | 指令功能                                                                 |
|----------------------|--------------------------------------------------------------------------|
| 0x44                 | 温度转换指令：主机发送该指令后，DS18B20 开始采集温度并转换为数字信号（文档标注“//ds1820 start convert”）。 |
| 0xBE                 | 读取暂存器指令：主机发送该指令后，可读取 DS18B20 内部暂存器中的 9 字节数据（含温度数据、阈值等）。 |
| 0x4E                 | 写入暂存器指令：主机发送该指令后，可设置温度上限（TH）和温度下限（TL）阈值。 |
| 0xEE                 | 复制暂存器指令：将暂存器中的阈值数据复制到 EEPROM，实现掉电保存。         |
| 0x8B                 | 召回 EEPROM 指令：将 EEPROM 中保存的阈值数据召回至暂存器。               |

## 四、DS18B20 软件设计流程（基于 MCU 编程）
### 1. 核心初始化函数（GPIO 配置 + 1-Wire 初始化）
#### （1）配置 D0 引脚为通用 I/O 模式
- 功能：将 D0 对应的 GPIO 引脚配置为推挽输出/输入模式，支持主机拉低总线和读取总线电平（以 STM32 为例）。
- 代码示例：
```c
#include "stm32f10x.h"

#define DS18B20_DQ_GPIO_PORT  GPIOB
#define DS18B20_DQ_GPIO_PIN   GPIO_Pin_0
#define DS18B20_DQ_GPIO_CLK   RCC_APB2Periph_GPIOB

// 配置 D0 引脚为输出模式
void DS18B20_DQ_Output(void) {
    GPIO_InitTypeDef GPIO_InitStruct;
    RCC_APB2PeriphClockCmd(DS18B20_DQ_GPIO_CLK, ENABLE);
    GPIO_InitStruct.GPIO_Pin = DS18B20_DQ_GPIO_PIN;
    GPIO_InitStruct.GPIO_Mode = GPIO_Mode_Out_PP; // 推挽输出
    GPIO_InitStruct.GPIO_Speed = GPIO_Speed_50MHz;
    GPIO_Init(DS18B20_DQ_GPIO_PORT, &GPIO_InitStruct);
}

// 配置 D0 引脚为输入模式
void DS18B20_DQ_Input(void) {
    GPIO_InitTypeDef GPIO_InitStruct;
    RCC_APB2PeriphClockCmd(DS18B20_DQ_GPIO_CLK, ENABLE);
    GPIO_InitStruct.GPIO_Pin = DS18B20_DQ_GPIO_PIN;
    GPIO_InitStruct.GPIO_Mode = GPIO_Mode_IN_FLOATING; // 浮空输入
    GPIO_Init(DS18B20_DQ_GPIO_PORT, &GPIO_InitStruct);
}

// 设置 D0 引脚电平（高/低）
void DS18B20_DQ_SetLevel(uint8_t level) {
    if (level == 1) {
        GPIO_SetBits(DS18B20_DQ_GPIO_PORT, DS18B20_DQ_GPIO_PIN);
    } else {
        GPIO_ResetBits(DS18B20_DQ_GPIO_PORT, DS18B20_DQ_GPIO_PIN);
    }
}

// 读取 D0 引脚电平
uint8_t DS18B20_DQ_GetLevel(void) {
    return GPIO_ReadInputDataBit(DS18B20_DQ_GPIO_PORT, DS18B20_DQ_GPIO_PIN);
}
```

#### （2）1-Wire 初始化函数（复位 + 应答检测）
```c
// 返回值：1-初始化成功（收到应答），0-初始化失败（未收到应答）
uint8_t DS18B20_Init(void) {
    uint8_t ack = 0;
    
    DS18B20_DQ_Output(); // 配置为输出模式
    DS18B20_DQ_SetLevel(0); // 拉低总线，产生复位脉冲
    delay_us(600); // 拉低 600μs（在 480~960μs 范围内）
    
    DS18B20_DQ_SetLevel(1); // 释放总线
    delay_us(30); // 等待 30μs（在 15~60μs 范围内）
    
    DS18B20_DQ_Input(); // 配置为输入模式
    ack = DS18B20_DQ_GetLevel(); // 读取应答脉冲（低电平为应答）
    
    delay_us(60); // 等待应答脉冲结束
    DS18B20_DQ_Output();
    DS18B20_DQ_SetLevel(1); // 恢复总线空闲状态
    
    return !ack; // 收到应答（ack=0）返回 1，未收到返回 0
}
```

### 2. 写数据函数（单字节）
```c
// 向 DS18B20 写入 1 字节数据
void DS18B20_WriteByte(uint8_t data) {
    uint8_t i;
    DS18B20_DQ_Output();
    
    for (i = 0; i < 8; i++) {
        // 写 1 位数据
        DS18B20_DQ_SetLevel(0); // 拉低总线开始写时序
        delay_us(2); // 拉低至少 1μs
        
        if (data & 0x01) {
            DS18B20_DQ_SetLevel(1); // 写 1：15μs 内拉高
        } else {
            DS18B20_DQ_SetLevel(0); // 写 0：保持低电平 60μs
        }
        delay_us(60); // 写时序持续 60μs
        DS18B20_DQ_SetLevel(1); // 释放总线
        delay_us(1); // 相邻写时序间隔 1μs
        data >>= 1; // 处理下一位数据
    }
}
```

### 3. 读数据函数（单字节）
```c
// 从 DS18B20 读取 1 字节数据
uint8_t DS18B20_ReadByte(void) {
    uint8_t i, data = 0;
    DS18B20_DQ_Output();
    DS18B20_DQ_SetLevel(1); // 总线空闲时为高电平
    delay_us(1);
    
    for (i = 0; i < 8; i++) {
        DS18B20_DQ_SetLevel(0); // 拉低总线开始读时序
        delay_us(2); // 拉低至少 1μs
        
        DS18B20_DQ_SetLevel(1); // 释放总线
        DS18B20_DQ_Input(); // 配置为输入模式
        delay_us(1); // 等待数据稳定
        
        data >>= 1;
        if (DS18B20_DQ_GetLevel() == 1) {
            data |= 0x80; // 读取到高电平，置位对应位
        }
        
        delay_us(60); // 读时序不超过 60μs
        DS18B20_DQ_Output();
        DS18B20_DQ_SetLevel(1); // 恢复总线空闲状态
    }
    return data;
}
```

### 4. 温度采集与转换函数
#### （1）启动温度转换
```c
void DS18B20_StartConvert(void) {
    DS18B20_Init(); // 初始化
    if (DS18B20_Init() == 1) { // 初始化成功
        DS18B20_WriteByte(0xCC); // 跳过 ROM 地址（单从机场景）
        DS18B20_WriteByte(0x44); // 发送温度转换指令
    }
}
```

#### （2）读取温度数据并计算实际温度
DS18B20 温度数据为 16 位二进制补码，存储在暂存器的第 0 字节（低 8 位）和第 1 字节（高 8 位），需按规则转换为实际温度值。
```c
// 返回值：实际温度值（单位：℃，精度 0.0625℃）
float DS18B20_ReadTemperature(void) {
    uint8_t tempL = 0, tempH = 0;
    uint16_t tempData = 0;
    float temperature = 0.0;
    
    DS18B20_Init();
    if (DS18B20_Init() == 1) {
        DS18B20_WriteByte(0xCC); // 跳过 ROM 地址
        DS18B20_WriteByte(0xBE); // 读取暂存器指令
        
        tempL = DS18B20_ReadByte(); // 读取温度低 8 位
        tempH = DS18B20_ReadByte(); // 读取温度高 8 位
        tempData = (tempH << 8) | tempL; // 组合为 16 位数据
    }
    
    // 温度计算：正数直接乘 0.0625，负数先求补码再乘 0.0625
    if ((tempData & 0xF800) == 0) { // 正数（高 5 位为 0）
        temperature = tempData * 0.0625;
    } else { // 负数（高 5 位为 1）
        tempData = (~tempData) + 1; // 求补码（符号位不变，其余取反加 1）
        temperature = - (tempData * 0.0625);
    }
    
    return temperature;
}
```

### 5. 多从机场景处理（可选）
若总线上挂载多个 DS18B20，需通过 ROM 地址匹配指定从机，核心步骤：
1. 发送 0x55 指令（匹配 ROM 地址）。
2. 发送目标从机的 64 位 ROM 地址（前 8 位为家族码，中间 48 位为唯一序列号，最后 8 位为 CRC 校验码）。
3. 发送控制指令（如 0x44 启动转换、0xBE 读取数据）。

## 五、常见问题与解决方案（结合实操场景）
### 1. 初始化失败（未收到应答脉冲）
#### 可能原因
- 硬件连接错误：D0 引脚接线错误、上拉电阻缺失或阻值错误、传感器插反。
- 电源供电异常：Vcc 电压超出范围、电源噪声过大。
- 时序错误：软件延时不符合 480~960μs 复位脉冲要求（如延时过短或过长）。
- 传感器故障：DS18B20 损坏或接触不良。

#### 解决方案
- 检查硬件：核对 D0、Vcc、GND 接线，确认上拉电阻为 4.7KΩ~10KΩ，传感器未插反。
- 验证电源：用万用表测量 Vcc 电压，确保在 3.3V~5V 范围内，添加旁路电容滤除噪声。
- 校准延时：根据 MCU 时钟频率调整延时函数（如 delay_us 函数），确保复位脉冲和等待时间符合时序要求。
- 更换传感器：若上述排查无效，尝试更换新的 DS18B20 传感器。

### 2. 温度数据异常（如固定值、偏差大）
#### 可能原因
- 未等待转换完成：发送 0x44 指令后立即读取数据，DS18B20 未完成温度转换。
- 数据组合错误：低 8 位和高 8 位顺序颠倒，导致数据错误。
- 负数转换规则错误：未正确求补码，导致负数温度计算偏差。
- 数值未放大：文档提及“改一下公式，放大一下数值”，可能因显示精度设置问题导致数值显示异常。

#### 解决方案
- 添加转换延时：发送 0x44 指令后，延时至少 100ms（DS18B20 转换时间通常为 10~100ms）再读取数据。
- 修正数据组合：确保 tempData = (tempH << 8) | tempL（高 8 位左移 8 位，与低 8 位组合）。
- 正确处理负数：严格按照“取反加 1”的补码规则计算，避免符号位错误。
- 调整显示格式：若显示整数温度，可将计算结果四舍五入（如 temperature = (int)(temperature + 0.5)）；若需显示小数，确保显示精度支持 0.0625℃。

### 3. 分盘后 Keil5 工程打不开（间接影响 DS18B20 开发）
#### 问题原因
分盘导致工程依赖的芯片包路径失效或缺失，DS18B20 初始化函数（如 GPIO 配置、延时函数）需芯片包支持。

#### 解决方案（文档验证有效）
- 在线安装芯片包
  1. 打开 Keil5 工程，点击右下角 `Pack Installer`（未响应则点击左上角刷新图标）。
  2. 选择对应芯片型号（如 STM32F103C8、GD32F103C8、MM32F103c8），下载并安装匹配的芯片包。
- 离线安装芯片包
  1. 从开发板供应商获取（如中精灵开发板资料自带芯片包）。
  2. 网络下载（如江大提供的芯片包资源）。
  3. 向他人索要匹配的芯片包，直接导入 Keil5（避免重新解压导致路径错误，文档中提及“重新解压自己的芯片包资料压缩包”为错误方法）。

### 4. 串口打印温度中文乱码（间接问题）
#### 问题原因
Keil5 工程编码与串口接收端编码不一致，导致中文注释或温度单位（如“℃”）乱码。

#### 解决方案（文档推荐）
- 方法 1：编码转换
  1. 用记事本打开工程核心文件（如 main.c），以 UTF-8 编码复制内容。
  2. 在 Keil5 中打开该文件，将 Encode 格式改为 Chinese GB2318。
- 方法 2：编译器配置
  在 Keil5 的 C/C++ 页面 Misc Control 行添加指令：`-no-multibyte-chars`（注：仅 C++ 环境可能兼容）。

## 六、关键注意事项
1. 时序精度是核心：DS18B20 对 1-Wire 协议时序要求极高，延时函数需根据 MCU 实际时钟频率精确校准（如 72MHz 时钟下，1μs 约需 72 个时钟周期），避免因时序偏差导致通信失败。
2. 单从机与多从机区分：单从机场景可使用 0xCC 指令跳过 ROM 地址，简化操作；多从机场景必须通过 0x55 指令匹配 ROM 地址，避免指令冲突。
3. 温度转换等待时间：DS18B20 完成一次温度转换需 10~100ms（与分辨率相关），发送 0x44 指令后需等待转换完成再读取数据，否则会读取到旧数据或错误数据。
4. 补码转换规则：负数温度需严格按照“符号位不变，其余各位取反加 1”的规则求补码，再乘以 0.0625，避免计算错误。
5. 抗干扰设计：除硬件抗干扰外，软件中可添加多次采样取平均值的方法（如连续读取 3 次温度，取平均值），减少噪声导致的温度波动。
6. 总线空闲状态：每次通信完成后，需将 D0 总线恢复为高电平，确保下次通信正常初始化。
