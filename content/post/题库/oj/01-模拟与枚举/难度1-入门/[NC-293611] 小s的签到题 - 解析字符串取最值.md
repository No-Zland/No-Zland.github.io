### 知识点：

签到级的读入加比较题，模型就是「一次遍历维护最优解」。结论先给：答案是「通过人数」最大的那道题，人数并列时取题号字母最小的，所以一遍扫描同时维护当前最大人数与该人数下的最小字母即可。推导：题面把通过人数和提交人数用 '/' 拼成一个字符串，只有 '/' 前面那段参与比较，提交人数纯属干扰项，因此按整串读入后手工截断到 '/' 最稳，也避开了格式化读入对分隔符的依赖。n ≤ 26 且题号两两不同，直接比较字符大小就是字典序。并列的处理是唯一容易写歪的地方：人数严格更大才无条件替换字母，人数相等时要再和已记录的字母比一次大小，这两个分支不能合并，否则先出现的题会挡住后面字母更小的题。

### 题目描述

> 昨晚在酒吧遇见白月光了，昨晚又在酒吧遇见白月光了，昨晚和白月光一起组队打acm了，昨晚封榜过三题拿下金牌。
>
> 小s去单挑小柒举办的DCPC，由于宿醉直接睡了2个小时，醒来后他看了一眼榜，瞬间清醒了。
>
> 小s拿到了一个比赛榜单，他要用最快的速度找到签到题，但是小s脑子还是有点晕，请你帮帮小s，助力他找到签到题。
>
> 比赛榜单是一个  $2$  行  $n$  列的表格：
>
>  $\hspace{23pt}\bullet\,$ 第一行是  $n$  个大写字母，代表题号；
>
>  $\hspace{23pt}\bullet\,$ 第二行是  $n$  个字符串，对应每一道题目的通过人数和提交人数，字符串由两个整数构成，整数之间使用字符  $\texttt{`/'}$  隔开。
>
> 我们定义，通过人数最多的题目是签到题。请你找到签到题的题号并输出。特别地，如果有多个签到题，输出题号字母表顺序最小的那道。

**输入描述**

> 第一行输入一个正整数  $n \left(2\leq n\leq 26\right)$ ，表示题目数量。
> 第二行输入  $n$  个两两不同的大写字母，表示每一道题的题号。
> 第三行输入  $n$  个字符串，表示每一道题的通过人数和提交人数。每个字符串格式为  $a\texttt{/}b$ ，其中  $a$  表示通过人数， $b$  表示提交人数。保证  $0 \leq a \leq b \leq 10^9$ 。

**输出描述**

> 输出一个大写字母，表示签到题的题号。

#### 示例

**输入**

```text
11
A B C D E F G H I J K
116/212 3/12 117/282 15/35 90/419 7/44 83/446 48/150 35/229 25/116 5/10
```

**输出**

```text
C
```

### 最终代码：

```cpp
// NC293611 小s的签到题
// 题意：n 道题，每道题给出「通过人数/提交人数」，通过人数最多的题为签到题，
//       并列时输出题号字典序最小的那个。
// 做法：只比较 '/' 前的人数，同时维护「当前最大人数 + 该人数下最小的字母」。
#include <cstdio>
#include <vector>
using namespace std;

int main() {
    int n;
    if (scanf("%d", &n) != 1) return 0;
    vector<char> id(n);
    for (int i = 0; i < n; ++i) {
        char buf[8];
        if (scanf("%7s", buf) != 1) return 0;
        id[i] = buf[0];
    }
    long long best = -1;
    char ans = 'Z';
    for (int i = 0; i < n; ++i) {
        char s[64];
        if (scanf("%63s", s) != 1) return 0;
        long long pass = 0;
        for (int k = 0; s[k] && s[k] != '/'; ++k) pass = pass * 10 + (s[k] - '0');
        if (pass > best) {                       // 严格更大才替换
            best = pass;
            ans = id[i];
        } else if (pass == best && id[i] < ans) {
            ans = id[i];                         // 人数相同，取字母更小的
        }
    }
    printf("%c\n", ans);
    return 0;
}
```

### 解题思路

第一反应是这题短得可疑，但越短越容易在细节上翻车。我先确认「通过人数最多」只看斜杠前面的数，提交人数完全不参与判断，于是决定按字符串读入、再截到 '/' 转成整数，而不是直接 scanf 整数——这样对题面给的形式最不敏感。接着处理并列：题号按字母序取最小，所以我把更新写成两段，严格大于才无条件覆盖，等于时再单独和当前答案比字母。第三点是我特意检查过的：输入里的题号不一定有序，不能靠「取最后一个」之类的取巧，必须显式比较字母。整个程序就是一次扫描维护最优解，样例一次通过。

#### 卡点与关键一步

- 只需要比较 `a`（通过人数），`b`（提交人数）不参与任何判断，别顺手按通过率排序。
- 并列时要比题号字母大小，且输入顺序与字母序无关，不能默认后面读到的更优或更劣。
- 人数上限 1e9，用 `int` 刚好够但用 `long long` 更省心，别用 `char` 累加。

#### 复杂度

| 项 | 值 |
|---|---|
| 时间复杂度 | O(n) |
| 空间复杂度 | O(n) |
