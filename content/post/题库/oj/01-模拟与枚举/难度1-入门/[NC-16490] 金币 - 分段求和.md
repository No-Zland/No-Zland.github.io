### 知识点：

模型是分段常数的求和：第 k 段持续 k 天、每天 k 枚，整段贡献 k×k。前 K 天要么正好停在某段末尾，要么落在某段中间，所以逐段推进、每段实际取 min(剩余天数, k) 天即可，答案 = Σ k×min(k, 剩余天数)。闭式写法：完整走完 n 段时天数为 n(n+1)/2，金币为 Σk² = n(n+1)(2n+1)/6，余下 r 天每天是 n+1 枚，再加 r(n+1)。因为 n≈√(2K)，按段循环只有 O(√K) 轮。核心易混点是「天数累计是 1+2+…+k」而「金币累计是 1²+2²+…+k²」，两个量必须分开维护。

### 题目描述

> 国王将金币作为工资，发放给忠诚的骑士。第一天，骑士收到一枚金币；之后两天（第二天和第三天），每天收到两枚金币；之后三天（第四、五、六天），每天收到三枚金币；之后四天（第七、八、九、十天），每天收到四枚金币……；这种工资发放模式会一直这样延续下去：当连续N天每天收到N枚金币后，骑士会在之后的连续N+1天里，每天收到N+1枚金币。 
>    请计算在前K天里，骑士一共获得了多少金币。

**输入描述**

> 输入只有1行，包含一个正整数K，表示发放金币的天数。

**输出描述**

> 输出只有1行，包含一个正整数，即骑士收到的金币数。

#### 示例 1

**输入**

```text
6
```

**输出**

```text
14
```

#### 示例 2

**输入**

```text
1000
```

**输出**

```text
29820
```

### 最终代码：

```cpp
#include <cstdio>

// 第 k 个阶段：连续 k 天每天 k 枚。按阶段累加，最后一段不足 k 天时按天补。
int main() {
    long long K;
    if (scanf("%lld", &K) != 1) return 0;
    long long ans = 0, day = 0;
    for (long long k = 1; day < K; ++k) {
        long long take = (K - day < k) ? (K - day) : k;  // 本阶段实际取几天
        ans += take * k;
        day += take;
    }
    printf("%lld\n", ans);
    return 0;
}
```

### 解题思路

第一反应是按天模拟：维护当前阶段 k 和这个阶段还剩几天，每过一天加 k 枚。这样最不容易写错，K 在一万级别，逐天循环也完全跑得动。但我又想少写点状态，就改成按“段”推进：第 k 段共 k 天，一次取 min(剩余天数, k) 天，本段贡献就是 k 乘以实际取的天数，剩下不足 k 天时也只加那么多，循环次数因此从 K 降到 O(√K)。验算用了两条路：K=6 手推 1 + 2×2 + 3×3 = 14，对上样例；K=1000 用闭式，前 44 段走完是 990 天、29370 枚，剩 10 天每天 45 枚，合计 29820，也对上。最后又写了一份逐天模拟，把 1 到 10000 全部对拍了一遍，没有差异。

#### 卡点与关键一步

- 最后一段可能不满 k 天，必须取 min(剩余天数, k)，不能整段加 k×k
- 天数是 1+2+…+k 累计、金币是 1²+2²+…+k² 累计，两者别写混
- 答案要用 long long，K 大时 int 会溢出

#### 复杂度

| 项 | 值 |
|---|---|
| 时间复杂度 | O(√K) |
| 空间复杂度 | O(1) |
