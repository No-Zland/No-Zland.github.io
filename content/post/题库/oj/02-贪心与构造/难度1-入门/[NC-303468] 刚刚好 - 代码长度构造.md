### 知识点：

这题考的不是算法，而是「读懂评测机制」：题目无输入、输出任意，SPJ 只校验提交源码的长度是否恰好 1024 字节。结论：随便写一个能编译、能正常结束的程序，再用注释把源文件精确填充或裁剪到 1024 字节。推导要点：统计的是提交源文件的字节数，注释、空格、换行全都算，所以最合适的填充物是块注释——它不影响编译，又能按字节精确控制；C++ 里只要保证 /* 与 */ 成对出现就不会破坏语法。若用 Windows 编辑器存成 CRLF，每个换行会多算 1 字节，与评测机的 LF 口径不一致，所以要统一行尾并用文件字节数（而非字符数）核对，中文注释一个字就是 3 个字节。

---

### 题目描述

> 我们的代码到这刚刚好，剩不多也不少，还能忘掉。
>
> 请确保你的代码长度为  $1024$  ，其他随意。
>
> 注意，换行符等格式符号，也会被计算。

**输入描述**

> 本题无输入。

**输出描述**

> 想输出也可以输出，不重要。

#### 示例

**输入**

```text
无
```

**输出**

```text
无
```

---

### 最终代码：

```cpp
// NC303468 刚刚好：SPJ 不检查输出，只要求提交的代码长度恰好 1024 字节。
// 所以思路是：写一个能编译、能正常结束的最小程序，再把整个文件精确填充到 1024 字节。
#include <cstdio>
int main() {
    const char w[] = {'\xE6', '\x97', '\xA0', '\0'};  // 三个字节即"无"，用转义避开编码问题
    std::fputs(w, stdout);
    return 0;
}
/* 以下为长度填充，使文件总字节数恰好 1024 */
/**************************************************************************************************************************************************************************************************************************************************************************************************************************************************************************************************************************************************************************************************************************************************************************/
```

### 解题思路

读到「请确保你的代码长度为 1024，其他随意」时我先愣了一下：无输入、无有效输出、SPJ 也不看结果，那它到底在考什么？再想一层就明白了——它考的是提交规范本身，评测机会对提交源码的字节数做特判，长度不对直接判错。于是解法分两步：第一步写一个一定能编译、一定能正常退出的小程序，顺手往 stdout 输出一个「无」（样例输出写的就是这两个字，这样和样例也对得上，虽然 SPJ 并不校验输出）；第二步把整个文件凑到恰好 1024 字节，用一段块注释当填充区。这里踩过坑：一开始凭感觉数一行星号，文件到底是 1024 还是 1023 完全没底；后来改成先写空的 /**/ 量出固定部分的字节数，再算出需要补多少颗星，最后直接读文件的字节长度确认等于 1024。输出「无」用 UTF-8 字节转义写，避免源文件编码被编译器转换导致对不上样例。

#### 卡点与关键一步

- 长度统计的是文件字节数：中文注释一个字 3 字节、CRLF 换行 2 字节，按「字符数」数必然错
- 填充必须包在注释里且 /* 与 */ 完整，否则直接编译失败
- 别把长度写成「大致 1024」，评测是精确匹配，差 1 字节也算错
