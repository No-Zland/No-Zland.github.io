### 知识点：

结论：固定选 c=2b−a，三个数 {a,b,c} 排序后必成等差数列。推导：若 a≤b，则 2b−a≥b，排序为 a,b,2b−a，公差 b−a；若 a>b，则 2b−a<b，排序为 2b−a,b,a，公差 a−b。也就是说把 b 当作等差中项，第三项自然由对称关系得到，不需要真的排序。若算出的 2b−a 非正，可换成 2a−b，此时 a 作中项，{b,a,2a−b} 同样等差。本题是 Special Judge，任何合法构造都判对，所以只需给出一种稳定写法，不必枚举所有解。

---

### 题目描述

> 小歪有两个整数  $a$  和  $b$  ，他想找到这样一个整数  $c$  ，使得这三个整数在经过排序后能成为一个等差数列。

**输入描述**

> 在一行上输入两个整数  $a,b\left(1 \leqq a,b \leqq 10^6 \right)$  代表已有的数字。

**输出描述**

> 在一行上输出一个整数代表你所找到的第三个数字。
>
> 如果存在多个解决方案，您可以输出任意一个，系统会自动判定是否正确。注意，自测运行功能可能因此返回错误结果，请自行检查答案正确性。

#### 示例 1

**输入**

```text
3 2
```

**输出**

```text
1
```

#### 示例 2

**输入**

```text
3 2
```

**输出**

```text
4
```

### 最终代码：

```cpp
#include <cstdio>

// 构造等差数列的第三项。
// 若把 b 放在中间，则 c = 2b - a，三个数重排后必为 a, b, 2b-a（差为 b-a），
// 或 2b-a, b, a（差为 a-b），一定是等差数列。
// 若 2b-a <= 0（只可能发生在 a 比 b 大很多时），改用 c = 2a - b，
// 此时 c 必为正，且 a 落在中间，同样构成等差数列。
int main() {
    long long a, b;
    if (scanf("%lld %lld", &a, &b) != 2) return 0;
    long long c = 2 * b - a;
    if (c <= 0) c = 2 * a - b;
    printf("%lld\n", c);
    return 0;
}
```

*代码为参考实现（按题意重写并用样例验证），非本人原始提交。*

### 解题思路

第一反应是分情况讨论谁当等差中项：b 当中间项得到 2b−a，a 当中间项得到 2a−b，c 当中间项则要先看 a+b 是否为偶数。三种都能写，但前两种不需要判奇偶，代码最短。我选 c=2b−a，因为不论 a、b 谁大，排序后都能成等差，只是公差正负不同，推导一遍就放心了。接着想到 a 比 b 大很多时 2b−a 可能为负；题面只说 c 是整数，负值理论上也合法，但为了输出习惯和稳妥，我加了 c≤0 时改取 2a−b 的兜底，此时 a≥2b，2a−b 必为正。最后用 3 2 验证得到 1，和样例第一组一致，再用随机数据检查排序后差值相等。

#### 卡点与关键一步

- 本题是 Special Judge，同一组输入可以有很多合法输出，样例甚至给了 3 2 的两组答案 1 和 4；本地对拍脚本若只认其中一个会误报 WA
- 不要想当然把 c 取成 a+b，排序后一般不是等差数列
- 三种构造里“c 作中项”要先判 a+b 的奇偶，直接用 2b−a 可以完全避开
