### 知识点：

结论：n 段里必须恰好选 n/2 段，让总和最大，就选最长的 n/2 段。交换论证：设最优解没选某段长度 L，而选了另一段长度 L'<L，把 L' 换成 L 后仍满足「恰好 n/2 段」的约束，总和严格变大，矛盾；所以最优解必由最大的 n/2 个元素组成。实现就是降序排序后取前 n/2 项求和，O(n log n)。n≤10⁴ 时这已足够；若 n 很大可用 nth_element 把复杂度降到期望 O(n)。这题其实在练「把『选一半』这种组合约束正确翻译成排序取前 k」的交换论证，而不是排序本身。

### 题目描述

> bs对算法有着浓厚的兴趣，所以他会尽可能的花更多的时间学习算法。假设bs有n段空余时间，n为偶数，每段空余时间只能选择算法和校内课程中其中一个进行学习，由于学校答辩无数，所以他只能选择n / 2段时间学习算法。 
>    问：bs能学习算法的最长总时间为多少？

**输入描述**

> 第一行输入一个整数n， n为偶数，代表bs的空闲时间段。2 <= n <= 10000,
> 第二行输入n个整数，代表n段时间。每段时间的长度不超过 10000， 且都大于0。

**输出描述**

> 输出bs学习算法的最长总时间。

#### 示例

**输入**

```text
10
10 1 9 2 8 3 7 4 6 5
```

**输出**

```text
40
```

### 最终代码：

```cpp
#include <cstdio>
#include <vector>
#include <algorithm>
#include <functional>

int main() {
    int n;
    if (scanf("%d", &n) != 1) return 0;
    std::vector<long long> a(n);
    for (int i = 0; i < n; i++) scanf("%lld", &a[i]);
    std::sort(a.begin(), a.end(), std::greater<long long>());
    long long sum = 0;
    for (int i = 0; i < n / 2; i++) sum += a[i];
    printf("%lld\n", sum);
    return 0;
}
```

### 解题思路

看到「只能选 n/2 段、让总时间最大」，我先问自己：选哪些？直觉是挑最长的，但要给出理由。于是用交换论证走了一遍：如果最优方案里存在「选了较短的、漏了较长的」，换掉之后总和更大且段数不变，矛盾——所以最优解就是最长的 n/2 段。想清楚这一点后代码就退化成排序。注意不是「所有大于平均值的段」也不是「前 n/2 个输入」，必须按长度排序。样例 10 1 9 2 8 3 7 4 6 5 排序后前五个是 10 9 8 7 6，和为 40，与样例一致。

#### 卡点与关键一步

- 恰好选 n/2 段，不是「所有 ≥ 平均值的段」，数量必须卡死
- 排序要降序（或升序取后一半），别按输入顺序取前 n/2 个
- 总和用 long long 更稳（虽然 n≤10⁴ 时 int 也够）

#### 复杂度

| 项 | 值 |
|---|---|
| 时间复杂度 | O(n log n) |
| 空间复杂度 | O(n) |
