### 知识点：

32 位补码本质就是整数在模 2³² 下的余数：把 x 转成 32 位无符号数（C++ 里对负数等价于加 2³²），再从第 31 位打到第 0 位，固定 32 个字符即可。题目描述的「正数原码、负数取反加一」只是这个余数的构造过程：对负数 x，~(|x| 的原码)+1 恰好等于 2³²+x 的二进制位模式，两种写法结果完全一致。因此不必真的去模拟取反加一，也不需要单独处理符号位和 0，直接按无符号位模式打印最省事，且天然正确处理 0 与 INT_MIN。结论模板：`unsigned u=(unsigned)(int)x; for b=31..0 putchar((u>>b&1)+'0');`

### 题目描述

> 你是一台超级计算机，你非常适合计算一个数字的补码，现在给你若干个数字，请你输出32位数字的01数字串代表他的补码。 
>    正数：
>  正整数的补码是其二进制表示，与原码相同
>  负数：
>  求负整数的补码，将其原码除符号位外的所有位取反（0变1，1变0，符号位为1不变）后加1

**输入描述**

> 一行输入一个数字T
> 随后T行每行一个数字代表给定数字
>  $1\leq T\leq 10^5,x在INT范围内$

**输出描述**

> 总共输出T行每行一个长度为32的数字串。

#### 示例

**输入**

```text
1
1
```

**输出**

```text
00000000000000000000000000000001
```

### 最终代码：

```cpp
#include <cstdio>

int main() {
    int T;
    if (scanf("%d", &T) != 1) return 0;
    while (T--) {
        long long x;
        scanf("%lld", &x);
        unsigned int u = (unsigned int)(int)x;  // 截断到 32 位，即为补码位模式
        char buf[33];
        for (int b = 31; b >= 0; b--) buf[31 - b] = ((u >> b) & 1u) ? '1' : '0';
        buf[32] = '\0';
        puts(buf);
    }
    return 0;
}
```

### 解题思路

第一版我老老实实按题面写：判符号、取绝对值、取反、加一、再特判 0 和 −0，代码又长又容易在 INT_MIN 上翻车（|INT_MIN| 溢出）。写到一半意识到「补码」就是模 2³² 的余数，于是把 x 强转成 unsigned int，负数的转换在标准里就是加 2³²，直接拿到位模式，再逐位输出 32 个字符，逻辑一步到位。特判全删掉后反而更稳。自测时验了三个值：1 → 31 个 0 加 1；−1 → 32 个 1；INT_MIN → 1 后跟 31 个 0，与手算和 Python 的 %032b 都一致。

#### 卡点与关键一步

- 必须固定输出 32 位，不能用不定长的二进制输出，正数前面要补 0
- INT_MIN 取绝对值会溢出，不要用 abs 或 −x 来模拟取反加一
- 读入用 long long 再接 (int) 截断更稳，避免 %d 读边界值时的意外

#### 复杂度

| 项 | 值 |
|---|---|
| 时间复杂度 | O(T) |
| 空间复杂度 | O(1) |
