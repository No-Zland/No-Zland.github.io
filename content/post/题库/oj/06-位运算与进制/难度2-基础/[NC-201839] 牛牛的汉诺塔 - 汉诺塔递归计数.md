### 知识点：

汉诺塔的移动次数要按「起点→终点」分 6 类统计，属于递归过程的分类计数模型。核心结论：把 n 个盘子从 s 移到 d（辅助杆唯一确定，a=3-s-d）的过程拆成三段——先递归 n-1 个从 s 到 a，中间单独一步 s→d，再递归 n-1 个从 a 到 d。于是 6 维计数向量满足 f(n,s,d)=f(n-1,s,a)+f(n-1,a,d)+e(s,d)，其中 e(s,d) 是只有 s→d 这一维为 1 的单位向量。由于对称性，状态只由 (n,s,d) 决定，共 6n 个，记忆化后整体 O(n)。总步数恒为 2^n-1；各类计数按 3^n 量级增长，n=60 时最大约 4.2e28，已超出 64 位整数，需要用 __int128 或高精度。

### 题目描述

> 汉诺塔是一个经典问题，相传在古印度圣庙中，有一种被称为汉诺塔(Hanoi)的游戏。该游戏是在一块铜板装置上，有三根杆(编号A、B、C)，在A杆自下而上、由大到小按顺序放置n个金盘。游戏的目标：把A杆上的金盘全部移到C杆上，并仍保持原有顺序叠好。操作规则：每次只能移动一个盘子，并且在移动过程中三根杆上都始终保持大盘在下，小盘在上，操作过程中盘子可以置于A、B、C任一杆上。 
>
>
>    汉诺塔以及其衍生问题往往使用递归来求解，也是学习和理解递归很好的老师。  
>
>
>    其伪代码如下 
>
> ```
> Function Hanoi(n,a,b,c)
>     if n==1 then
>         print(a+'->'+c)
>     else
>         Hanoi(n-1,a,c,b)
>         print(a+'->'+c)
>         Hanoi(n-1,b,a,c)
>     end if
> end Function 
> ```
>
>
>      牛牛很快就理解了代码的意思并且写出了求解汉诺塔的程序，他现在想研究汉诺塔的规律。  
>      请你统计以下信息：A->B,A->C,B->A,B->C,C->A,C->B的次数，以及所有移动的总步数。

**输入描述**

> 仅一行，输入一个正整数n $(1 \leq n \leq 60)$ 表示汉诺塔的层数。

**输出描述**

> 首先输出6行
> A->B:XX
> A->C:XX
> B->A:XX
> B->C:XX
> C->A:XX
> C->B:XX
> 分别表示每种移动情况出现的次数
> 最后输出一行
> SUM:XX
> 表示所有移动情况的总和。

#### 示例

**输入**

```text
3
```

**输出**

```text
A->B:1
A->C:3
B->A:1
B->C:1
C->A:0
C->B:1
SUM:7
```

### 最终代码：

```cpp
#include <cstdio>
#include <string>
#include <algorithm>
using namespace std;

typedef __int128 i128;

// 输出顺序固定为 A->B, A->C, B->A, B->C, C->A, C->B
int pid_of(int s, int d) {
    if (s == 0) return d == 1 ? 0 : 1;  // A->B : A->C
    if (s == 1) return d == 0 ? 2 : 3;  // B->A : B->C
    return d == 0 ? 4 : 5;              // C->A : C->B
}

int n;
i128 memo[61][3][3][6];
bool vis[61][3][3];

void go(int nn, int s, int d, i128 res[6]) {
    if (vis[nn][s][d]) {
        for (int i = 0; i < 6; i++) res[i] = memo[nn][s][d][i];
        return;
    }
    for (int i = 0; i < 6; i++) res[i] = 0;
    if (nn == 1) {
        res[pid_of(s, d)] = 1;
    } else {
        int a = 3 - s - d;   // 唯一的辅助杆
        i128 t1[6], t2[6];
        go(nn - 1, s, a, t1);   // 先把 n-1 个盘子挪到辅助杆
        go(nn - 1, a, d, t2);   // 再把 n-1 个盘子从辅助杆挪到目标杆
        for (int i = 0; i < 6; i++) res[i] = t1[i] + t2[i];
        res[pid_of(s, d)] += 1; // 中间那一步
    }
    vis[nn][s][d] = true;
    for (int i = 0; i < 6; i++) memo[nn][s][d][i] = res[i];
}

void print128(i128 x) {
    if (x == 0) { printf("0"); return; }
    string s;
    while (x > 0) { s += char('0' + (int)(x % 10)); x /= 10; }
    reverse(s.begin(), s.end());
    fputs(s.c_str(), stdout);
}

int main() {
    if (scanf("%d", &n) != 1) return 0;
    i128 res[6];
    go(n, 0, 2, res);   // A -> C
    const char *names[6] = {"A->B", "A->C", "B->A", "B->C", "C->A", "C->B"};
    i128 sum = 0;
    for (int i = 0; i < 6; i++) {
        printf("%s:", names[i]);
        print128(res[i]);
        printf("\n");
        sum += res[i];
    }
    printf("SUM:");
    print128(sum);
    printf("\n");
    return 0;
}
```

### 解题思路

第一反应是按伪代码直接模拟，把每一步的字符串打出来再统计——立刻否掉：n=60 时是 2^60 步，输出都存不下。于是改成「统计递归调用的贡献」，模拟的意义只在于弄清每类移动发生几次。我先写了一个只跑小 n 的暴力递归版，把 n=1..12 的六元组打出来，确认总步数是 2^n-1、A->C 恰好 2^(n-1) 次，再用这份暴力数据对拍正式版。正式写法是记忆化：go(n,s,d) 返回 6 元计数向量，先取辅助杆 a=3-s-d，再分别调用 go(n-1,s,a) 与 go(n-1,a,d)，最后给 s->d 加 1。因为只有 6 种 (s,d) 组合，每个 n 只有 6 个状态，递归树被压成一条链。输出按题目给定顺序逐行打印，最后一行 SUM 由六项求和，可与 2^n-1 互相校验。

#### 卡点与关键一步

- 计数是 3^n 量级，n=60 时约 4.2e28，long long 直接溢出，必须用 __int128 或高精度。
- 六行顺序固定为 A->B、A->C、B->A、B->C、C->A、C->B，不能按自己的枚举顺序输出。
- 递归拆分时辅助杆是 a=3-s-d，第二段的起点/终点是 (a,d) 而不是 (d,a)，写反了 A->C 的次数会明显偏离 2^(n-1)。

#### 复杂度

| 项 | 值 |
|---|---|
| 时间复杂度 | O(n) |
| 空间复杂度 | O(n) |
