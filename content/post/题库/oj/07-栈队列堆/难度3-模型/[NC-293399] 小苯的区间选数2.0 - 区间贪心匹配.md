### 知识点：

这题考的是把 MEX 问题转成区间与数值的配对。结论：答案就是能连续配出 0,1,...,m-1 的最大 m，做法是按值从小到大扫，每次在还没用掉、且覆盖当前值 v 的区间里挑右端点最小的那个，挑不到就结束。推导：想让 MEX≥m，必须给 0..m-1 每个值各配一个互不相同的区间，这是二分图匹配，边只在区间覆盖的值上；由于右侧是区间，具有活动安排的结构，可以贪心替代匈牙利。交换论证：若某个可行匹配把 v 配给区间 I，而我们挑了 r 最小的 J，则 J 的右端点不超过 I，把 I 换成 J 后，剩余值可用的区间集合不会变小。实现上用一个按 r 的小根堆，边扫边把 l≤v 的区间入堆，弹出 r<v 的过期项。

### 题目描述

> 给定了  $n$  个区间，小苯需要从每个区间中选择一个数字，构成一个长度为  $n$  的序列，他希望自己可以最大化序列的  $\rm MEX$ ，请你算一算  $\rm MEX$  的最大值是多少吧。
>
>  $\rm MEX:$  即最小未出现非负整数，例如  $\rm MEX\{0,1,2\}=3,\ MEX\{1,2,3\}=0$ 。

**输入描述**

> 每个测试文件均包含多组测试数据。第一行输入一个整数  $T\ (1\leqq T\leqq 100)$  代表数据组数，每组测试数据描述如下：
>
> 第一行一个正整数  $n\ (1 \leqq n \leqq 2 \times 10^5)$ ，表示区间的个数。
> 接下来  $n$  行，每行两个整数  $0 \leqq l_i \leqq r_i \leqq 10^9$ ，描述每个区间。
>
> 除此之外，保证单个测试文件的  $n$  之和不超过  $2 \times 10^5$ 。

**输出描述**

> 对于每组测试数据：
> 在单独的一行输出一个整数，表示  $\rm MEX$  的最大值。

#### 示例

**输入**

```text
2
5
0 2
0 1
3 3
3 4
2 5
3
1 1
2 2
3 3
```

**输出**

```text
5
0
```

### 最终代码：

```cpp
#include <cstdio>
#include <vector>
#include <queue>
#include <algorithm>
#include <utility>
using namespace std;

// 小苯的区间选数2.0
// 要给 0,1,2,... 每个值各找一个互不相同的区间覆盖它，
// 贪心：按左端点扫描值 v，候选区间里右端点最小的优先（活动安排式匹配）。
int main() {
    int T;
    if (scanf("%d", &T) != 1) return 0;
    while (T--) {
        int n;
        scanf("%d", &n);
        vector<pair<int, int>> seg(n);
        for (int i = 0; i < n; i++) scanf("%d %d", &seg[i].first, &seg[i].second);
        sort(seg.begin(), seg.end());
        priority_queue<int, vector<int>, greater<int>> pq;
        int idx = 0, ans = 0;
        // 最多只能匹配 n 个值：MEX <= n
        for (int v = 0; v < n; v++) {
            while (idx < n && seg[idx].first <= v) {
                pq.push(seg[idx].second);
                idx++;
            }
            while (!pq.empty() && pq.top() < v) pq.pop();
            if (pq.empty()) break;
            pq.pop();
            ans = v + 1;
        }
        printf("%d\n", ans);
    }
    return 0;
}
```

### 解题思路

第一反应是「每个区间挑一个数，求最大 MEX」，但组合数量太大，不能枚举。很快意识到 MEX 只关心 0,1,2,... 是否连续出现，于是问题变成：能不能让 0..m-1 各自落到不同的区间里。我一度想对 m 二分再判可行性，但判可行性本身就要匹配，不如直接顺序贪心。真正让我确定做法的是区间这类对象的一个直觉：越早结束的区间越不灵活，所以每个值都应该优先占用右端点最小的可用区间——这和活动安排选最早结束是同一个道理。实现时把区间按左端点排序，指针推进入堆，扫到 v 时先把 l≤v 的塞进小根堆，再把 r<v 的清掉，堆顶就是该给 v 用的区间。由于最多 n 个区间，值只需扫到 n-1。样例第一组手推正好得到 5，第二组第一下就取不到 0，输出 0。

#### 卡点与关键一步

- 每个区间只能贡献一个数，同一个值也只能出现一次，匹配是「值↔区间」的一一对应。
- 扫到 v 时必须把 r<v 的区间弹出，否则会拿到覆盖不了 v 的区间。
- 值只需扫到 n-1，MEX 不可能超过区间个数 n。

#### 复杂度

| 项 | 值 |
|---|---|
| 时间复杂度 | O(n log n) |
| 空间复杂度 | O(n) |
