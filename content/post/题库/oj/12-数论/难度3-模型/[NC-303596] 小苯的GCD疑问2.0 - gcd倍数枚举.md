### 知识点：

结论先给：固定最终 gcd=g 时，最优集合就是 [1,n] 中 g 的全部倍数 g,2g,...,mg（m=⌊n/g⌋），此时 SUM=g·m(m+1)/2，答案为 g²·m(m+1)/2，且这个集合的 gcd 恰好是 g，因为 g 本身被选中。可行性要求 m≥k，即 g≤n/k。上界证明：任何 gcd 为 G 的集合，元素都是 G 的倍数，SUM=G·（若干互不相同的倍数之和）≤G·m(m+1)/2，所以按 G 枚举不会漏掉最优。直接枚举 g 到 n/k 是 O(n) 不可行（n≤1e9），但 ⌊n/g⌋ 只有 O(√n) 种取值，同一段内 m 不变而 g² 单增，因此只需在每个块的最右端 g'=n/m 处取值。

### 题目描述

> 小红这天给了小苯一个数字  $n$ ，他希望小苯从  $\rm [1,n]$  中选择至少  $k$  个数字，将他们加入一个不可重的数字集合  $S$ 。
>
> 在小苯加入完数字后，记  $S$  中所有元素的总和、最大公约数分别为： $\rm SUM, GCD$ 。
>
> 你的任务就是帮助小苯以最优策略选择数字加入  $S$ ，以最大化： $\rm GCD\times SUM$  的值，并求出这个最大值是多少。

**输入描述**

> 每个测试文件均包含多组测试数据。第一行输入一个整数  $T\ (1\leqq T\leqq 100)$  代表数据组数，每组测试数据描述如下：
>
> 一行两个正整数  $n,k\ (1 \leqq k \leqq n \leqq 10^{9} )$ ，分别表示小红给小苯的数字，以及小苯至少需要选择的数字个数。

**输出描述**

> 对于每组测试数据：
> 在单独的一行输出一个整数，表示题中所求式子的最大值。

#### 示例

**输入**

```text
2
9 2
9 3
```

**输出**

```text
54
54
```

### 最终代码：

```cpp
#include <cstdio>
#include <string>
#include <algorithm>
using namespace std;
typedef long long ll;
typedef __int128 i128;

// 小苯的GCD疑问2.0
// 固定最终 gcd = g，能选的最优集合就是 [1,n] 中 g 的全部倍数（含 g 本身，gcd 恰为 g），
// 此时 m = floor(n/g) 个倍数，SUM = g*m(m+1)/2，值 = g^2*m(m+1)/2。
// 需要 m >= k，即 g <= n/k。同一段 m 相同的 g 里取最大的 g。
int main() {
    int T;
    if (scanf("%d", &T) != 1) return 0;
    while (T--) {
        ll n, k;
        scanf("%lld %lld", &n, &k);
        ll maxg = n / k;
        i128 best = 0;
        ll g = 1;
        while (g <= maxg) {
            ll m = n / g;
            ll hi = n / m;          // 这一段 floor(n/x) 相同的最右端点
            if (hi > maxg) hi = maxg;
            ll mm = n / hi;         // 应与 m 相同
            i128 val = (i128)hi * mm * (i128)hi * (mm + 1) / 2;
            if (val > best) best = val;
            g = hi + 1;
        }
        if (best == 0) {
            printf("0\n");
        } else {
            string s;
            while (best > 0) {
                s.push_back('0' + (int)(best % 10));
                best /= 10;
            }
            reverse(s.begin(), s.end());
            printf("%s\n", s.c_str());
        }
    }
    return 0;
}
```

### 解题思路

看到「至少 k 个」和「最大化 GCD×SUM」，第一反应是枚举 gcd，因为 gcd 只能是某个整数 g，一旦定下来，选数范围就限定在 g 的倍数里。接着想选多少个：直觉是选得越多 SUM 越大，而把所有倍数都选上 gcd 仍然是 g（g 自己就在里面），所以每个 g 都选满 m=⌊n/g⌋ 个，不需要在个数上做取舍。于是得到 g²·m(m+1)/2。第二道坎是 n 到 1e9，不能从 1 枚举到 n/k；我注意到 m=⌊n/g⌋ 随 g 分段为常数，段数只有 O(√n)，段内答案对 g 单调，所以每段只算右端点。写完后用 n=9,k=2 手推：g=3 得 9·6=54，比 g=1 的 45、g=2 的 40 都大，和样例一致；n=9,k=3 同样 54。最后为了保险，把乘法都放进 __int128。

#### 卡点与关键一步

- 「至少 k 个」不是恰好 k 个：固定 g 时选满 m 个倍数 SUM 更大，gcd 也不会变，别只选 k 个。
- 可行条件是 m=⌊n/g⌋≥k，枚举上界是 n/k，越界会算出元素不足 k 个的非法答案。
- 答案最大到 n²（1e18），long long 处在边缘，中间乘法用 __int128 更稳。

#### 复杂度

| 项 | 值 |
|---|---|
| 时间复杂度 | O(√n) |
| 空间复杂度 | O(1) |
