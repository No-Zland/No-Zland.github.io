# Linux 用户与组的基本概念

Linux 是多用户、多任务操作系统，通过 “用户 - 组 - 权限” 的层级模型实现资源访问控制，确保不同使用者的操作边界清晰。

## 用户（User）的分类

Linux 系统中的用户分为三类，对应不同的系统权限与使用场景：

| 用户类型 | 特点 | 适用场景 |

|---|---|---|

| 超级用户（root） | UID（用户 ID）固定为 0，拥有系统最高权限，可执行任何操作（如修改系统配置、删除核心文件） | 系统管理员维护（如安装软件、管理用户） |

| 系统用户 | UID 范围通常为 1-999（不同发行版可能微调），用于运行系统服务（如 Apache、MySQL），无登录权限 | 系统进程运行，避免服务以 root 权限风险运行 |

| 普通用户 | UID 范围通常为 1000 及以上，权限受限制，仅能操作自身家目录及授权资源 | 日常用户使用（如编写代码、查看文档） |

## 组（Group）的分类

组是用户的集合，用于批量管理用户权限，分为三类：

| 组类型 | 特点 | 作用 |

|---|---|---|

| 私有组（初始组） | 每个用户创建时默认生成，组名与用户名相同，且仅包含该用户 | 保障用户初始文件的私有性 |

| 公有组（附加组） | 由管理员创建，可添加多个用户，组内用户共享该组的权限 | 批量授权（如让多个用户访问同一项目目录） |

| 系统组 | 与系统用户对应，用于管理系统服务，组 ID（GID）通常为 1-999 | 保障系统服务的权限隔离 |

## 3.1.3 核心配置文件

用户与组的信息均存储在系统配置文件中，修改这些文件（需 root 权限）会直接影响用户 / 组状态，常见核心文件如下：

| 配置文件路径 | 功能描述 |

|---|---|

| /etc/passwd | 存储所有用户的公开信息（用户名、UID、GID、家目录、登录 Shell 等），所有用户可读取 |

| /etc/shadow | 存储用户的密码信息（加密后的密码、密码过期时间等），仅 root 可读取 |

| /etc/group | 存储所有组的公开信息（组名、GID、组内用户列表），所有用户可读取 |

| /etc/gshadow | 存储组的密码信息（如组管理员密码），仅 root 可读取（部分系统用不到） |

| /etc/login.defs | 定义用户创建的默认规则（如 UID/GID 范围、密码过期天数、家目录默认路径） |

# Linux 用户管理命令

用户管理涵盖 “创建 - 查询 - 修改 - 删除” 全生命周期，核心命令以表格形式呈现，所有命令需 root 权限（可通过sudo前缀执行）。

## 用户创建命令：useradd

useradd用于创建新用户，默认遵循/etc/login.defs的规则，可通过选项自定义配置。

| 命令名称 | 功能描述 | 样例（执行效果） |

|---|---|---|

| useradd | 创建新用户，支持通过选项指定 UID、家目录、登录 Shell 等 | 1. useradd testuser：创建默认配置的普通用户testuser（家目录为/home/testuser）2. useradd -u 1050 -d /opt/test -s /bin/bash testuser2：创建 UID=1050、家目录为/opt/test、登录 Shell 为/bin/bash的用户testuser2 |

## 用户密码设置命令：passwd

passwd用于设置或修改用户密码（Linux 用户默认无密码，需手动设置后才能登录）。

| 命令名称 | 功能描述 | 样例（执行效果） |

|---|---|---|

| passwd | 1. 不加用户名时，修改当前登录用户的密码；2. 加用户名时，修改指定用户的密码（需 root 权限） | 1. passwd：当前用户修改自身密码（需输入旧密码验证）2. passwd testuser：root 为testuser设置密码（执行后按提示输入密码，密码不显示）3. passwd -l testuser：锁定testuser（无法登录，解锁用-u） |

## 用户信息查询命令：id、finger、whoami

用于查看用户的 UID、GID、所属组等信息，不同命令侧重不同。

| 命令名称 | 功能描述 | 样例（执行效果） |

|---|---|---|

| id | 显示用户的 UID、GID 及所属的所有组（最常用） | id testuser：输出uid=1001(testuser) gid=1001(testuser) groups=1001(testuser)（显示testuser的 UID、GID 及所属组） |

| finger | 显示用户的详细信息（含用户名、家目录、登录 Shell、最近登录时间等） | finger testuser：输出testuser的完整信息（需先安装finger工具，如yum install finger） |

| whoami | 显示当前登录用户的用户名（简单查询） | 若当前以testuser登录，执行whoami输出testuser |

## 用户信息修改命令：usermod

usermod用于修改已存在用户的配置（如 UID、家目录、所属组等），需注意：修改正在登录的用户可能导致异常。

| 命令名称 | 功能描述 | 样例（执行效果） |

|---|---|---|

| usermod | 修改用户的属性，支持选项与useradd类似（如-u改 UID、-d改家目录、-g改初始组） | 1. usermod -u 1060 testuser：将testuser的 UID 改为 10602. usermod -aG dev testuser：将testuser添加到dev附加组（-a表示 “追加”，避免覆盖原有附加组） |

## 用户删除命令：userdel

userdel用于删除用户，默认仅删除用户账号，需通过选项删除关联资源。

| 命令名称 | 功能描述 | 样例（执行效果） |

|---|---|---|

| userdel | 删除用户，-r选项可同时删除用户的家目录和邮件目录 | 1. userdel testuser：仅删除testuser的账号（家目录/home/testuser保留）2. userdel -r testuser2：删除testuser2的账号及关联的家目录、邮件目录 |

# Linux 组管理命令

组管理与用户管理逻辑类似，核心命令围绕 “创建 - 查询 - 修改 - 删除”，同样需 root 权限。

## 组创建命令：groupadd

groupadd用于创建新组，默认遵循/etc/login.defs的 GID 范围规则。

| 命令名称 | 功能描述 | 样例（执行效果） |

|---|---|---|

| groupadd | 创建新组，-g选项可指定 GID | 1. groupadd dev：创建默认 GID 的dev组2. groupadd -g 1030 testgroup：创建 GID=1030 的testgroup组 |

## 组信息查询命令：groups、grep（结合配置文件）

用于查看用户所属组或组的详细信息。

| 命令名称 | 功能描述 | 样例（执行效果） |

|---|---|---|

| groups | 显示指定用户所属的所有组（初始组 + 附加组） | groups testuser：输出testuser : testuser dev（表示testuser的初始组是自身，附加组是dev） |

| grep | 结合/etc/group文件查询组信息（适用于批量查询或精确匹配） | grep "^dev" /etc/group：查询dev组的信息，输出dev:x:1029:（组名、加密标记、GID、组内用户） |

## 组信息修改命令：groupmod

groupmod用于修改已存在组的属性（如组名、GID）。

| 命令名称 | 功能描述 | 样例（执行效果） |

|---|---|---|

| groupmod | 修改组的属性，-g改 GID，-n改组名 | 1. groupmod -g 1040 dev：将dev组的 GID 改为 10402. groupmod -n develop dev：将dev组的名称改为develop |

## 组删除命令：groupdel

groupdel用于删除组，需注意：不能删除用户的初始组（需先修改用户的初始组或删除用户）。

| 命令名称 | 功能描述 | 样例（执行效果） |

|---|---|---|

| groupdel | 删除指定组（前提：组不是任何用户的初始组，且组内无用户） | 1. groupdel testgroup：删除testgroup组（若该组是某用户的初始组，会提示错误）2. 若删除dev组提示 “组是初始组”，需先执行usermod -g othergroup testuser（将testuser的初始组改为othergroup），再删除dev组 |

## 组内用户管理命令：gpasswd

gpasswd用于精细化管理组内用户（如添加 / 删除组内用户、设置组管理员），是usermod -aG的补充。

| 命令名称 | 功能描述 | 样例（执行效果） |

|---|---|---|

| gpasswd | 1. -a 用户名 组名：添加用户到组；2. -d 用户名 组名：从组删除用户；3. -A 用户名 组名：设置组管理员 | 1. gpasswd -a testuser dev：将testuser添加到dev组（等同于usermod -aG dev testuser）2. gpasswd -d testuser dev：将testuser从dev组删除3. gpasswd -A adminuser dev：设置adminuser为dev组的管理员（可管理组内用户） |

# 特殊用户与组管理

## 超级用户（root）的权限控制

root 拥有系统最高权限，为避免误操作，通常建议：

- 日常操作使用普通用户，需管理员权限时通过sudo命令临时获取（sudo 命令，如sudo useradd newuser）；

- 禁止 root 直接远程登录：修改/etc/ssh/sshd_config文件，设置PermitRootLogin no，重启 SSH 服务（systemctl restart sshd）。

## 系统用户 / 组的特殊性

系统用户（如bin、daemon）和系统组（如sys、adm）用于运行系统服务，其特点：

- 无登录 Shell（/sbin/nologin或/bin/false），无法通过终端登录；

- UID/GID 在 1-999 范围内，与普通用户区分；

- 禁止删除或修改系统用户 / 组，否则可能导致系统服务崩溃（如删除apache用户会导致 Apache 服务无法启动）。
