# 递推、递归与分治

> 一句话本质：递推把答案排成一张有依赖的表自底向上填，递归把大问题缩成同形小问题自顶向下拆，分治在递归之上还要付「合并」的代价。

## 一、是什么

**递推**：写出 $f(n)$ 与更小项的关系，从初值沿依赖顺序逐个算出 $f(n)$，不产生函数调用。**递归**：把 $f(n)$ 交给 $f(n-1)$，触底后逐层返回，答案在返回路上组装。**分治**：把区间劈成两半分别递归，再把两半结果合并——钱花在合并，不在劈。

识别信号：

1. 问「第 $n$ 项」「$n$ 级台阶几种走法」，$n$ 很大而前几项能手算。
2. 题面自带二选一（走 1 步或 2 步、取 1 个或 2 个）——转移式就是两项相加。
3. 大区间能劈成两半，答案由左右两半拼出（逆序对、最近点对、区间最值）。
4. 数「合法括号序列」「出栈顺序」「二叉树形态」——卡特兰，手算前三项对照。
5. 递归能跑但 $n$ 一大就超时，函数反复收到同样的参数——缺记忆化。
6. 递归深度等于 $n$ 且 $n\ge10^5$，本地小数据正常、大数据 RE——该改迭代。

不该用它：子问题既不重叠又没有可合并的结构（递归只是把循环写复杂）；转移依赖「未来」的状态（有后效性，该换 DP 的状态设计）；深度 $10^5$ 的递归（默认栈只有几 MB）。

## 二、形式

递推三要素：初值、转移、边界。

$$f(1)=1,\quad f(2)=2,\quad f(n)=f(n-1)+f(n-2)\ (n\ge3)$$

分治的代价式，主定理的直觉版就是比大小：

$$T(n)=aT(n/b)+f(n)\quad\text{与}\quad n^{\log_b a}\ \text{比较}$$

汉诺塔 $H(n)=2H(n-1)+1$、$H(1)=1$，展开得 $H(n)=2^n-1$。代码形式：`long long f(int n)` 或 `for` 迭代；分治写成 `long long solve(int l, int r)`，函数体固定三段「边界 → 递归 → 合并」。数据形式：`memo[]` 存状态（或滚动两个变量），分治另需一个 `tmp[]` 承接合并结果。

## 三、怎么理解

直觉：递推像多米诺，前一块必须真的能推倒后一块；分治像两人各整理一半扑克牌，最后把两叠有序牌并成一叠才是真正费钱的那步。

为什么正确：递归靠数学归纳——假设规模小于 $n$ 的答案都正确，只要「边界正确」且「转移/合并保持正确」，结论对 $n$ 成立。归并求逆序对的合并不变量是「两半各自有序，跨区间逆序对个数 = 左半剩余元素个数」，每个逆序对只在 $a[i]>a[j]$ 那一次被数，不重不漏。

手推：斐波那契 $1,1,2,3,5,8,13$，故 $f(6)=8$。汉诺塔 $n=3$：把上面 2 个移到 B（3 步）、最大盘到 C（1 步）、2 个再移过去（3 步），共 7 步 $=2^3-1$。逆序对 $[3,1,2]$：劈成 $[3]$ 与 $[1,2]$，右半内部 0 个；合并时 3>1 记 1、3>2 记 1，共 2。

## 四、怎么变成代码

映射：初始项就写 `if (n <= 2) return n;`，别用「看起来像」的数列；`memo` 用 $-1$ 表示未算，别用 $0$——合法答案可能就是 0；闭区间 $(l,r)$ 与 `mid = l + (r-l)/2` 配套，`l >= r` 是叶子；`tmp` 合并后必须整体回填 `a[l..r]`，否则上层拿到旧值；分治顺序必须是先递归、后合并，因为合并要消费两半已排序的结果。

```cpp
#include <iostream>
#include <vector>
using namespace std;

vector<long long> memo;

long long climb(int n) {                     // 爬楼梯：每次 1 级或 2 级
    if (n <= 2) return n;                    // f(1)=1, f(2)=2
    if (memo[n] != -1) return memo[n];       // 记忆化：-1 表示未算
    return memo[n] = climb(n - 1) + climb(n - 2);
}

long long hanoi(int n) {                     // H(n) = 2H(n-1) + 1
    return n == 1 ? 1 : 2 * hanoi(n - 1) + 1;
}

long long mergeCount(vector<int>& a, vector<int>& tmp, int l, int r) {
    if (l >= r) return 0;                                  // 单元素无逆序对
    int mid = l + (r - l) / 2;
    long long cnt = mergeCount(a, tmp, l, mid) + mergeCount(a, tmp, mid + 1, r);
    int i = l, j = mid + 1, k = l;
    while (i <= mid && j <= r) {
        if (a[i] <= a[j]) tmp[k++] = a[i++];
        else { tmp[k++] = a[j++]; cnt += mid - i + 1; }    // 左半剩余全大于 a[j]
    }
    while (i <= mid) tmp[k++] = a[i++];
    while (j <= r) tmp[k++] = a[j++];
    for (int t = l; t <= r; ++t) a[t] = tmp[t];            // 回填，别省
    return cnt;
}

int main() {
    memo.assign(64, -1);
    cout << climb(10) << "\n";                 // 89
    cout << hanoi(3) << "\n";                  // 7
    vector<int> a = {3, 1, 2}, tmp(3);
    cout << mergeCount(a, tmp, 0, 2) << "\n";  // 2
    return 0;
}
```

## 五、具体例子

### 1. 爬楼梯：递推三要素

问题：$n$ 级台阶，每次走 1 或 2 级，求方案数，$n\le90$。套形式：最后一步只能从 $n-1$ 跨 1 级、或从 $n-2$ 跨 2 级，两类互斥且穷尽，故按加法原理相加——不是「长得像斐波那契」，是分类讨论的结果。复杂度 $O(n)$ 时间，滚动后 $O(1)$ 空间。

```cpp
#include <iostream>
using namespace std;

long long climbFloor(int n) {
    if (n <= 2) return n;                    // f(1)=1, f(2)=2
    long long a = 1, b = 2;                  // f(n-2), f(n-1)
    for (int i = 3; i <= n; ++i) {
        long long c = a + b;
        a = b;
        b = c;
    }
    return b;
}

int main() {
    cout << climbFloor(5) << "\n";           // 8
    return 0;
}
```

### 2. 汉诺塔：递归树与 $2^n-1$

问题：把 $n$ 个盘从 A 经 B 移到 C，每次只能移一个且大盘不能压小盘，打印移动序列。递归树恰好 $2^n-1$ 个结点，每个结点对应一次真实移动，所以复杂度就是 $O(2^n)$——这也解释了为什么 $n=64$ 只能算公式不能真跑。

```cpp
#include <iostream>
using namespace std;

void move(int n, char from, char to, char via) {
    if (n == 0) return;
    move(n - 1, from, via, to);              // 先把上面 n-1 个挪开
    cout << from << "->" << to << "\n";      // 最大盘落下
    move(n - 1, via, to, from);              // 再把 n-1 个挪回来
}

int main() {
    move(3, 'A', 'C', 'B');                  // 7 行
    return 0;
}
```

复杂度 $O(2^n)$ 时间、$O(n)$ 递归栈。`move(n-1, from, via, to)` 的参数顺序是最容易写反的地方，反了不会报错，只会输出不可行的序列。

### 3. 归并排序求逆序对

问题：$n\le10^5$，求逆序对个数。暴力两两比较是 $5\times10^9$，必超时。套分治：$T(n)=2T(n/2)+O(n)$，每层合并总代价 $O(n)$、共 $\log_2n$ 层。代码即上面的 `mergeCount`。复杂度 $O(n\log n)$ 时间、$O(n)$ 空间。

## 六、复杂度与易错点

| 项 | 值 |
|---|---|
| 时间复杂度 | 朴素递归 $O(1.618^n)$；记忆化后 $O(n)$；分治 $O(n\log n)$；汉诺塔输出本身 $O(2^n)$ |
| 空间复杂度 | 记忆化 $O(n)$；递归栈 $O(n)$；归并辅助数组 $O(n)$ |

- `memo` 用 `if (memo[n])` 判「算过没」，答案为 0 的状态被无限重算。
- 递归深度到 $10^5$ 爆栈，本地小数据正常、评测 RE。
- 逆序对写 `cnt += mid - i`，漏 `+1`，答案系统性偏小。
- 合并后忘回填 `a[l..r]`，上层拿到未排序的数组，逆序对少算。
- 递推只在最后取模，中间乘法先溢出成负数。
- $H(n)=2^n-1$ 在 $n=64$ 时超出 `long long`，该取模或上高精度。
