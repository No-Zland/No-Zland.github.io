# 位运算、进制与高精度

> 一句话本质：位运算把整数当成 32 个独立比特并行操作，高精度把竖式翻译成数组——都是换一个表示，问题就变简单。

## 一、是什么

位运算是对整数二进制表示逐位施加的操作（`& | ^ ~ << >>`）。它的本质是：一个 `int` 就是 32 个布尔值，一次 `&` 等于 32 次布尔与**并行**执行。所以位运算的真正用途不是「省时间」，而是**把集合塞进一个整数**。

高精度是用数组存一个超出内置类型范围的整数，按十进制位模拟竖式加减乘。它本质上是「把小学算术写成循环」：数位是数组元素，进位是变量。

位运算解决：状态压缩（$n\le20$ 时「选哪些」就是 $2^n$ 个子集）、lowbit 类的树形跳转（树状数组）、溢出与符号判断、异或的消去律。高精度解决：超过 19 位（`long long` 上限 $9.2\times10^{18}$）的加减乘、$2^p$ 的位数、阶乘、大斐波那契项。

识别信号：

- 出现「二进制」「第 $k$ 位」「2 的幂」「按位与 / 或 / 异或」；
- $n \le 20\sim25$，要枚举所有选取方案；
- 顶到 $10^{18}$ 还要相乘，或答案位数明显超过 19 位；
- 输入是上百位的数字字符串；
- 出现「$k$ 进制」「进制转换」「末尾有几个 0」；
- 出现「只出现一次的数」「区间异或和」——异或消去律 $a\oplus a=0$。

不该用它的时候：

- $n>25$ 还枚举子集：$2^{30}$ 必死，该换 meet-in-the-middle 或 DP；
- 值域没超过 `long long` 却写高精度：徒增常数与出错面；
- 需要高精除高精：$O(n^2)$ 且极易写错，优先找取模或数论做法；
- 用 $2^{64}$ 自然溢出做「精确」判断：它只是概率正确，数据可以构造。

## 二、形式

**数学形式.** 补码（$w$ 位，模 $M=2^w$）：

$$-x \equiv \sim x + 1 \pmod{M}, \qquad x + \sim x = M - 1.$$

lowbit 取最低位的 1，它等于 $2^{\text{ctz}(x)}$：

$$\text{lowbit}(x) = x \,\&\, (-x) = x \,\&\, (\sim x + 1).$$

高精度乘法（低位在前，$a_i$ 是第 $i$ 位）：先卷积再进位，

$$c_k = \sum_{i+j=k} a_i b_j, \qquad c_k \leftarrow (c_k + \text{carry}) \bmod 10.$$

位数估计：$2^p$ 的十进制位数为 $\lfloor p\log_{10}2\rfloor + 1$。

**代码形式.**

```cpp
#include <vector>
#include <string>
using namespace std;

int lowbit(int x);                    // 最低位的 1
using Big = vector<int>;              // 低位在前
Big mul(const Big& a, const Big& b);  // 竖式乘法
```

**数据形式.** 位运算的状态就是一个整数的比特位，`mask` 的第 $i$ 位表示「选不选第 $i$ 个」。高精度的状态是 `vector<int>`，`v[0]` 是个位，长度可变，最高位不为 0（0 本身除外）。

## 三、怎么理解

**直觉.** 补码像模 $2^w$ 的钟表：$-x$ 就是「再走 $M-x$ 步回到 0」的刻度。lowbit 像一排开关，`x & -x` 找到最右边亮着的那盏灯——因为 $-x$ 把 $x$ 从最低位的 1 起全部翻转再进一位，相与后只剩那一位。子集枚举像「只允许在 `mask` 的 1 位上做减法」，减完自动借位，于是每次都能落在另一个子集上。

**为什么 $-x=\sim x+1$.** $x$ 与 $\sim x$ 逐位互补，相加每位都是 1，故 $x+\sim x = M-1$；再加 1 得 $x+(\sim x+1)=M\equiv0$。按定义 $\sim x+1$ 就是 $x$ 的加法逆元，而模 $M$ 下逆元唯一。

**为什么 `INT_MIN` 取反还是它自己.** `INT_MIN` $=-2^{31}$，相反数是 $+2^{31}$，超出 `int` 上界 $2^{31}-1$。模 $2^{32}$ 下 $-(-2^{31})\equiv2^{31}$，而 $2^{31}$ 的 32 位补码正是 `0x80000000`，即 `INT_MIN` 的位模式。不是巧合，是溢出回绕；`abs(INT_MIN)` 因此是未定义行为。

**为什么乘法要先累加后进位.** $c_k$ 会被多个 $(i,j)$ 命中。若边乘边进位，后面再加进来的乘积会撞上已被清空的位，结果错位，而且错误只在某些数位上出现，极难调。

**手推 $123\times45$.** $a=[3,2,1]$、$b=[5,4]$，先卷积：$c_0=3\times5=15$，$c_1=3\times4+2\times5=22$，$c_2=2\times4+1\times5=13$，$c_3=1\times4=4$，得 $[15,22,13,4,0]$。再统一进位：$c_0=5$ 进 1，$c_1=23\to3$ 进 2，$c_2=15\to5$ 进 1，$c_3=5$。结果 $[5,3,5,5]$，即 $5535=123\times45$。

## 四、怎么变成代码

映射：

- `i, j`：两个数的十进制位下标，从 0（个位）开始；`c[i+j]` 是「第 $i+j$ 位」的**未进位累加值**。
- `carry`：上一位留下的进位。加法、乘法的进位都只由当前一位决定，所以都能用一个变量顺序推进。
- 循环顺序（乘法）：**两趟**。第一趟双重循环只累加，第二趟单循环统一进位。结果数组开 $|a|+|b|$ 位，乘积位数不超过两者位数之和。
- 边界：最后去前导零，但要保底留一位，否则 $0\times0$ 会输出空串。
- 子集枚举：`s = (s-1) & mask` 在 $s=0$ 后会绕回 `mask`，必须先 `break`。
- 进制转换：短除取余再逆序，是从低位往高位生成；秦九韶 $v=v\cdot base+d$ 一趟扫完，是从高位往低位。`0` 必须特判，否则返回空串。
- 类型选择：不超过 18 位用 `long long`，不超过 38 位用 `__int128`（它不能直接 `cin` / `cout`），再大才上高精度。`1 << 31` 是有符号溢出，写 `1u << 31`。

完整模板：

```cpp
#include <vector>
#include <string>
#include <algorithm>
#include <cctype>
using namespace std;

int lowbit(int x) { return x & -x; }                  // 12 -> 4

int popcountOf(unsigned x) {                           // 数 1，O(popcount)
    int c = 0;
    while (x) { x &= x - 1; ++c; }                     // 每次消掉最低位的 1
    return c;
}

template <class F>
void enumSubsets(int mask, F f) {                      // 枚举全部子集，含 0
    for (int s = mask; ; s = (s - 1) & mask) {
        f(s);
        if (s == 0) break;                             // 0 再减会绕回 mask
    }
}

string toBase(unsigned long long n, int base) {        // 十进制 -> 2..36 进制
    if (n == 0) return "0";                            // 不特判就返回空串
    string s;
    while (n) {
        int d = int(n % base);
        s += char(d < 10 ? '0' + d : 'A' + d - 10);
        n /= base;
    }
    reverse(s.begin(), s.end());                       // 短除逆序即高位在前
    return s;
}

long long fromBase(const string& s, int base) {        // 秦九韶，O(len)
    long long v = 0;
    for (char ch : s) {
        int d = isdigit((unsigned char)ch) ? ch - '0'
                                           : toupper((unsigned char)ch) - 'A' + 10;
        v = v * base + d;                              // 从左到右累乘
    }
    return v;
}
```

## 五、具体例子

### 例 1：lowbit 与子集枚举（$n\le20$）

问题：$n\le20$ 个正整数 $w_i$ 与目标 $S$，求元素和恰为 $S$ 的子集个数。

套哪个形式：状态压缩。`mask` 的二进制位表示「选 / 不选」，全集 $2^n\le10^6$。逐位扫是 $O(n2^n)$，用 lowbit 递推可降到 $O(2^n)$：取 `low = mask & -mask`，其下标为 `ctz(mask)`，则

$$\text{sum}[mask] = \text{sum}[mask \oplus low] + w_{\text{ctz}(mask)}.$$

$mask\oplus low$ 严格小于 `mask`，所以按 `mask` 递增枚举即可。

```cpp
#include <cstdio>
#include <vector>
using namespace std;

int main() {
    int n; long long S;
    scanf("%d %lld", &n, &S);
    vector<long long> w(n);
    for (long long& x : w) scanf("%lld", &x);
    int full = 1 << n;
    vector<long long> sum(full, 0);
    long long ans = 0;
    for (int mask = 1; mask < full; ++mask) {
        int low = mask & -mask;                       // 最低位的 1
        int idx = __builtin_ctz((unsigned)mask);      // 它的下标
        sum[mask] = sum[mask ^ low] + w[idx];         // 规模更小的子问题
        if (sum[mask] == S) ++ans;
    }
    printf("%lld\n", ans);
    return 0;
}
```

复杂度：$O(2^n)$ 时间、$O(2^n)$ 空间。

### 例 2：补码，`-x = ~x + 1`

问题：不用 `-` 求相反数，并解释 `INT_MIN` 取反后为何还是它。

```cpp
#include <cstdio>
#include <climits>

unsigned negBits(unsigned x) { return ~x + 1u; }   // 位模式层面的取负

int main() {
    int x = -5;
    printf("%d\n", (int)negBits((unsigned)x));     // 5
    unsigned m = (unsigned)INT_MIN;                // 0x80000000
    printf("%u %u\n", m, negBits(m));              // 2147483648 2147483648
    return 0;
}
```

`-5` 的补码手算：$5=$ `000…0101`，取反 `111…1010`，加一 `111…1011`，即 $-5$。对 `INT_MIN` 做同一操作，位模式不变，所以「取反还是它」。

复杂度：$O(1)$。

### 例 3：高精度乘法（竖式 + 进位）

问题：求两个不超过 500 位的十进制数之积，如 $123\times45=5535$。

套哪个形式：卷积 + 统一进位。$c_{i+j}$ 累加 $a_ib_j$，最后从低位到高位扫一遍进位。

```cpp
#include <cstdio>
#include <vector>
#include <string>
#include <algorithm>
using namespace std;

using Big = vector<int>;                        // 低位在前

Big toBig(const string& s) {
    Big a;
    for (int i = (int)s.size() - 1; i >= 0; --i) a.push_back(s[i] - '0');
    while (a.size() > 1 && a.back() == 0) a.pop_back();
    return a;
}

string toString(const Big& a) {
    string s;
    for (int i = (int)a.size() - 1; i >= 0; --i) s += char('0' + a[i]);
    return s;
}

Big mul(const Big& a, const Big& b) {
    Big c(a.size() + b.size(), 0);              // 位数之和够放
    for (size_t i = 0; i < a.size(); ++i)
        for (size_t j = 0; j < b.size(); ++j)
            c[i + j] += a[i] * b[j];            // 第一趟：只累加
    int carry = 0;
    for (size_t i = 0; i < c.size(); ++i) {     // 第二趟：统一进位
        int v = c[i] + carry;
        c[i] = v % 10;
        carry = v / 10;
    }
    while (c.size() > 1 && c.back() == 0) c.pop_back();   // 去前导零
    return c;
}

int main() {
    char sa[512], sb[512];
    scanf("%511s %511s", sa, sb);
    printf("%s\n", toString(mul(toBig(sa), toBig(sb))).c_str());
    return 0;
}
```

复杂度：$O(nm)$ 时间，$O(n+m)$ 空间。$10^4$ 位相乘是 $10^8$ 级，多半要 T，那时才轮到 NTT 或压位。

## 六、复杂度与易错点

| 操作 | 时间复杂度 | 空间复杂度 |
|---|---|---|
| 单次位运算 / lowbit | $O(1)$ | $O(1)$ |
| 子集枚举 | $O(2^n)$ 或 $O(2^{\text{popcount}})$ | $O(1)$ |
| 进制转换 | $O(\log_{base} n)$ / $O(\text{len})$ | $O(1)$ |
| 高精度加 / 乘 | $O(n)$ / $O(nm)$ | $O(n+m)$ |

1. `1 << 31` 与 `abs(INT_MIN)` 都是未定义行为，前者写 `1u << 31`，后者手动判。
2. 子集枚举少了 `if (s == 0) break;`，0 之后回绕到 `mask`，死循环。
3. `toBase` 没特判 0，返回空串，第一个点就 WA。
4. 高精度乘法边乘边进位，中间的 `carry` 被后续乘积污染，结果错位。
5. `__int128` 直接用 `cout` 输出，编译不过或乱码。
6. 估位数忘了 $+1$，$2^{10}=1024$ 是 4 位却按 3 位判断，选错类型。
