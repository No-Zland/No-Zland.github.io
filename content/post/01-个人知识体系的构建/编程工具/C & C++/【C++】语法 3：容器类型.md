# C++ 语法3：容器类型

这篇覆盖竞赛起步阶段真正会用到的容器：`vector`、`pair`、`map` / `unordered_map`、`set` / `multiset`、`stack`、`queue`、`priority_queue`。不追求讲全，只追求**知道什么时候该用哪个、怎么写不会挂**。

## 1. 先建立选择习惯：按需求选容器，不按名字选

竞赛中选容器只看三个问题：**要不要有序？要不要去重？是不是只关心最大/最小？**

| 需求 | 容器 | 核心操作复杂度 |
|---|---|---|
| 变长数组，按下标访问 | `vector` | 下标 O(1)，尾部增删均摊 O(1) |
| 把两个值捆在一起 | `pair` | 自带比较 |
| 键值映射，需要按 key 有序 | `map` | 插入/查找/删除 O(log n) |
| 键值映射，只关心查找速度 | `unordered_map` | 平均 O(1)，最坏 O(n) |
| 去重 + 有序 + 查找是否存在 | `set` | O(log n) |
| 允许重复 + 有序 | `multiset` | O(log n) |
| 后进先出 | `stack` | O(1) |
| 先进先出 | `queue` | O(1) |
| 每次取最大/最小 | `priority_queue` | 插入 O(log n)，取顶 O(1) |

一个常见的误区是“`unordered_map` 平均 O(1)，所以永远比 `map` 快”。**平均不等于保证**：`unordered_map` 在哈希碰撞严重时会退化到 O(n)，Codeforces 上出现过用 `unordered_map` 被卡到 TLE、换成 `map` 反而 AC 的案例。如果题目需要有序性，或者输入可能构造哈希碰撞，`map` 的 O(log n) 是确定性的，反而更稳。

## 2. `vector`：默认的动态数组

`vector` 是竞赛中使用频率最高的容器，没有之一。基础操作在基础篇已经讲过，这里只补充竞赛中真正需要留意的点。

### 2.1 两种构造方式，性能差别很大

```cpp
vector<int> a(n);              // 直接指定大小，一次分配，后续按下标访问
vector<int> b;
for (int i = 0; i < n; i++) b.push_back(x);  // 空 vector + 反复 push_back
```

第一种写法和原生 `new int[n]` 在访问性能上**没有实质差异**，底层就是连续内存，下标访问编译后和指针偏移一样。第二种写法不是错，但 `push_back` 每次要检查容量、偶发扩容时要整体搬移，在 \(n\) 很大且需要极致压常数时可能成为瓶颈。**如果一开始就知道大小，直接用 `vector<int> a(n)`**。

### 2.2 `vector` 扩容会导致迭代器、指针、引用全部失效

```cpp
vector<int> v = {1, 2, 3};
int* p = &v[0];
v.push_back(4);        // 可能扩容，v 的元素整体搬到新内存
// *p 现在是悬空指针，未定义行为
```

竞赛中最容易踩这个坑的场景是：**边遍历 `vector` 边插入**。如果必须这样做，改用下标循环，或者提前 `v.reserve(n)` 预留足够空间。

### 2.3 二维 `vector` 的竞赛写法

**已知 \(n\) 行 \(m\) 列**，直接构造：

```cpp
vector<vector<int>> a(n, vector<int>(m));
```

**行数已知、每行长度不定**，先开 \(n\) 个空行，再逐行 `push_back`：

```cpp
vector<vector<int>> a(n);
for (int i = 0; i < n; i++) {
    for (int j = 0; j < m; j++) {
        int x; cin >> x;
        a[i].push_back(x);
    }
}
```

二维 `vector` 的内存**不是连续的**（每行单独分配），访问时多一次指针间接，缓存命中率不如一维连续数组。如果题目对常数敏感，可以用一维数组手动偏移：`grid[i * m + j]` 代替 `a[i][j]`。起步阶段不必强求，知道有这回事即可。

## 3. `pair`：把两个值捆在一起，白送比较

```cpp
pair<int, int> p = {3, 5};
p.first;   // 3
p.second;  // 5

pair<int, int> q = make_pair(3, 5);
```

`pair` 的价值在于**自带字典序比较**：先比 `first`，`first` 相同再比 `second`。这意味着 `pair` 可以直接放进 `set`、`map` 的 key，也可以直接 `sort`，不需要手写 `cmp`：

```cpp
vector<pair<int, int>> v = {{2, 3}, {1, 5}, {1, 2}};
sort(v.begin(), v.end());
// 结果：{1, 2}, {1, 5}, {2, 3}
```

二维坐标、区间端点、需要同时维护“值 + 下标”时，`pair` 是最省事的选择。

## 4. `map` 与 `unordered_map`：键值映射

### 4.1 最核心的三个操作

```cpp
map<string, int> mp;
mp["apple"] = 5;             // 插入或覆盖
mp.count("apple");           // 返回 0 或 1，判断 key 是否存在
mp.find("apple");            // 返回迭代器，找不到返回 mp.end()

for (auto& [k, v] : mp) {    // 按 key 升序遍历（C++17 结构化绑定）
    cout << k << ' ' << v << '\n';
}
```

### 4.2 `mp[key]` 会“偷偷插入”默认值

这是竞赛中最高频的隐蔽 bug 来源：

```cpp
map<string, int> mp;
if (mp["not_exist"] == 0) {   // 这一行已经插入了 {"not_exist", 0}
    // ...
}
```

`operator[]` 在 key 不存在时**会插入一个值初始化的元素**（`int` 就是 0，`string` 就是空串），然后返回它的引用。如果你只是想查询，应该用 `count` 或 `find`：

```cpp
if (mp.count("key")) { ... }              // 只查，不插
auto it = mp.find("key");                 // 只查，不插
if (it != mp.end()) { /* it->second */ }
```

`unordered_map` 的 `operator[]` 行为完全一样。**多组数据或内存紧张的题目中，反复用 `mp[key]` 查询不存在的 key，会让 map 膨胀到 MLE**。

### 4.3 `map` vs `unordered_map` 的选择

- 需要**按 key 有序遍历**：必须用 `map`。
- 需要 **`lower_bound` / `upper_bound` 对 key 做二分**：`map` 支持，`unordered_map` 不支持。
- 只关心“key 存不存在 / 对应值是多少”，且**能接受最坏情况的风险**：`unordered_map` 平均更快。
- 输入可能被构造来卡哈希（例如大量特定模数的 key）：**用 `map`**。Codeforces 上 `unordered_map` 被卡到 TLE 而 `map` AC 是真实发生过的。

竞赛中如果拿不准，**默认用 `map`**。O(log n) 在 \(n \le 10^5\) 时通常完全够用，确定性比理论上的常数优势更值钱。

## 5. `set` 与 `multiset`：有序集合

### 5.1 `set`：去重 + 有序 + 支持二分

`set` 存储**唯一且已排序**的元素，所有操作 O(log n)。它不支持下标访问，不能用 `s[0]`，但可以用迭代器或范围 `for`。

```cpp
set<int> st = {5, 1, 3, 1};   // 实际内容：{1, 3, 5}

st.insert(4);
st.erase(3);                  // 按值删除
st.count(5);                  // 1 或 0
st.find(5);                   // 迭代器，找不到返回 st.end()

*st.begin();                  // 最小值
*st.rbegin();                 // 最大值
```

### 5.2 `set` 自带的 `lower_bound` / `upper_bound`

这是 `set` 在竞赛中最重要的能力：在**有序集合内部**做二分。

```cpp
auto it = st.lower_bound(x);   // 第一个 >= x 的元素
auto it = st.upper_bound(x);   // 第一个 > x 的元素

if (it != st.end()) {
    // *it 就是答案
}
```

注意：`set` 的 `lower_bound` **必须用成员函数 `st.lower_bound(x)`**，不要用全局的 `std::lower_bound(st.begin(), st.end(), x)`。后者对非随机访问迭代器是线性复杂度，等于白写。

### 5.3 `multiset`：允许重复的 `set`

```cpp
multiset<int> ms = {1, 2, 2, 2, 3};

ms.erase(2);              // 删除所有值为 2 的元素！剩 {1, 3}
ms.erase(ms.find(2));     // 只删除其中一个 2
```

`multiset::erase(value)` 删除**所有**等于该值的元素，这是一个经典的误用点。只想删一个，必须传迭代器：`erase(ms.find(value))`。

### 5.4 用 `vector` 代替 `set` 做“离线去重 + 有序”

如果只需要**最终结果有序且去重**，而不需要在过程中动态插入删除，`vector` + `sort` + `unique` 比 `set` 常数小得多：

```cpp
sort(v.begin(), v.end());
v.erase(unique(v.begin(), v.end()), v.end());
```

`set` 的价值在于**动态**维护有序性。如果所有元素一开始就已知，先读进 `vector` 再离线处理，通常更快。

## 6. `stack` 与 `queue`：只暴露端点的适配器

```cpp
stack<int> st;
st.push(1);
st.top();      // 栈顶
st.pop();      // 弹出，不返回被弹的值
st.empty();  st.size();

queue<int> q;
q.push(1);
q.front();     // 队头
q.back();      // 队尾
q.pop();       // 弹出队头，不返回
q.empty();  q.size();
```

`pop()` **不返回被删除的值**，必须先 `top()` / `front()` 再 `pop()`：

```cpp
int x = st.top(); st.pop();
```

这两个容器在竞赛中主要用于显式地实现栈/队列逻辑（括号匹配、BFS 等），本身没有太多坑。

## 7. `priority_queue`：默认大顶堆，小顶堆和自定义比较要写对

### 7.1 默认是大顶堆

```cpp
priority_queue<int> pq;   // 每次 top() 是最大值
pq.push(5); pq.push(2); pq.push(8);
pq.top();                 // 8
pq.pop();                 // 删除 8
```

### 7.2 小顶堆的写法

```cpp
priority_queue<int, vector<int>, greater<int>> pq;
pq.push(5); pq.push(2); pq.push(8);
pq.top();                 // 2
```

`greater<int>` 让“更小”的元素优先级更高，所以堆顶是最小值。

### 7.3 `pair` 在 `priority_queue` 中的默认行为

`priority_queue<pair<int, int>>` 默认按**字典序**比较：先比 `first`，大的在堆顶；`first` 相同比 `second`，大的在堆顶。这在 Dijkstra 中直接可用（`pair<距离, 节点>`，距离小的先出队，因为默认大顶堆取反或者用 `greater`）。

### 7.4 自定义比较：写一个带 `operator()` 的 struct

当元素是自定义结构体，或者需要“第一关键字最小、第一关键字相同时第二关键字最大”这类非标准顺序时，需要自定义比较器：

```cpp
struct Node {
    int time, id;
};

struct cmp {
    bool operator()(const Node& a, const Node& b) const {
        if (a.time != b.time) return a.time > b.time;  // time 小的优先
        return a.id < b.id;                              // time 相同，id 大的优先
    }
};

priority_queue<Node, vector<Node>, cmp> pq;
```

**`cmp` 的语义容易搞反**：`return true` 表示 `a` 的优先级**低于** `b`，`a` 应该排在 `b` 后面（离堆顶更远）。所以想让 `time` 小的在堆顶，就写 `a.time > b.time`——看起来是“大于”，但表达的是“a 的时间更大时，a 应该排在后面”。洛谷题目中的典型写法也是 `priority_queue<node, vector<node>, cmp>`，`cmp` 里按第一关键字、第二关键字逐级写比较。

## 8. 容器共性：迭代器失效与传参

### 8.1 迭代器失效：`vector` 最严重，关联容器只失效被删的那个

`vector` 在 `push_back`、`insert`、`erase`、`resize` 导致扩容或元素移动时，**从修改位置到末尾的所有迭代器、指针、引用都会失效**。`map` / `set` 的插入不会使已有迭代器失效，删除只使指向被删元素的迭代器失效。竞赛中如果需要在遍历中删除，`vector` 用下标或 `erase(remove(...), end())` 的惯用法，关联容器用 `it = c.erase(it)` 的写法。

### 8.2 传参：一律 `const&`，不要按值传容器

```cpp
void process(const vector<int>& v);
void process(const map<int, int>& mp);
```

按值传容器会发生**整个容器的拷贝**，长 `vector` 或大 `map` 时直接导致 MLE 或 TLE。只读用 `const&`，需要修改用 `&`。

### 8.3 多组数据记得清空

如果容器定义在循环外，**每轮开始前必须 `clear()`**。`vector::clear()` 不释放容量，通常不需要担心反复分配；但如果多组数据规模差异很大，偶尔可以考虑重新构造。

## 9. 选型速查

| 场景 | 首选 | 备注 |
|---|---|---|
| 存一组数，按下标访问 | `vector<T> a(n)` | 已知大小直接构造，不要空 vector 循环 `push_back` |
| 把两个值绑在一起排序 | `pair` | 自带字典序，不用写 `cmp` |
| 统计出现次数 / 键值映射，需要有序 | `map` | 默认用 `map`，除非确定不需要有序且能接受哈希风险 |
| 只查 key 在不在，不关心值 | `set` | 比 `map` 语义更直接 |
| 动态维护有序集合，需要二分 | `set` | 用成员 `st.lower_bound(x)`，不要用全局 `std::lower_bound` |
| 允许重复的有序集合 | `multiset` | 删一个值用 `erase(find(x))`，不要 `erase(x)` |
| 每次取最大/最小 | `priority_queue` | 默认大顶堆；小顶堆 `greater<T>`；自定义 `cmp` 注意 `return true` 的语义 |
| 后进先出 / 先进先出 | `stack` / `queue` | `pop()` 不返回值，先取再弹 |

## 10. 最小可提交片段

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;

    vector<int> a(n);
    for (int i = 0; i < n; i++) cin >> a[i];

    map<int, int> freq;                 // 有序键值映射
    for (int x : a) freq[x]++;

    set<int> distinct;                  // 有序去重
    for (int x : a) distinct.insert(x);
    auto it = distinct.lower_bound(5);  // 第一个 >= 5

    priority_queue<int> max_heap;       // 大顶堆
    priority_queue<int, vector<int>, greater<int>> min_heap;  // 小顶堆
    for (int x : a) {
        max_heap.push(x);
        min_heap.push(x);
    }

    // 离线去重 + 排序（比 set 更快，如果不需要动态维护）
    sort(a.begin(), a.end());
    a.erase(unique(a.begin(), a.end()), a.end());

    return 0;
}
```

这一篇覆盖了起步阶段 90% 以上的容器需求。剩下的 `deque`、`list`、`bitset`、`array` 等在入门题中出现频率很低，遇到再查即可。容器本身的语法不复杂，真正的难点是**在题目里判断该用哪个**，这只能通过做题积累，没有捷径。
