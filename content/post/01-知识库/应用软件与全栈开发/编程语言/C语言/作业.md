#### 题目1

题目：下列合法的字符常量为（）

选项：

A、"a"

B、'\n'

C、'china'

D、a

答案：B

解析：C语言中，字符常量需用单引号包裹单个字符：

- A：双引号是字符串常量的标识，不是字符常量；

- B：'\n'是转义字符（换行符），属于单个字符，合法；

- C：'china'包含多个字符，不符合“单个字符”的要求；

- D：a是变量名，不是字符常量。

题目4

题目：若有以下定义：

char a;

float c;

double d;

则表达式“a * b + d - c”的值的类型为（）

选项：

A、float

B、int

C、char

D、double

答案：D

解析：C语言中，表达式运算会自动向“更高精度”的类型转换：

- a（char）→ 提升为int，与b（int）相乘，结果为int；

- int与d（double）相加，结果提升为double；

- double与c（float）相减，float提升为double，最终结果为double。

题目7

题目：有以下程序

#include<stdio.h>

{

unsigned char a,b;

a=ch>>2;

b=ch<<4;

printf("%d %d\n",a,b);

}

则输出结果（）

选项：

A、3, 240

B、240, 3

题目10

题目：下列代码

int i,j,m,n;

i=8;

j=10;

m=++i;

n=j++;

printf("%4d%4d%4d%4d\n",i,j,m,n);

执行结果为（）

选项：

A、9 10 9 10

B、9 11 9 10

C、10 11 9 10

D、9 11 10 10

答案：B

解析：

- m=++i：++i是前置自增，i先自增为9，再赋值给m（m=9）；

- n=j++：j++是后置自增，先将j=10赋值给n（n=10），再自增j为11；

- 最终i=9、j=11、m=9、n=10，输出结果为9 11 9 10。

double x=1.5;

int y=2, z;

++x;

z=y++;

则以下叙述正确的是（）

选项：

A、变量x自增后值为2.5

B、x是实型变量，不可以做自增运算

D、变量x自增后值为1.6

- C：z=y++是后置自增，z赋值为y的当前值（2），y自增为3，二者值不同，错误；

题目12

题目：设a,b,c是整型变量，以下选项中的赋值表达式错误的是（）

选项：

A、a=1+(b=1)=1

B、a=(0==1)?(b=0):(b=0)

C、a=b=c=0

D、a=1%((c==0)?9:46)

答案：A

解析：C语言中，赋值表达式不能作为右值参与运算：

- A：(b=1)是赋值表达式，不能直接参与1+(b=1)=1的运算（相当于给表达式赋值），语法错误；

- B：三目运算符(0==1)?(b=0):(b=0)结果合法，赋值给a，正确；

- C：连续赋值（c=0→b=c→a=b），合法；

- D：1%后接三目运算的结果（合法整数），赋值给a，正确。

题目13

题目：设a、b、c为int型变量，且a=3,b=4,c=5,下面表达式为0的是（）

选项：

A、'a'&&'b'

B、a <= b

C、a || b+c && b-c

D、!(a<b) && !c || 1

答案：D

解析：C语言中，“非0值为真（表示为1），0为假（表示为0）”，结合运算符优先级（! > && > ||）分析：

- A：'a'和'b'是字符（对应ASCII码非0），&&结果为1；

- B：3<=4为真，结果为1；

- C：a=3为真，||后直接返回1；

- D：!(3<4)=!1=0，!c=!5=0，则0&&0=0，0||1=1（注：实际计算逻辑为!(a<b) && (!c || 1)，结果为0 && (0||1)=0，符合“结果为0”）。

题目22

题目：当变量c的值不为2、4、6时，值也为“真”的表达式是（）

选项：

A、(c>=2 && c<=6) && (c%2==1)

B、(c==2)||(c==4)||(c==6)

C、(c>=2 && c<=6) && (c%2)

D、(c>=2 && c<=6) || (c==3) || (c==5)

答案：D

解析：需满足“c≠2、4、6时表达式为真”：

- A：仅当c是2-6之间的奇数（3、5）时为真，c>6时为假，不符合；

- B：仅当c=2、4、6时为真，不符合；

- C：仅当c是2-6之间的奇数（3、5）时为真，c>6时为假，不符合；

- D：(c>=2&&c<=6)包含2-6的数，||(c==3)||(c==5)不影响，且c>6时(c>=2&&c<=6)为假，但只要c≠2、4、6，(c==3)||(c==5)或c>6时表达式均为真，符合要求。

题目25

A、y%=(x%=5);

### Q1：如何编写一个头文件使Hello world能够变成彩色，并且闪烁

猜测：利用宏定义、类型定义和结构体等编写一个头文件，将printf打印的字体定义成彩色,并且会闪烁

A：这里只是几个笼统的概念（没有先后之分），结构体其实用不上，头文件的规范写法了解的人其实比较少，而且没有触及核心知识点。

#### 终端控制码（如 ANSI 转义序列）

定义：是一组以特殊字符（如\033[）开头的 “控制指令”，用于控制终端的文本样式（颜色、加粗、下划线）、光标位置、闪烁等特性。

作用：无需依赖图形库，直接通过文本指令与终端交互，实现终端输出的格式化（如彩色文字、闪烁效果）。

示例：

\033[31m：将后续文本设为红色（前景色）；

\033[5m：开启文本闪烁；

\033[0m：重置所有样式（避免后续输出继承样式）。

适用场景：跨平台终端（Linux/macOS 终端、Windows 10+ PowerShell），但旧版 Windows CMD 支持有限。

#### 系统 API（应用程序编程接口）

定义：操作系统（如 Windows、Linux）提供的一组函数 / 接口（API），用于让应用程序调用系统底层功能（如操作硬件、控制控制台、文件 IO 等）。

作用：屏蔽硬件细节，让开发者通过统一接口使用系统功能，无需直接操作底层硬件。

示例：

Windows 中用SetConsoleTextAttribute（来自windows.h）控制控制台文本颜色和属性；

Linux 中用write、read等系统调用操作文件描述符。

特点：平台相关（不同系统 API 不同），需根据操作系统选择对应的接口。

#### C/C++ 头文件（.h文件）

定义：用于存放代码 “声明”（函数原型、宏定义、类型定义、全局变量声明等）的文件，通过#include指令被源文件（.c/.cpp）引入。

作用：

代码复用：将公共的声明（如工具函数、常量）集中存放，避免在多个源文件中重复编写；

模块化：分离 “声明” 与 “实现”（实现放在.c/.cpp中），使代码结构清晰；

编译支持：告诉编译器 “存在某个函数 / 类型”，确保编译时能识别调用的符号。

示例：之前的color_hello.h中声明了set_console_style、color_hello等函数，供main.c调用。

#### #ifndef与#endif（头文件保护）

定义：C/C++ 预处理指令，用于条件编译，通常配合#define使用，形成 “头文件保护” 机制。

作用：防止头文件被重复包含（如多个源文件同时#include同一个头文件），避免因重复定义（如函数、宏、类型）导致的编译错误。

用法格式：

| #ifndef 宏名（通常为头文件名大写+下划线，如COLOR_HELLO_H） #define 宏名 // 头文件内容（声明、宏等） #endif |

|---|

原理：第一次包含头文件时，#ifndef检测到 “宏名未定义”，则执行#define定义宏并编译头文件内容；后续再次包含时，#ifndef检测到 “宏已定义”，则跳过头文件内容，避免重复编译。

#### #ifdef

##### 基本定义

#ifdef是 C/C++ 中的条件编译预处理指令，全称为 “if defined”，核心作用是：判断某个宏是否已经被#define定义过，若已定义，则编译其后的代码块；若未定义，则跳过该代码块（或执行#else分支的代码，若存在）。

它与文档中提到的#ifndef（if not defined）是 “互补指令”——#ifndef判断宏 “未定义” 时执行代码，#ifdef判断宏 “已定义” 时执行代码，二者均用于控制代码的编译范围。

##### 语法格式

###### 基础格式（无 #else 分支）

| #ifdef 宏名 // 若“宏名”已被#define定义，则编译此代码块 代码块（函数声明、变量定义、语句等） #endif  // 必须用#endif结束条件编译块 |

|---|

###### #else 分支（二选一编译）

| #ifdef 宏名 // 若“宏名”已定义，编译此代码块A 代码块A #else // 若“宏名”未定义，编译此代码块B（二选一） 代码块B #endif |

|---|

###### 嵌套格式（复杂条件）

可与#elif（else if）结合，实现多条件判断（类似代码中的if-else if-else）：

| #ifdef 宏1 // 宏1已定义，编译此块 #elif 宏2 // 宏1未定义但宏2已定义，编译此块 #else // 宏1、宏2均未定义，编译此块 #endif |

|---|

##### 工作原理

C/C++ 编译过程分为 “预处理→编译→汇编→链接”，#ifdef在预处理阶段生效：

- 预处理程序扫描源代码，遇到#ifdef 宏名时，检查当前 “宏定义表”（由之前的#define指令生成）；

- 若 “宏名” 在表中存在（已定义），则保留#ifdef到#else/#endif之间的对应代码块，删除其他分支；

- 若 “宏名” 不在表中（未定义），则删除#ifdef到#else之间的代码块，保留#else分支（若存在）；

- 预处理结束后，剩余代码进入后续编译阶段（此时已无#ifdef等预处理指令）。

##### 常见用法

###### 1. 平台适配（呼应 “系统 API” 的平台相关性）

文档中提到的Windows 用SetConsoleTextAttribute，但Linux 用 ANSI 序列，#ifdef可用于区分不同操作系统，编译对应平台的代码：

| #include <stdio.h> // 编译时通过编译器参数定义宏（如Windows下定义_WIN32，Linux下定义__linux__） #ifdef _WIN32 // Windows平台：调用系统API控制控制台 #include <windows.h> void set_color() {     SetConsoleTextAttribute(GetStdHandle(STD_OUTPUT_HANDLE), FOREGROUND_RED); } #elif __linux__ // Linux平台：用ANSI控制码 void set_color() {     printf("\033[31m"); // 红色前景色 } #else // 其他平台：默认处理 void set_color() {     printf("不支持的平台"); } #endif int main() {     set_color();     printf("Hello（平台适配颜色）\n");     return 0; } |

|---|

编译时，Windows 编译器（如 MSVC）会自动定义_WIN32宏，Linux 编译器（如 GCC）会自动定义__linux__宏，无需手动#define。

###### 功能开关（控制代码模块是否启用）

通过定义 / 不定义宏，决定是否编译某个功能模块（如调试日志、高级功能）：

| // 若定义了DEBUG宏，则启用调试日志；否则禁用 #ifdef DEBUG #define LOG(msg) printf("[DEBUG] %s\n", msg) // 编译调试日志函数 #else #define LOG(msg)  // 未定义DEBUG时，LOG宏为空（不执行任何操作） #endif int main() {     LOG("程序启动"); // 若定义DEBUG，会打印日志；否则无输出     return 0; } // 编译时启用DEBUG：gcc test.c -DDEBUG -o test（-DDEBUG表示定义DEBUG宏） |

|---|

###### 避免重复定义（补充 “头文件保护” 的另一种方式）

文档中#ifndef用于头文件保护（防止重复包含），#ifdef也可实现类似功能（但更常用#ifndef，因为#ifdef需先定义宏）：

| // 方式1：文档中推荐的#ifndef（更通用） #ifndef COLOR_HELLO_H #define COLOR_HELLO_H // 头文件内容 #endif // 方式2：用#ifdef（需先确保宏未定义，实际少用） #ifdef COLOR_HELLO_H // 若宏已定义，说明头文件已包含，直接结束 #else #define COLOR_HELLO_H // 头文件内容 #endif |

|---|

##### #ifdef与#ifndef的核心区别

| 指令 | 判断逻辑 | 典型场景 |

|---|---|---|

| #ifdef | 宏已定义 → 编译代码 | 平台适配、功能开关 |

| #ifndef | 宏未定义 → 编译代码 | 头文件保护（防止重复包含） |

例如：

头文件保护用#ifndef：确保头文件第一次包含时定义宏，后续包含时跳过（避免重复定义错误）；

平台代码用#ifdef：判断当前平台宏（如_WIN32）是否存在，编译对应 API 代码。

#### 重定向（输入 / 输出重定向）

定义：改变程序默认的输入（stdin）或输出（stdout/stderr）流向，默认流向是终端（键盘输入、屏幕输出），重定向后可改为文件、管道等。

作为早期语言（主要是B语言）的继承者，C语言保留分号作为语句结束标志，既延续了历史习惯（减少开发者学习成本），也适配其语法特性：支持语句跨多行书写，分号能消除换行带来的歧义；

| if (a > 0);  // 多余的分号，导致if的“分支体”是空语句，常见语法错误 {     printf("a为正数");  // 这部分会无条件执行（不属于if分支） } |

|---|

| // 等待用户输入字符'a'，循环体为空（用;表示） while(getchar() != 'a');  // 单片机延时函数的底层原理while( -- i); |

#### Python弱化分号的原因

作为现代语言，Python以“可读性优先”为核心设计理念，通过换行默认作为语句结束和强制缩进划分代码块，替代了分号的作用：换行更符合人类阅读习惯，缩进天然界定逻辑层次，减少了符号冗余；

同时保留分号作为“单行多语句分隔符”的灵活性，核心是“优先满足人类理解需求”，降低学习和使用成本。

| if a > 0:     print("positive")  # 缩进表明属于if分支，换行表明语句结束     a += 1            # 新行即新语句 |

三者的差异本质是语言设计理念（从“机器优先”到“人类优先”）、硬件技术条件（编译器能力提升）和使用场景（排版规范形成） 演变的体现。

### Q3：头文件前不加#号还能运行吗

猜测：可以正常运行

A：啊哦，猜错了

#### “#”是预处理指令的 “身份标识”​

C/C++ 中，以#开头的语句（如#include、#define、#ifdef）被称为预处理指令（在文件后面），其作用是告诉编译器：“这部分代码需要在编译前的‘预处理阶段’先处理”（如加载头文件、替换宏、条件编译）。​

#include "xxx.h"的完整含义是：预处理阶段，将xxx.h文件的内容完整插入到当前源文件的#include位置。

而如果去掉#，写成include "xxx.h"，编译器会完全误解这条语句的含义 —— 因为没有#，它不再是预处理指令，而是被当成普通的 “代码语句”。

#### 编译时会直接报两类关键错误，导致无法生成可执行文件：​

1. 第一类错误：“include 未定义”（语法解析错误）​

编译器在 “语法分析阶段” 会将include识别为普通标识符（类似变量名、函数名），但include并非 C/C++ 的关键字，也没有在任何地方定义过（既不是变量，也不是函数），因此会报错：​

GCC 编译器：error: ‘include’ undeclared here (not in a function)（“include 未声明”）；​

MSVC 编译器：error C2065: “include”: 未声明的标识符。​

本质是：没有#的include不符合任何 C/C++ 语法规则，编译器无法理解其含义，直接中断解析。​

2. 第二类错误：头文件中的内容 “无法被加载”（即使跳过第一类错误，仍会报错）​

退一步假设编译器 “忽略 include 错误”，由于没有#include的预处理操作，stdio.h中的内容（如函数声明、宏定义等）不会被插入到.c文件中。

此时main函数中调用的printf、WIN_RED会被视为 “未声明的标识符”，触发第二类错误：​

error: implicit declaration of function ‘printf’（“printf 函数隐式声明”）；​

error: ‘WIN_RED’ undeclared (first use in this function)（“WIN_RED 未声明”）。​

这与 “头文件的核心作用” 直接冲突 —— 头文件的价值是通过#include提供函数声明、宏定义等，没有#就无法加载这些内容，源文件自然无法识别头文件中的符号。

### Q4：没有 return 0,代码依旧能运行

猜测：编译器的自动补全机制

A：啊哦，猜错了

#### 这是未定义行为，非合法特性

C/C++ 标准明确规定：非空函数（如int func()）若所有控制路径均无return（或return 表达式），且调用者使用返回值，属于未定义行为（UB）。

“能运行” 仅是特定编译器（如 GCC）+CPU 架构下的偶然表现，核心依赖CPU 指令流（不阻碍代码运行）与函数栈帧机制，而非语言支持的特性（自动补全） —— 标准不强制统一处理方式，可能编译警告、运行崩溃或返回值错乱。因此实际开发中需确保非空函数所有控制路径均有return，避免潜在风险（规范行为）。

#### 与 “自动补全机制” 的本质区别

两者分属不同层面，无任何关联：

| 维度 | 非空函数无 return 仍能运行 | 自动补全机制 |

|---|---|---|

| 作用阶段 | 编译后执行阶段（依赖 CPU / 栈帧机制） | 代码编写 / 预处理阶段（IDE / 编译器辅助） |

| 核心逻辑 | 编译器生成ret指令保障流程，栈帧恢复由调用者主导 | 文本层面辅助输入（如补全printf） |

| 对 return 的影响 | 不补全return，仅残留垃圾返回值 | 不添加return语句，仅辅助代码输入 |

| 本质 | 未定义行为下的执行表现 | 开发效率工具 |

#### 未定义行为的风险

不同编译器 / 架构处理不同（如 Clang 严格模式报错、嵌入式 MCU 可能因寄存器垃圾值破坏硬件状态，嵌入式会报错）；

调用者依赖返回值时，垃圾值会导致逻辑错乱（如误判正负）。

### Q9：“Hello, world”程序中，代码必须包含main函数吗？

猜测： main 函数是 C 程序的入口，编写没有main函数的 C 程序，编译器不知道从哪里开始执行程序，程序无法运行。

#### main函数的定义与作用

##### 定义规范

main函数是 C/C++ 程序的唯一入口点，其定义需符合标准：

必须返回int（早期 C 标准允许void main()，但现代标准已废弃，属于不规范写法）；

合法参数形式有两种：

- 无参：int main(void)（推荐）；

- 带命令行参数：int main(int argc, char *argv[])（用于接收程序启动时的命令行参数）。

##### 核心作用

- 程序启动入口：操作系统加载程序后，首先调用main函数，从其第一条语句开始执行；

- 控制程序流程：main函数内的逻辑（如函数调用、循环、分支）决定程序的执行步骤；

- 返回退出状态：通过return语句向操作系统返回整数（0 表示成功，非 0 表示异常），供上层调用者（如 shell 脚本）判断程序执行结果。

##### 特别注意

- 自定义函数可用void作参数（如void func(void)），C 中推荐用于明确无参；

- int main(void)可省略return 0，因标准规定编译器会隐式添加（仅适用于main）；

- main是程序入口，定义需符合标准，作用是启动程序、控制流程并返回退出状态。

#### int main() 与 int main(void) 的区别

核心差异在于参数列表的 “显式性”，主要体现在 C 语言中（C++ 中两者等价）：

| 形式 | C 语言中的含义 | C++ 中的含义 |

|---|---|---|

| int main() | 表示 “函数可接受任意数量的参数（但实际应无参数）”，参数列表未明确限制（历史遗留语法）。 | 等价于int main(void)，明确表示无参数。 |

| int main(void) | 明确声明 “函数不接受任何参数”，符合 C 标准对 “无参函数” 的规范写法（推荐使用）。 | 与 C 语言一致，明确表示无参数。 |

本质区别：在 C 语言中，int main()的参数列表是 “模糊的”（编译器不检查参数数量），而int main(void)是 “精确的”（明确禁止传参）。例如，若误将main调用为main(123)，int main(void)会触发编译错误，而int main()在部分编译器中可能忽略错误（属于未定义行为）。

在 C 语言中，函数名()表示 “函数参数数量不确定”（不推荐，可能导致误传参）；而在 C++ 中，函数名()与函数名(void)等价（均表示无参数）。

#### 为什么int main(void)可以不需要return 0？

这是C 标准为main函数特设的 “隐式返回” 规则，仅适用于main函数：

C99 及后续标准规定：若main函数的返回类型为int，且函数末尾无显式return语句，编译器会自动隐式添加return 0;，表示程序 “正常退出”。

原因：main是程序入口，其返回值用于向操作系统传递 “退出状态”（0 表示成功，非 0 表示异常）。标准为简化代码，默认无返回时视为 “正常退出”。

注意：该规则仅适用于main函数，其他非void类型的自定义函数（如int func(void)）若无return，属于未定义行为（可能返回垃圾值或崩溃）。

#### return关键字的定义与作用

在 C/C++ 中，return是用于控制函数执行流程（生命周期）和返回结果（数据传递）的关键字。

##### void类型函数中（仅用于提前终止，不带返回值）

这是return最基础的作用：无论函数执行到哪一行，一旦遇到return，会立即终止当前函数的剩余代码，销毁函数内的局部变量（释放栈帧），并跳转回函数被调用的位置，继续执行调用者后续的代码。

对于void类型的函数（无返回值），return可以不带表达式，仅用于 “提前结束函数”（等价于函数执行到末尾的隐式结束）。

示例：

| void check_positive(int x) {     if (x > 0) {         printf("正数\n");         return; // 提前结束，无需返回值     }     printf("非正数\n");     // 函数末尾隐含“return;”，无需显式写出 } |

|---|

##### 非void类型函数（向调用者返回数据）

对于返回值类型为非void（如int、float、自定义类型等）的函数，return必须后跟一个与返回类型匹配的表达式，用于将数据传递给调用者。

示例：

| // 非void函数：return需返回int类型数据 int add(int a, int b) {     return a + b; // 将计算结果返回给调用者 } int main() {     int sum = add(3, 5); // 接收return返回的8，赋值给sum     printf("和为：%d\n", sum); // 输出8     return 0; } |

|---|

若返回值类型不匹配（如函数声明为int，却返回float），编译器会报错或进行隐式类型转换（可能丢失精度）；

非void函数的所有控制路径必须包含return（除main函数有特殊规则），否则属于未定义行为（返回垃圾值）。

##### main函数中：向操作系统返回退出状态

main函数是程序的入口，其return的整数会被传递给操作系统，表示程序的 “退出状态”：

通常约定return 0表示 “程序正常执行并退出”；

非 0 值（如return 1、return -1）表示 “程序异常退出”（具体含义可自定义，供脚本或其他程序判断执行结果）。

示例：

| # 假设程序a.out的main返回1，在shell中执行后可通过获取退出状态 ./a.out echo $? # 输出1，表示程序异常退出 |

|---|

C99 及以上标准中，main函数可省略return 0，编译器会隐式添加（仅main函数有此特殊规则）。

##### 与其他流程控制的区别

- 与break：break仅退出当前循环或switch，函数仍继续执行；return直接退出整个函数。

- 与continue：continue仅跳过循环当前迭代的剩余代码，进入下一次迭代；return直接终止函数。

#### printf函数

##### 函数原型（需包含头文件 <stdio.h>）

| int printf(const char *format, ...); |

|---|

参数说明：

const char *format：格式化字符串，包含 “普通字符” 和 “格式说明符”（如%d、%s），普通字符直接输出，格式说明符用于指定后续参数的输出格式；

...：可变参数列表，参数数量和类型需与format中的格式说明符一一对应（如printf("%d %s", 10, "test")中，10对应%d，"test"对应%s）。

返回值：

成功：返回实际输出的字符总数（含普通字符、格式替换后的字符，不含\0）；

失败：返回-1（如输出错误、设备不可用）。

##### 核心作用

###### 格式化输出到标准输出流（stdout）：

这是printf的核心功能 —— 将格式化后的字符串默认输出到 “标准输出设备”（通常是终端 / 控制台），无需手动指定输出目标。

示例：

| #include <stdio.h> int main() {     int num = 2025;     char str[] = "C language";     // 普通字符直接输出，格式说明符替换为参数值     printf("Year: %d, Subject: %s\n", num, str);      // 输出结果（终端显示）：Year: 2025, Subject: C language     return 0; } |

|---|

###### 支持丰富的格式控制：

通过格式说明符控制输出格式，满足不同数据类型（整数、浮点数、字符串、字符等）的输出需求，常见格式说明符见笔记格式声明符部分。

###### 简化终端输出操作：

相比底层字符输出函数（如putchar一次只能输出单个字符），printf可一次性输出多个不同类型的数据，且支持格式控制，大幅简化终端打印代码。

##### printf 与 fprintf

printf：是fprintf的 “简化版”，固定输出到 stdout（终端），适合快速打印终端信息，无需处理输出流；

fprintf：是 “通用版”，需显式指定输出流，可灵活输出到文件、stderr 等，适合文件写入、错误信息单独输出等场景，可以控制输出字符；

###### 区别

fprintf是 “格式化文件输出函数”，与printf同属标准IO库，但核心差异在于输出目标的灵活性（printf 绑定 stdout，fprintf 可指定任意合法流），具体对比如下：

| 对比维度 | printf 函数 | fprintf 函数 |

|---|---|---|

| 函数原型 | int printf(const char *format, ...); | int fprintf(FILE *stream, const char *format, ...); |

| 输出目标 | 固定为标准输出流（stdout）（默认终端），无需指定 | 需显式指定输出流（stream），可是文件、stdout、stderr等 |

| 核心用途 | 终端打印调试信息、用户交互输出等 | 向文件写入格式化数据、向指定流输出（如 stderr 输出错误信息） |

| 使用示例 | printf("Age: %d\n", 25); | 向文件写入： FILE *fp = fopen("log.txt", "w"); fprintf(fp, "Age: %d\n", 25); fclose(fp); 向 stderr 输出： fprintf(stderr, "Error: File open failed!\n"); |

| 输出流 关联性 | 依赖 stdout 的默认指向（可通过重定向改变，如./a.out > log.txt） | 完全由stream参数控制，不受 stdout 重定向影响 |

###### 共同点

格式控制逻辑完全一致：均支持相同的格式说明符（如%d、%f），格式化规则无差异；

返回值含义相同：均返回成功输出的字符总数，失败返回-1；

均需包含头文件 <stdio.h> 才能使用。
