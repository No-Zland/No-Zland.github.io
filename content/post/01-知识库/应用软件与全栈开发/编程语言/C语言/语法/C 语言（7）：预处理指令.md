> 预处理指令是 C 语言编译前的“文本操作指令”，由编译器的预处理阶段执行。
> 
> 它们以 `#` 开头，不需要分号结尾，核心作用是文本替换、文件引入和代码条件筛选。
> 
> 本文围绕三大类展开：宏定义、文件包含、条件编译，并补充头文件保护、跨平台适配和调试开关等常见用法。

---

## 1. 预处理指令概览

### **作用：** 

在编译之前处理源代码文本。

C 语言常见的预处理指令包括：

| 指令                                   | 作用                       |
| ------------------------------------ | ------------------------ |
| `#define`                            | 定义宏                      |
| `#undef`                             | 取消宏定义                    |
| `#include`                           | 包含文件                     |
| `#if` / `#elif` / `#else` / `#endif` | 条件编译                     |
| `#ifdef` / `#ifndef`                 | 判断宏是否定义                  |
| `#error`                             | 触发编译错误                   |
| `#pragma`                            | 编译器相关指令，如 `#pragma once` |
### **注意：** 

它们不是 C 语句，不受普通语法规则约束，但会影响后续编译的内容。

- **文本替换特性**：宏替换是 **纯文本替换**，没有类型检查，也不执行语法验证。例如 `#define PI 3.14a` 在定义时不一定报错，真正使用 `PI` 时才可能暴露问题。
- **括号要加足**：带参数宏的参数和整体表达式都应加括号，否则容易因运算符优先级导致逻辑错误。
- **宏与常量不同**：`#define PI 3.14` 是文本替换；`const float pi = 3.14f;` 是有类型常量，编译时检查类型，通常占内存。按需选择。

## 2. 宏定义

宏定义通过 `#define` 将标识符与文本或表达式绑定。

#### **作用：** 

预处理阶段会把代码中所有宏名 **替换** 为对应文本，实现“一处定义、多处复用”。

#### **分类：**

**无参数宏** 和 **带参数宏**。

### 2.1 无参数宏

#### 格式：

```c
#define 宏名 替换文本
```

替换文本可以省略，此时宏名仅作为“标识”，例如 `#define DEBUG`。

```c
#include <stdio.h>

#define PI 3.14159
#define MAX_SIZE 100
#define GREET "Hello C Preprocessor"

int main(void) {
    float radius = 5.0f;
    float area = PI * radius * radius;
    int arr[MAX_SIZE];

    printf("圆面积：%.2f\n", area);
    printf("%s\n", GREET);

    return 0;
}
```

预处理后，`PI` 被替换为 `3.14159`，`MAX_SIZE` 被替换为 `100`，`GREET` 被替换为字符串字面量。`arr[MAX_SIZE]` 在编译前等价于 `arr[100]`。

### 2.2 带参数宏

#### 格式：

```c
#define 宏名(参数列表) 替换表达式
```

参数列表没有类型，替换表达式应加括号避免优先级问题。

```c
#include <stdio.h>

#define MAX(a, b) ((a) > (b) ? (a) : (b))
#define SQUARE(x) ((x) * (x))

int main(void) {
    int x = 3, y = 5;

    printf("最大值：%d\n", MAX(x, y));
    printf("(x+2) 的平方：%d\n", SQUARE(x + 2));

    return 0;
}
```

`MAX(x, y)` 展开为 `((x) > (y) ? (x) : (y))`，结果为 `5`。  
`SQUARE(x + 2)` 展开为 `((x + 2) * (x + 2))`，结果为 `25`。

如果 `SQUARE` 写成 `#define SQUARE(x) x * x`，那么 `SQUARE(3 + 2)` 会展开为 `3 + 2 * 3 + 2`，结果是 `11`，而不是 `25`。所以带参数宏的参数和整体表达式都要加括号。

### 2.3 取消宏定义

#### 格式：

```c
#undef 宏名
```

#### **作用：**

取消已定义的宏，后续代码中该宏名不再生效：

```c
#include <stdio.h>

#define NUM 100

int main(void) {
    printf("%d\n", NUM);  // 输出 100

#undef NUM
    // printf("%d\n", NUM);  // 错误：NUM 未定义

    return 0;
}
```

### 2.4 宏的注意事项

1. **宏不是函数**：宏在预处理阶段展开，没有函数调用开销，但也没有类型检查和调试符号。
2. **参数和整体都要加括号**：例如 `#define SQUARE(x) ((x) * (x))`，不要写成 `x * x`。
3. **避免副作用**：如果宏参数在展开后出现多次，可能被求值多次。例如 `MAX(i++, j++)` 可能导致自增多次，应避免这种用法。
4. **宏名通常用大写**：这是约定俗成，便于区分宏和普通变量/函数。
5. **多行宏用反斜杠续行**：

```c
#define CHECK(cond, msg) \
    do { \
        if (!(cond)) { \
            printf("%s\n", msg); \
        } \
    } while (0)
```

这种 `do { ... } while (0)` 写法可以让宏在语法上表现得像一条语句，避免在 `if-else` 中展开后出错，这种表达在Linux内核中很常见。

## 3. 文件包含

`#include` 指令将指定文件的全部内容嵌入当前文件，实现头文件复用。

### 3.1 标准库头文件

#### 格式：

```c
#include <头文件名>
```

编译器从系统头文件路径查找，例如 `/usr/include`、`C:\MinGW\include`。

```c
#include <stdio.h>

int main(void) {
    printf("Hello from stdio.h\n");
    return 0;
}
```

**注意：** `<stdio.h>` 中的函数声明被引入后，才能使用 `printf`、`scanf` 等函数。

### 3.2 自定义头文件

#### 格式：

```c
#include "头文件名"
```

编译器先 **从当前源文件所在路径查找，找不到再去系统路径查找**。适合包含项目内自定义头文件。

示例：`myfunc.h` 声明函数，`main.c` 包含并调用。

**myfunc.h：**

```c
#ifndef MYFUNC_H
#define MYFUNC_H

int add(int a, int b);

#endif
```

**main.c：**

```c
#include <stdio.h>
#include "myfunc.h"

int add(int a, int b) {
    return a + b;
}

int main(void) {
    int sum = add(3, 5);
    printf("3 + 5 = %d\n", sum);
    return 0;
}
```

实际项目中，函数实现通常放在单独的 `.c` 文件中，头文件只放声明。这样多个源文件可以共享同一份声明，链接时再找到实现。

### 3.3 路径写法（两类）

#### 1. 相对路径
##### 格式：

```c
#include "./include/myfunc.h"       // 当前目录下的 include 子目录
#include "../../include/myfunc.h"    // 上两级目录下的 include 子目录
```

跨平台项目 **推荐使用相对路径**，避免写死绝对路径。

#### 2. 绝对路径

绝对路径也可以写，但**可移植性差**：

##### 格式：

```c
#include "C:/project/include/myfunc.h"
```

### 3.4 头文件保护

**产生：** 头文件可能被多个源文件包含，也可能出现 A 包含 B、C 同时包含 A 和 B 的情况。如果没有保护，B 的内容可能被重复嵌入，导致结构体、函数声明等重复定义。

#### 常用两种方式：

##### 方式一：`#ifndef` / `#define` / `#endif`

```c
#ifndef MYFUNC_H
#define MYFUNC_H

/* 函数声明、结构体定义等 */

#endif
```

##### 方式二：`#pragma once`

```c
#pragma once

/* 函数声明、结构体定义等 */
```

`#pragma once` 写法更简洁，但属于编译器扩展，并非所有编译器都保证支持；`#ifndef` 方式更通用。实际项目中二者选其一即可，不要混用。

> 注意：`#include` 主要用于包含头文件（`.h`），不建议包含源文件（`.c`），否则容易导致代码重复编译和链接错误。

## 4. 条件编译

### 作用：

通过条件判断控制“哪些代码参与编译”。**预处理阶段会删除不满足条件的代码**，常用于跨平台适配、调试开关和代码版本控制。

### 4.1 `#if` / `#elif` / `#else` / `#endif`

```c
#if 条件表达式
    满足条件的代码
#elif 另一个条件表达式
    满足此条件的代码
#else
    所有条件都不满足的代码
#endif
```

**条件表达式的要求：**

`#if` 的条件表达式在预处理阶段求值，必须由整型常量表达式组成，可以包含：

- 整型字面常量、字符常量
- 已定义的宏（会被展开）
- `defined` 运算符
- 算术、关系、逻辑、位运算

不能包含变量、函数调用、类型转换、`sizeof`、浮点数等。

```c
#define MAX_SIZE 100

#if MAX_SIZE > 50
    /* 合法：MAX_SIZE 展开为 100，条件为真 */
#endif

#if 1
    /* 合法：常量条件 */
#endif

// #if variable > 50
// 错误：variable 不是预处理阶段的常量
```

**嵌套条件编译：**

```c
#define OS_WIN 1
#define DEBUG 1

#if OS_WIN
    #ifdef DEBUG
        printf("Windows 调试模式\n");
    #else
        printf("Windows 发布模式\n");
    #endif
#endif
```

每个 `#if`、`#ifdef`、`#ifndef` 都必须有对应的 `#endif`。嵌套时要注意配对，避免遗漏。

### 4.2 `#ifdef` 与 `#ifndef`

`#ifdef 宏名` 等价于 `#if defined(宏名)`，**宏已定义** 时编译代码：

```c
#ifdef DEBUG
    printf("调试信息\n");
#endif
```

`#ifndef 宏名` 等价于 `#if !defined(宏名)`，**宏未定义** 时编译代码：

```c
#ifndef MY_HEADER_H
#define MY_HEADER_H

/* 头文件内容 */

#endif
```

`#ifndef` 最常见于**头文件保护**：第一次包含时宏未定义，进入保护块并定义宏；后续再次包含时宏已定义，整个块被跳过。

### 4.3 `#error` 编译错误指令

`#error` 用于在条件不满足时触发编译错误，常用来 **提示不支持的环境**：

```c
#if !defined(_WIN32) && !defined(__linux__)
    #error "不支持当前操作系统"
#endif
```

### 4.4 典型应用1：跨平台适配

不同系统的头文件和函数不同，可以用条件编译适配。编译器会自动定义平台宏，例如 GCC 在 Linux 下定义 `__linux__`，MSVC 在 Windows 下定义 `_WIN32`。

```c
#include <stdio.h>

#ifdef _WIN32
    #include <windows.h>
    #define SLEEP_MS(x) Sleep(x)
#elif defined(__linux__)
    #include <unistd.h>
    #define SLEEP_MS(x) sleep((x) / 1000)
#else
    #error "不支持当前操作系统"
#endif

int main(void) {
    printf("休眠 3 秒...\n");
    SLEEP_MS(3000);
    printf("休眠结束\n");
    return 0;
}
```

预处理后，Windows 下 `SLEEP_MS(3000)` 展开为 `Sleep(3000)`，Linux 下展开为 `sleep(3)`。

### 4.5 典型应用2：调试开关

用宏 `DEBUG` 控制调试日志是否参与编译，发布版本关闭调试代码：

```c
#include <stdio.h>

#define DEBUG

int main(void) {
    int num = 10;

#ifdef DEBUG
    printf("调试：num 的初始值为 %d\n", num);
#endif

    num *= 2;
    printf("最终结果：%d\n", num);

    return 0;
}
```

开发阶段保留 `#define DEBUG`，发布阶段注释掉这一行，调试日志代码就不会被编译进最终程序。

## 5. 实践建议

### 5.1 调试日志与发布版本

除了用 `#ifdef DEBUG` 包裹调试代码，也可以在编译时通过命令行定义宏，而不修改源码：

```bash
gcc -DDEBUG main.c -o main
```

`-DDEBUG` 等价于在源码开头写 `#define DEBUG`。这样同一份源码可以编译出调试版和发布版。

### 5.2 用宏或枚举简化 `main` 逻辑

宏可以定义数组长度、错误码等常量，减少硬编码：

```c
#include <stdio.h>

#define ARR_SIZE 10
#define ERR_PARAM 1

int main(void) {
    int arr[ARR_SIZE];

    if (ARR_SIZE <= 0) {
        return ERR_PARAM;
    }

    (void)arr;
    return 0;
}
```

对于整型常量和错误码，`enum` 或 `const` 往往比宏更利于调试和类型检查。宏不是唯一选择，按场景选用即可。

### 5.3 头文件保护

所有自定义头文件都建议加包含保护，而不仅是可能被多次包含的头文件：

```c
#ifndef MY_HEADER_H
#define MY_HEADER_H

/* 函数声明、结构体定义等 */

#endif
```

### 5.4 编译选项建议

初学阶段建议开启常见警告，有助于发现宏参数缺少括号、未使用变量等问题：

```bash
gcc -std=c11 -Wall -Wextra -pedantic main.c -o main
```

如需更严格检查，可加 `-Werror` 将警告视为错误。

---

## 6. 小结

预处理指令在编译之前完成文本替换、文件引入和条件筛选。记住三条主线：

- **宏定义**：`#define` / `#undef`，本质是文本替换，带参数宏要加足括号，避免副作用。
- **文件包含**：`#include <>` 查系统路径，`#include ""` 先查当前路径；头文件要加保护，不要包含 `.c` 文件。
- **条件编译**：`#if` / `#ifdef` / `#ifndef` / `#error`，用于跨平台适配、调试开关和头文件保护；条件表达式只能使用预处理阶段可求值的整型常量表达式。

预处理指令不参与类型检查，也不生成运行时代码，但它们决定了编译器“看到什么”。理解这一点，就能更安全地使用宏、组织头文件，并用条件编译适配不同环境。
