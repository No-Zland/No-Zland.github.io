# 基地培训 2026-11-02：易错点专题

**形式**：每道题先让学生凭直觉写/说思路 → 暴露盲区 → 代码验证 → 扩散到一类问题  
**核心原则**：不按知识点顺序讲，按“学生大概率会踩的坑”选题。每道题只讲一个“没注意到的地方”。

# 第一题：多组数据求和

**知识点：**
1. 区分全局/静态变量与局部自动变量：**局部自动变量不会自动清零**，循环内变量也要显式初始化。
2. 增强循环意识：外层控制 T 组，内层处理每组 n 个数。
3. 掌握多种循环写法，并理解 `for` 与 `while` 的适用场景。

## 题目描述：

输入 \(T\)，接下来 \(T\) 组数据，每组先给 \(n\)，再给 \(n\) 个整数，求每组数据的和。

**样例输入**
```text
3
3 1 2 3
2 10 20
4 1 1 1 1
```

**样例输出**
```text
6
30
4
```

---
## Q1：读完题，该题至少需要几层循环？

**A：** 本题模型下通常需要**两层循环**：

- 外层：枚举 \(T\) 组数据；
- 内层：读入/处理每组的 \(n\) 个数。

---

## Q2：对于这两层循环，你们会怎么设计？

**A：** 最常用两种写法。

### way1：`for` 写法

```c
for (int i = 0; i < T; i++) {
    ...
}
```

优点：保留原始 `T`，还能用 `i` 表示当前第几组。

### way2：`while` 写法

```c
while (T--) {
    ...
}
```

优点：写法简洁。  
注意：`while (T--)` 会消耗 `T`，循环体内 `T` 已经减 1，循环结束后一般 `T = -1`。

> 教学表述建议：不要说“本质上就两种”，而说“最常用的是这两种，`for` 和 `while` 可以互换，选择取决于是否需要保留原始 `T` 或当前组号”。

---

## Q3：为什么不用 `while(--T)` 或者 `do {} while(T--)` 呢？

**A：** 不是简单“少一次”，而是三者语义不同，执行次数不同。

| 写法 | \(T=3\) 时执行次数 | \(T=0\) 时 | 说明 |
|---|---:|---|---|
| `while (T--)` | 3 次 | 0 次 | 先判断非零，再减 1；循环后一般 `T = -1` |
| `while (--T)` | 2 次 | 先变成 `-1`，条件为真，通常不推荐；若不修改 `T` 可能无限循环 | 先减 1，再判断 |
| `do {} while (T--)` | 4 次 | 1 次 | 先执行一次，再判断；\(T \ge 0\) 时会多执行一次 |

结论：

- `while (T--)`：适合“执行 T 次，且循环后不需要原始 T”；
- `while (--T)`：容易少执行一次，`T = 0` 时还容易出问题，不推荐；
- `do {} while (T--)`：先执行后判断，通常会多执行一次，不推荐用于本题。

---

## Q4：第二种写法，什么情况下不能用呢？

**A：** `while (T--)` 会修改 `T`，循环体内 `T` 已经减 1，循环结束后一般 `T = -1`。

以下情况不适合直接用：

1. 后续还要用原始 `T`；
2. 循环体内需要知道“当前是第几组”；
3. 循环结束后还要用 `T` 做其他运算。

这时应使用：

```c
for (int tc = 0; tc < T; tc++) {
    ...
}
```

或者先保存原始值：

```c
int total = T;
while (T--) {
    ...
}
// total 仍然保留原始组数
```

---

## Q5：下面代码运算结果会是什么？

```c
#include<stdio.h>

int main(){
    int T;
    scanf("%d", &T);

    long long sum;

    while (T--) {
        int n;
        scanf("%d", &n);

        for (int i = 0; i < n; i++) {
            int x;
            scanf("%d", &x);
            sum += x;
        }

        printf("%lld\n", sum);
    }

    return 0;
}
```

**A：结果不可预测。**

原因：`sum` 是局部自动变量，没有初始化。读取未初始化局部变量是**未定义行为**，可能输出任意值，也可能在不同环境下表现不同，甚至崩溃。不能保证“每次都不一样”，也不能把某次输出当作正确结果。

> 教学建议：不要给具体随机输出当作可复现结果。可以课堂演示，但要强调“不可依赖、不可复现”。

---

## Q5.1：可以说一下为什么吗？

**A：** `sum` 没有赋初值。局部自动变量未初始化时，值是不确定的；直接执行 `sum += x` 会读取未初始化的值，属于未定义行为。

正确做法是每组开始时显式初始化：

```c
long long sum = 0;
```

---

## Q5.2：为什么赋初值后结果还是不对呢？

假设写成：

```c
long long sum = 0;

while (T--) {
    int n;
    scanf("%d", &n);

    for (int i = 0; i < n; i++) {
        int x;
        scanf("%d", &x);
        sum += x;
    }

    printf("%lld\n", sum);
}
```

运行结果会变成：

```text
6
36
40
```

**A：** 因为 `sum` 定义在 `while` 外面，`long long sum = 0;` 只在程序开始时执行一次。上一组的结果会带进下一组：

- 第一组：`sum = 6`；
- 第二组：`6 + 10 + 20 = 36`；
- 第三组：`36 + 1 + 1 + 1 + 1 = 40`。

注意：这里的 `sum` 仍然是**局部变量**，问题不是“局部变量与全局变量的区别”，而是：

> `sum` 定义在 `while` 外，初始化只执行一次；每组独立的状态没有在每组开始时重新初始化。

**正确写法：把 `sum` 定义在 `while` 循环块内，并初始化为 0。**

```c
#include<stdio.h>

int main(){
    int T;
    scanf("%d", &T);

    while (T--) {
        int n;
        scanf("%d", &n);

        long long sum = 0;

        for (int i = 0; i < n; i++) {
            int x;
            scanf("%d", &x);
            sum += x;
        }

        printf("%lld\n", sum);
    }

    return 0;
}
```

---

## 扩散：多组数据中的初始化习惯

**正确表述：**

> 累加器、计数器、标记变量（`flag`、`vis` 数组等）如果属于“每组独立状态”，就要在每组开始时显式初始化或清空。  
> **作用域本身不会自动清零，初始化语句才会。**

具体建议：

1. `sum`、`cnt`、`flag` 等每组独立变量，在每组开始时显式赋值：
   ```c
   long long sum = 0;
   int cnt = 0;
   int flag = 0;
   ```

2. 需要跨组保留的量，不要误清。例如总答案、全局统计量。

3. 小数组可以定义在每组作用域内并初始化；大数组不要一律放循环内，可能栈溢出。竞赛中常用全局/静态数组，每组用 `memset` 或时间戳清空。

后面做多组数据的图论题、DP 题时，这个习惯非常重要。

# 第二题：冒泡排序与选择排序的区别

**知识点：**
1. 抓住核心差异：**交换到底发生在哪一层循环**——冒泡在 `j` 层，选择在 `i` 层。
2. 理解两种算法的**循环不变量**：已排好区间方向相反（冒泡在末尾，选择在开头）。
3. 区分**比较次数**与**交换次数**：两者比较都是 \(O(n^2)\)，差别在交换量。
4. 掌握**稳定性**的判断方法，能自己构造不稳定反例。
5. 能对比最好/最坏/平均复杂度，理解冒泡 `flag` 优化为何选择排序学不来。

## 题目描述：

给定一个整数数组，分别用冒泡排序和选择排序升序排列，观察并解释两者的差异。

**样例数组**
```text
5 3 8 2 7 1
```

**排序后**
```text
1 2 3 5 7 8
```

---

## Q1：看这两段代码，第一眼最明显的区别是什么？

**A：** **交换语句的位置不同。**

```cpp
// 冒泡：swap 在 j 循环里
for (int i = 0; i < n - 1; ++i) {
    for (int j = 0; j < n - 1 - i; ++j) {
        if (a[j] > a[j + 1]) {
            swap(a[j], a[j + 1]);   // ← 内层 j 里交换
        }
    }
}
```

```cpp
// 选择：swap 在 i 循环里
for (int i = 0; i < n - 1; ++i) {
    int minIndex = i;
    for (int j = i + 1; j < n; ++j) {
        if (a[j] < a[minIndex]) {
            minIndex = j;           // ← 内层 j 只记下标，不交换
        }
    }
    if (minIndex != i) {
        swap(a[i], a[minIndex]);    // ← 外层 i 里交换
    }
}
```

> 教学建议：板书时把两段代码并排，用红笔圈出 `swap` 所在的行，让学生自己说出“一个在内层、一个在外层”。

---

## Q2：为什么说“i 和 j 的角色刚好反过来”？能具体说一下吗？

**A：** 可以，把两层循环的职责拆开看：

| 观察点 | 冒泡排序 | 选择排序 |
|---|---|---|
| 交换发生在 | 内层 `j` 循环 | 外层 `i` 循环 |
| 内层 `j` 的职责 | 比较 **并交换** | 只找 `minIndex`，**不交换** |
| 外层 `i` 的职责 | 控制轮数、缩小未排序边界 `n-1-i` | 控制轮数 + **执行一次交换** |
| 每轮交换次数 | 0 到 \(n-1-i\) 次，不确定 | 恰好 0 或 1 次 |

一句话口诀：

> **冒泡：内层 j 干活（边比边换），i 只负责缩边界。**
> **选择：内层 j 只找下标（不换），外层 i 才动手换。**

这也解释了为什么选择排序**每轮最多交换一次**——它的 `j` 循环纯粹是“侦查”，交换是“执行”，分两步走。

---

## Q3：冒泡里的 `flag`（`swapped`）优化是什么？选择排序能不能加？

**A：** 冒泡的优化：

```cpp
for (int i = 0; i < n - 1; ++i) {
    bool swapped = false;
    for (int j = 0; j < n - 1 - i; ++j) {
        if (a[j] > a[j + 1]) {
            swap(a[j], a[j + 1]);
            swapped = true;
        }
    }
    if (!swapped) break;   // 一整轮没交换 → 已经有序 → 提前停
}
```

**选择排序加不了同样的优化。** 原因：选择排序的 `j` 循环不交换，它必须**扫完整个未排序区间**才知道谁是最小值；中途没交换不代表已经有序。

| 情况 | 冒泡（带 flag） | 选择排序 |
|---|---|---|
| 最好（已有序） | \(O(n)\)，一轮就停 | \(O(n^2)\)，仍要扫完 |
| 最坏（逆序） | \(O(n^2)\) | \(O(n^2)\) |
| 平均 | \(O(n^2)\) | \(O(n^2)\) |

> 教学建议：这是“最好情况复杂度不同”的根源，值得单独强调——**冒泡能感知“已经有序”，选择不能。**

---

## Q4：两种排序每轮结束后，“已排好的区间”在哪一边？

**A：** 方向**相反**。

**冒泡排序不变量：**
> 第 `i` 轮结束后，数组**末尾**的 `i+1` 个元素已经是全局最大且有序的。

**选择排序不变量：**
> 第 `i` 轮结束后，数组**开头**的 `i+1` 个元素已经是全局最小且有序的。

染色图：

```text
冒泡：  [   未排序区   ][ 已排好，越来越大 ] →
选择：  [ 已排好，越来越小 ][   未排序区   ] →
```

> 教学建议：让学生用 `[5,3,8,2,7,1]` 手写每一轮结束后的数组，并用不同颜色标出“已排好区间”，直观感受方向相反。

---

## Q5：比较次数和交换次数分别差多少？拿样例数一数。

**A：** 用 `[5, 3, 8, 2, 7, 1]`（\(n=6\)）手数：

| 算法 | 比较次数 | 交换次数 |
|---|---:|---:|
| 冒泡（无优化） | 15 次 | 9 次 |
| 冒泡（带 flag，本例一路都有交换） | 15 次 | 9 次 |
| 选择排序 | 15 次 | 5 次（最多 \(n-1\)） |

**结论一句话：**
> 比较次数两者都是 \(O(n^2)\)，**差别在交换**——冒泡交换多，选择交换少。

所以当“交换成本高”（比如元素是很大的结构体/对象）时，选择排序更划算；当“数据基本有序”时，冒泡的 flag 优化更划算。

---

## Q6：什么是稳定性？两种排序谁稳定？给个反例。

**A：** **稳定性**：排序后，值相等的元素保持原来的相对顺序。

- **冒泡排序：稳定。** 只有 `a[j] > a[j+1]` 才交换，相等时不换，所以相等元素永远保持原顺序。
- **选择排序：通常不稳定。**

反例 `[5a, 5b, 2]`：

```text
初始：   5a 5b 2
第1轮：  找到最小值 2，与位置 0 的 5a 交换
结果：   2 5b 5a      ← 两个 5 的相对顺序变了
```

> 教学建议：不要直接给结论，让学生自己构造一个 3 元素的选择排序不稳定例子，比背结论效果好。

---

## Q7：把两种排序的关键对比整理成一张表。

**A：**

| 对比项 | 冒泡排序 | 选择排序 |
|---|---|---|
| 交换位置 | 内层 `j` 循环 | 外层 `i` 循环 |
| 每轮交换次数 | 0 到 \(n-1-i\) 次，不确定 | 0 或 1 次 |
| 循环不变量 | 末尾 `i+1` 个已排好 | 开头 `i+1` 个已排好 |
| 最好情况 | \(O(n)\)（带 flag） | \(O(n^2)\) |
| 最坏/平均 | \(O(n^2)\) | \(O(n^2)\) |
| 空间 | \(O(1)\) | \(O(1)\) |
| 稳定性 | ✅ 稳定 | ❌ 通常不稳定 |
| 适用场景 | 基本有序、需稳定 | 交换成本高、数据量小 |

---

## Q8：常见误区有哪些？

**A：**

| 误区 | 纠正 |
|---|---|
| “选择排序每轮交换很多次” | 每轮**最多 1 次** |
| “冒泡一定比选择慢” | 基本有序时冒泡可到 \(O(n)\)，选择永远 \(O(n^2)\) |
| “两者都稳定” | 只有冒泡稳定 |
| “`i` 循环只是数轮数，没用” | 冒泡的 `i` 决定内层边界 `n-1-i`；选择的 `i` 是交换位置 |
| “选择排序也能提前结束” | 不能，必须扫完找最小 |
| “`swap` 写在内层还是外层无所谓” | 这正是两者本质区别，写错就退化成另一种算法 |

---

## Q9：课堂练习怎么设计？

**A：**

**练习 1（改代码）：** 把选择排序改成**找最大值放末尾**，观察不变量方向如何变化。

**练习 2（找 bug）：** 下面这段选择排序哪里错了？

```cpp
for (int i = 0; i < n - 1; ++i) {
    int minIndex = i;
    for (int j = i + 1; j < n; ++j) {
        if (a[j] < a[minIndex]) minIndex = j;
        swap(a[i], a[minIndex]);   // ← 错：交换写进了内层
    }
}
```

> 这题正好呼应 Q1/Q2：交换应该在外层 `i` 里。写进内层后，就变成了“每轮多次交换的不稳定版本”，退化成类似冒泡的行为。

**练习 3（手写模拟）：** 给 `[4, 2, 7, 1]`，分别写出两种排序**每一轮结束后**的数组，并用颜色标出“已排好区间”。

**练习 4（思考题）：** 冒泡的 `swapped` 优化能不能搬到选择排序上？为什么？（对应 Q3）

**练习 5（拓展）：** 如果数组里有很多重复元素，两种算法分别表现如何？谁更稳定？（对应 Q6）

## 扩散：从这两个算法看“双层循环”的通用套路

**正确表述：**

> 双层循环的排序/枚举类算法，通常可以这样拆解：
> - **外层 `i`**：控制“已经处理了多少”“当前该放哪个位置”；
> - **内层 `j`**：控制“在剩余区间里做什么”——是**边比边交换**（冒泡），还是**只侦查不执行**（选择）。

判断一段排序代码属于哪种，最直接的方法就是看：

1. **`swap` 在哪一层？** 内层 → 冒泡类；外层 → 选择类。
2. **内层循环有没有副作用？** 只改变 `minIndex`（局部下标）→ 选择；直接改数组 → 冒泡。
3. **每轮交换次数是否固定？** 固定 0/1 次 → 选择；不定 → 冒泡。

这个“看 swap 在哪层”的方法，后面学插入排序、希尔排序时同样适用——**插入排序的交换也在内层**，但它是“边比较边后移”，又和冒泡不同，可以作为下一课的伏笔。

具体建议：

1. 讲新排序算法时，先问“swap 在哪层、内层有没有副作用”，再讲复杂度。
2. 让学生养成“先画已排好区间方向，再数交换次数”的习惯。
3. 稳定性判断不要背结论，用 `[5a, 5b, 2]` 这类带标记的数组现场推。

# 第三题：斐波那契数列（从递归定义到迭代实现）

**知识点：**
1. 从数列前几项**发现递推规律**，写出分段递推式。
2. 区分**递归定义**与**迭代实现**：定义是递归的，但代码不一定用递归。
3. 掌握迭代求斐波那契的**两种变量更新写法**：临时变量法、加减法。
4. 理解**滚动变量**思想：只保留前两项，空间 \(O(1)\)。
5. 注意 C 语言实现中的**边界、初始化、溢出**问题。

## 题目描述：

定义一个数列：

$$
f(1)=1,\quad f(2)=1,\quad f(n)=f(n-1)+f(n-2)\ (n\ge 3)
$$

给定整数 \(n\)，求 \(f(n)\)。

**样例输入**
```text
5
```

**样例输出**
```text
5
```

---

## Q1：从 1, 1, 2, 3, 5 能发现什么规律？怎么写成数学式？

**A：** 从第三项开始，每一项等于前两项之和。写成递推式：

$$
\begin{cases}
f(n)=1, & n\le 2\\
f(n)=f(n-1)+f(n-2), & n>2
\end{cases}
$$

这个式子是**递归定义**：要算 \(f(n)\)，先算 \(f(n-1)\) 和 \(f(n-2)\)。  
但“递归定义”不等于“必须写递归函数”，这一点是本题教学的关键。

---

## Q2：既然定义是递归的，为什么最终代码用循环而不是递归？

**A：** 递归写法直观，但**重复计算严重**。

```c
long long fib(int n) {
    if (n <= 2) return 1;
    return fib(n - 1) + fib(n - 2);
}
```

以 \(n=5\) 为例，`fib(3)` 会被算多次，`fib(2)` 被算更多次。递归树规模约为 \(O(2^n)\)，\(n=40\) 左右就会明显卡顿。

迭代写法从 \(f(1),f(2)\) 往后推，每项只算一次，时间 \(O(n)\)，空间 \(O(1)\)。

| 写法 | 时间复杂度 | 空间复杂度 | 是否重复计算 |
|---|---|---|---|
| 朴素递归 | \(O(2^n)\) | \(O(n)\) 递归栈 | 大量重复 |
| 迭代 | \(O(n)\) | \(O(1)\) | 无 |

> 教学建议：可以现场跑 \(n=40\) 的递归版本，让学生感受“定义简单 ≠ 实现高效”。

## Q3：迭代怎么写？第一种写法：临时变量法。

**A：** 用两个变量保存前两项，用临时变量算新项：

```c
long long a = 1, b = 1;   // a=f(1), b=f(2)
for (int i = 3; i <= n; i++) {
    long long tem = a + b; // 新项
    a = b;                 // 旧 b 变成新的 a
    b = tem;               // 新项变成新的 b
}
// 循环结束后 b = f(n)
```

过程演示（\(n=5\)）：

| 轮次 | `a` | `b` | `tem=a+b` |
|---|---:|---:|---:|
| 初始 | 1 | 1 | — |
| i=3 | 1 | 2 | 2 |
| i=4 | 2 | 3 | 3 |
| i=5 | 3 | 5 | 5 |

结束后 `b=5`，正确。

**注意：** 必须先算 `tem`，再改 `a`，最后改 `b`。如果先写 `a=b`，原来的 `a` 就丢了。

## Q4：第二种写法 `b += a; a = b - a;` 为什么也成立？

**A：** 这是利用“新 \(b\) 减去新 \(a\) 等于旧 \(a\)”的技巧。

```c
for (int i = 3; i <= n; i++) {
    b += a;      // b = 旧a + 旧b = 新项
    a = b - a;   // a = 新b - 新a = 旧b
}
```

以 \(a=1,b=1\) 为例：

| 步骤 | 操作 | `a` | `b` |
|---|---|---:|---:|
| 初始 | — | 1 | 1 |
| i=3 | `b+=a` → `b=2` | 1 | 2 |
| | `a=b-a` → `a=1` | 1 | 2 |
| i=4 | `b+=a` → `b=3` | 1 | 3 |
| | `a=b-a` → `a=2` | 2 | 3 |
| i=5 | `b+=a` → `b=5` | 2 | 5 |
| | `a=b-a` → `a=3` | 3 | 5 |

结束后 `b=5`，正确。

**优点：** 省一个临时变量，写法短。  
**缺点：** 可读性差，初学者容易看懵；而且依赖“减法不会溢出”的隐含前提。  
**教学建议：** 先讲临时变量法，保证学生理解“更新顺序”；再展示加减法，作为“省空间的技巧”拓展，不要求所有人掌握。

## Q5：最终代码为什么可以用 `a=0, b=1` 从 `i=1` 开始？和从 3 开始有什么区别？

**A：** 两种循环起点等价，只是“对齐方式”不同。

**从 3 开始（`a=1,b=1`）：** 直接对应定义 \(f(1)=f(2)=1\)，循环处理 \(f(3)\dots f(n)\)。

**从 1 开始（`a=0,b=1`）：** 把 \(a\) 看成 \(f(0)=0\)，\(b\) 看成 \(f(1)=1\)，循环 \(n-1\) 次，每次把 `b` 往前推一项。

```c
long long a = 0, b = 1;
for (int i = 1; i < n; i++) {
    long long tem = a + b;
    a = b;
    b = tem;
}
// b = f(n)
```

验证：

| \(n\) | 循环次数 | 结束后 `b` |
|---|---:|---:|
| 1 | 0 次 | 1 |
| 2 | 1 次 | 1 |
| 3 | 2 次 | 2 |
| 4 | 3 次 | 3 |
| 5 | 4 次 | 5 |

这种写法**不需要单独判断 \(n\le 2\)**，边界更统一。Python 里 `a, b = b, a + b` 就是这种写法的元组版；C 语言没有元组交换，所以要拆成临时变量。

> 教学建议：两种起点都讲，让学生体会“循环次数 = 目标项到起点的距离”，而不是死记 `i=3`。

## Q6：C 语言实现要注意哪些坑？

**A：**

| 坑 | 说明 | 正确做法 |
|---|---|---|
| `int` 溢出 | \(f(47)\) 左右就超过 `int` 范围 | 用 `long long`，输出 `%lld` |
| 变量未初始化 | `long long a, b;` 直接 `b += a` 是未定义行为 | 显式 `a=1,b=1` 或 `a=0,b=1` |
| 更新顺序错 | 先写 `a=b` 再算 `tem`，旧 `a` 丢失 | 先算 `tem`，再更新 `a`、`b` |
| 边界 `n<=2` | 从 3 开始的写法如果不特判，`b` 仍是初值 | 要么特判，要么用 `a=0,b=1` 统一处理 |
| 输入格式 | 多组数据时 `sum` 类问题会踩初始化坑 | 本题单组，但可提醒“多组时每组重算” |

## Q7：最终 C 语言代码。

**A：** 推荐用 `a=0,b=1` 的统一写法，边界最少：

```c
#include <stdio.h>

int main() {
    int n;
    scanf("%d", &n);

    long long a = 0, b = 1;   // a=f(0), b=f(1)

    for (int i = 1; i < n; i++) {
        long long tem = a + b;
        a = b;
        b = tem;
    }

    printf("%lld\n", b);

    return 0;
}
```

如果习惯“从 3 开始”，等价写法：

```c
#include <stdio.h>

int main() {
    int n;
    scanf("%d", &n);

    if (n <= 2) {
        printf("1\n");
        return 0;
    }

    long long a = 1, b = 1;   // a=f(1), b=f(2)

    for (int i = 3; i <= n; i++) {
        long long tem = a + b;
        a = b;
        b = tem;
    }

    printf("%lld\n", b);

    return 0;
}
```

## Q8：常见误区有哪些？

**A：**

| 误区 | 纠正 |
|---|---|
| “定义是递归的，所以代码必须递归” | 定义描述关系，实现可选递归或迭代 |
| “递归写法更短所以更好” | 朴素递归 \(O(2^n)\)，\(n\) 稍大就不可用 |
| “`a, b = b, a + b` 在 C 里也能直接写” | C 没有元组交换，必须用临时变量或加减法 |
| “`b += a; a = b - a;` 一定更好” | 省变量但可读性差，初学阶段优先临时变量法 |
| “从 3 开始必须特判” | 改用 `a=0,b=1` 从 1 开始可免特判 |
| “`int` 够用” | 斐波那契增长快，建议直接 `long long` |

## Q9：课堂练习怎么设计？

**A：**

**练习 1（手推）：** 用表格写出 \(n=7\) 时两种写法的 `a,b` 变化，验证结果都是 13。

**练习 2（找 bug）：** 下面代码哪里错了？

```c
long long a = 1, b = 1;
for (int i = 3; i <= n; i++) {
    a = b;
    b = a + b;   // ← 错：a 已经被覆盖
}
```

> 正确答案：先算 `tem=a+b`，再 `a=b; b=tem;`。这题直接对应 Q3 的“更新顺序”。

**练习 3（改代码）：** 把 `a=0,b=1` 的写法改成 `a=1,b=1` 从 3 开始，要求不特判 \(n\le2\) 也能正确，思考需要怎么调整循环。

**练习 4（思考题）：** 如果要求输出 \(f(n)\bmod 10^9+7\)，代码怎么改？会不会影响变量类型选择？（引出“取模后不会溢出”）

**练习 5（拓展）：** 如果要求同时输出 \(f(1)\dots f(n)\)，还能只用 \(O(1)\) 空间吗？为什么？

## 扩散：从斐波那契看“递推 → 滚动变量 → 矩阵快速幂”

**正确表述：**

> 斐波那契是“**递推**”的入门模型：当前项只依赖前有限项。  
> 当只依赖前两项时，可以用**滚动变量**把空间压到 \(O(1)\)——这就是本题两种写法的本质。  
> 如果 \(n\) 大到 \(10^{18}\)，\(O(n)\) 也不够，就需要**矩阵快速幂**把时间降到 \(O(\log n)\)；但那已经超出本题范围，可以作为后续伏笔。

具体建议：

1. 讲递推时，先让学生写**递归定义**，再问“能不能不重复算”，自然过渡到迭代。
2. 滚动变量法要强调“**更新顺序**”：先算新值，再覆盖旧值。
3. 遇到“只依赖前几项”的 DP，都可以类比斐波那契做空间压缩。
4. C 语言里没有元组交换，正好借本题讲“临时变量”的必要性，和 Python 的 `a,b=b,a+b` 形成对比。

> 一句话总结：**定义可以递归，实现优先迭代；两项滚动，先算后覆盖；边界统一，类型放宽。**
