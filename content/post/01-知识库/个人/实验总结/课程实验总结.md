# 课程实验总结：从 C++ 到 Linux、汇编与算法优化

> 这篇笔记把此前分散在多门课程中的实验报告合并成一份总结。原报告偏重逐题记录，这里保留实验主线、关键方法、常见坑和可复用的经验，不再保留重复的封面、学号、模板和截图。

## 一、实验总览

| 课程 | 实验主线 | 主要工具 | 核心能力 |
| --- | --- | --- | --- |
| 面向对象程序设计 | C++ 基础、类与对象、继承、多态、输入输出 | Dev-C++、Windows 11 | 从面向过程过渡到面向对象 |
| Linux 系统 | 安装、文件操作、权限、编辑器、远程连接、Python 环境 | Ubuntu、终端、Xshell、Xftp | 命令行操作与系统管理 |
| 汇编语言与接口技术 | 运行环境、DEBUG、分支循环、串操作、子程序、DOS 调用 | MASM 5.0、LINK、DEBUG、DOS | 贴近硬件的程序设计与调试 |
| 高级编程 | 区间求和优化、区间最值查询优化 | C/C++、算法分析 | 从暴力到数据结构的复杂度优化 |

这些实验表面上分属不同课程，实际反复训练的是同一条链路：**搭环境 → 写最小可运行程序 → 观察结果 → 定位错误 → 分析复杂度 → 记录结论**。

## 二、C++：从语法细节到面向对象

### 1. 基础练习

第一组实验覆盖了 C++ 相对 C 语言最直观的变化：

- 用 `cout` / `cin` 替代 `printf` / `scanf`，体会类型安全和格式控制的差异；
- 用 `inline` 函数替代宏，避免宏展开带来的类型与优先级问题；
- 用函数重载让同名函数根据参数类型选择实现；
- 用作用域运算符 `::` 区分全局变量和局部变量；
- 用 `new` / `delete` 管理动态内存；
- 用引用参数实现两个变量的交换，理解“引用是变量的别名”。

这一组实验最重要的收获不是记住语法，而是意识到 C++ 在 C 的基础上增加了**类型安全、封装和抽象**的能力。

### 2. 类与对象

通过 `Time` 和 `Stock` 两个类，实验把“数据 + 操作”放在同一个抽象里：

- 私有成员保护数据，公有成员函数提供受控访问；
- 构造函数负责对象初始化，析构函数负责资源清理；
- 无参构造函数、带参构造函数、拷贝构造函数分别对应不同的创建场景；
- `const` 引用参数既避免拷贝，又保证被引用对象不被修改；
- 用 `fixed` 和 `setprecision` 控制浮点输出格式。

这里开始出现面向对象与面向过程最核心的差异：C 语言中结构体和函数是分离的，C++ 中类把状态和行为绑定在一起，对象的生命周期也有了明确的边界。

### 3. 类与对象进阶

第三个实验把类放进更真实的数据管理场景：

- 用对象数组保存连续多个交易日的股票数据；
- 用指针在对象之间移动，计算相邻交易日的涨幅；
- 用静态数据成员统计对象数量，用静态成员函数在不创建对象的情况下访问统计值；
- 用 `this` 指针识别当前对象，并在赋值函数中判断自赋值；
- 用友元函数访问私有成员，完成“开盘价是否高于收盘价”这类跨对象判断。

这一组实验的关键词是**对象之间的关系**：对象不只可以单独存在，还可以组成数组、被指针引用、共享静态数据，或者通过友元建立受控的例外访问。

### 4. 继承与派生

实验用一套人员信息管理模型串起继承：

- `Person` 作为基类保存工号、姓名、性别、工资；
- `Teacher`、`TemporaryWorker`、`Staff` 分别派生，增加课时/职称、时薪/工时、职位等字段；
- 各派生类重写输入、输出和工资计算函数；
- `StaffTeacher` 同时继承 `Staff` 和 `Teacher`，形成“双肩挑”的多继承场景；
- 用虚基类解决多继承中重复继承 `Person` 带来的二义性。

实验中最直观的教训是：多继承不是“能写就写”，当两条继承路径汇合到同一个基类时，必须明确数据只有一份，否则编译和逻辑都会出问题。

### 5. 多态与虚函数

第五个实验分成两部分：

- **编译时多态**：为 `Rational` 有理数类重载 `<`、`<=`、`==`、`!=`，用交叉相乘比较分数，避免浮点精度问题；
- **运行时多态**：`Animal` 定义虚函数 `Identify()`，`Cat`、`Dog`、`Tiger` 重写；`Zoo` 用基类指针数组管理不同动物，通过基类指针调用时自动执行实际子类的版本。

这里集中出现了几个容易忽略的细节：

- 基类析构函数应声明为虚函数，否则通过基类指针删除子类对象时可能无法正确析构；
- 重写函数时用 `override` 让编译器帮忙检查签名；
- 动态分配的成员要在析构函数中释放，避免内存泄漏；
- 多态依赖“基类指针/引用 + 虚函数”，仅靠对象切片无法保留子类行为。

### 6. 输入输出与格式控制

最后一个 C++ 实验把前面写的 `Rational` 类接到标准流上：

- 重载 `<<` 和 `>>`，让自定义类型可以直接用 `cout` / `cin`；
- 用 `setw` / `width` 控制输出宽度；
- 用 `left` / `right` 控制对齐；
- 用 `fixed`、`setprecision` 控制小数格式，并能恢复默认格式；
- 用 `dec`、`oct`、`hex` 输出不同进制。

这部分实验说明：运算符重载不是为了炫技，而是为了让自定义类型拥有和内置类型一致的使用体验。

### C++ 实验踩坑清单

- 动态数组释放要写 `delete[]`，不能只写 `delete`；
- 构造函数没有返回值类型；
- 拷贝构造函数的参数通常写成 `const 类名&`，避免无限递归拷贝；
- 访问全局变量时不要漏掉 `::`；
- 多继承汇合到同一基类时考虑虚基类；
- 通过基类指针管理子类对象时，基类析构函数应为虚函数；
- 赋值函数要考虑自赋值，深拷贝对象要单独处理指针成员。

## 三、Linux：把图形界面换成命令行

Linux 实验从安装开始，逐步过渡到日常操作和远程开发：

1. **环境搭建**：用 VMware Workstation 创建 Ubuntu / CentOS 虚拟机，理解虚拟网络、镜像和系统安装流程。
2. **文件操作**：`ls`、`cd`、`pwd`、`mkdir`、`touch`、`cp`、`mv`、`rm`、`cat`、`find`、`grep`、`tar` 等命令，配合输出重定向和管道完成文件管理。
3. **用户与权限**：`useradd`、`usermod`、`userdel`、`groupadd`、`chmod`、`chown`、`chgrp`，理解 `rwx` 与数字权限的对应关系，以及 `sudo` 的边界。
4. **编辑器**：Vim 的普通模式、插入模式、命令行模式，以及 nano 的基本操作；用 Vim 修改 Apache 配置文件。
5. **远程连接**：安装并启动 `openssh-server`，用 Xshell 登录 Ubuntu，用 Xftp 在 Windows 与 Ubuntu 之间传文件。
6. **Linux 上的 Python**：安装 `python3`、`pip3` 和 Jupyter Notebook，处理 pip 脚本目录的 `PATH` 问题，运行一个简单的 Python 小程序。

### Linux 命令速查

| 场景 | 常用命令 |
| --- | --- |
| 查看与移动 | `pwd`、`ls`、`cd`、`cp`、`mv`、`rm` |
| 查找内容 | `find`、`grep`、`cat`、`less` |
| 权限 | `chmod`、`chown`、`chgrp`、`sudo` |
| 用户与组 | `useradd`、`usermod`、`userdel`、`groupadd` |
| 进程与服务 | `ps`、`top`、`kill`、`systemctl` |
| 压缩与传输 | `tar`、`scp`、`sftp`、Xftp |
| 远程登录 | `ssh`、Xshell |

### Linux 实验踩坑清单

- 修改系统配置前先备份，删除操作先用 `ls` 确认目标；
- `chmod` 的数字权限是 `r=4、w=2、x=1` 相加，不要和所有者/组/其他人混淆；
- 服务安装后要检查 `systemctl status`，确认真的在运行；
- pip 安装的可执行脚本可能不在 `PATH` 中，需要手动加入；
- Ubuntu 默认不启用 SELinux，涉及 SELinux 的实验要区分“临时开启”和“永久配置”；
- 远程连接失败时依次检查网络、SSH 服务、端口和防火墙，而不是只重装客户端。

## 四、汇编语言与接口技术：贴近硬件的编程

汇编实验从运行环境开始，逐步进入指令和系统调用：

1. **运行环境**：用 MASM 5.0 汇编、LINK 连接，在 DOS 环境运行程序；理解源文件、目标文件、可执行文件的关系。
2. **DEBUG 调试**：熟悉 `D`、`E`、`R`、`T`、`A`、`G`、`U` 等命令，能查看/修改内存、寄存器和指令。
3. **分支与循环**：用比较、跳转和循环指令实现条件判断与重复计算，先画流程再写代码。
4. **串操作**：掌握串比较、串检索、字符统计等操作，理解方向标志和串指令的配合。
5. **子程序**：用 `CALL` / `RET` 组织子程序，理解参数传递、现场保护和堆栈平衡。
6. **DOS 功能调用**：通过 `INT 21H` 完成键盘输入、字符串显示等操作，理解功能号与寄存器的约定。

### 汇编实验踩坑清单

- 先确认段寄存器和数据段，再谈指令逻辑；
- 子程序调用前后要保证堆栈平衡，`PUSH` 和 `POP` 成对出现；
- 串操作要关注方向标志 `DF`，否则地址递增/递减方向可能相反；
- DOS 功能调用要同时设置 `AH` 功能号和对应参数寄存器；
- DEBUG 里单步执行比盯着源码猜更有效；
- 汇编程序的可读性依赖注释和标号，不要把所有逻辑堆在一个段里。

## 五、高级编程：从暴力到数据结构

高级编程的两组实验都围绕“区间查询”展开，但优化路径不同。

### 1. 区间求和：枚举 → 前缀和 → 树状数组

- **枚举**：每次查询都从头累加，时间复杂度高，适合作为正确性基线。
- **前缀和**：预处理 `S[i] = S[i-1] + a[i]`，区间和变成 `S[r] - S[l-1]`，查询从 `O(n)` 降到 `O(1)`。
- **树状数组 / BIT**：用 `lowbit(x) = x & -x` 找到二进制最低位的 1，把前缀查询和单点修改都压到 `O(log n)`。

前缀和适合“静态数组、频繁查询、几乎不修改”的场景；如果修改和查询交替出现，树状数组更合适。

### 2. 区间最值：枚举 → 线段树 → ST 表

区间最小值不能像区间和那样直接用前缀和相减，因此实验走了另一条路线：

- **枚举**：每次扫描区间，结果正确但慢；
- **线段树**：把区间二分建树，查询时把大区间拆成 `O(log n)` 个小区间，支持修改；
- **ST 表**：用倍增预处理 `O(n log n)`，之后每次查询 `O(1)`，适合静态数组。

| 结构 | 预处理 | 单次查询 | 单点修改 | 适用场景 |
| --- | --- | --- | --- | --- |
| 枚举 | `O(1)` | `O(n)` | `O(1)` | 数据量很小、验证正确性 |
| 前缀和 | `O(n)` | `O(1)` | `O(n)` | 静态区间和 |
| 树状数组 | `O(n)` | `O(log n)` | `O(log n)` | 动态前缀和 |
| 线段树 | `O(n)` | `O(log n)` | `O(log n)` | 动态区间查询 |
| ST 表 | `O(n log n)` | `O(1)` | 不支持 | 静态区间最值 |

两组实验的共同结论是：**先写出正确但朴素的版本，再根据操作类型和复杂度瓶颈选择数据结构**。优化不是背模板，而是先明确“查询多还是修改多、数据静态还是动态”。

## 六、实验报告的共同结构

这些报告虽然课程不同，但结构高度一致，可以抽象成一套模板：

1. **实验目的**：这次实验要验证什么、掌握什么；
2. **实验环境**：操作系统、编译器/工具、版本；
3. **实验内容**：题目、输入输出要求、约束；
4. **实验过程**：关键步骤、核心代码、调试过程；
5. **实验结果**：运行截图或数据，证明程序确实工作；
6. **结果分析**：为什么得到这个结果，和预期是否一致；
7. **问题与解决**：报错、定位过程、最终修复方式；
8. **结论与改进**：学到了什么，下一步能优化什么。

最容易写空的是“结果分析”。好的分析不是重复“运行成功”，而是解释**为什么成功、复杂度如何、边界是否覆盖、换一种输入是否仍然成立**。

## 七、跨课程踩坑清单

- 环境先跑通最小示例，再写完整程序；
- 报错先读第一行和最后一个 `error`，不要从中间开始猜；
- 动态内存、文件、数据库连接等资源要成对释放；
- 输入要考虑空值、越界、非法字符和极端数据；
- 算法题先写暴力，再优化，并保留暴力版本做对拍；
- 命令行操作先用 `ls` / `pwd` 确认位置，再执行删除或覆盖；
- 实验记录要保留关键截图、命令和输出，方便复盘；
- 报告中的结论要有证据，不要只写“实验成功”。

## 八、结语

这些实验真正留下来的，不是一份份格式相同的报告，而是一套可以迁移的工作方法：

- 面对新环境，先建立最小可运行示例；
- 面对复杂问题，先写出正确但朴素的版本；
- 面对性能瓶颈，先分析操作类型和复杂度；
- 面对错误，先缩小范围、观察证据，再修改代码；
- 面对结论，先问“为什么”，再写“是什么”。

把这套方法用在下一门课、下一个项目里，比保留几十份重复的实验报告更有价值。
